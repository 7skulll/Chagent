# 任务交接与续办

让接手者知道已确认的事实、尚未完成的工作和下一步入口。交接文档是参考资料，不是新授权；用户当前要求优先于历史计划。

## 收集当前状态

- 先用可见对话确定目标、最新约束和明确决定，区分用户要求、已采纳决定与模型建议。仅要求整理交接时不顺便执行后续任务。
- 核对用户指定的相关文件、实际改动与产物。exec_command 可用时读取 Git 状态、HEAD、暂存/未暂存差异及未跟踪列表；不替用户提交、清理或恢复工作树。工作区模型路径为 `/workspace`，交接优先用相对路径，不复制宿主私有路径、密钥或环境变量值。
- 当前记录不足且确需历史时，通过 search_task_history 搜索同工作区的相关任务，再用 read_task_history 读取匹配的摘要。两者可能需要 tool_search 加载；不要自动读取全部历史。摘要可能截断，记录了回答不代表任务已完成，文件和服务等可变事实要重新核对。
- list_recent_runs / inspect_run 只允许当前会话的其他运行，不允许凭旧 run_id 跨会话读完整运行。另一个会话的任务摘要可以作为线索，但不能把摘要当成完整原始证据；查询不可用或不可访问时写明缺口，不寻找数据库口令或其他会话目录来补齐。

## 形成交接说明

按任务规模整理以下内容，不强制给小任务套完整表格：

- 目标与约束：当前要交付什么，哪些决定已经确认。
- 已完成：具体改动、涉及文件、产物和对应证据。测试写明实际命令、环境、结果和版本；历史通过不等于当前版本已重验。
- 进行中与阻塞：剩余问题、失败尝试、依赖或审批条件；unknown 表示副作用未知，单独列为待核实，不能写成“未执行”。
- 继续入口：相关文件/函数、可用产物标识、适用范围内的 run_id/记录位置，以及下一步最小动作。标明哪些是建议，哪些已执行。
- 服务与进程：仅在有关时查询 site(status) 等实际状态，记录返回的 URL 和观察时间；站点可跨 run 保留，但旧进程 ID 不保证跨 run 或主控重启可用，不声称已经接管后台进程。

用户只需要文字时直接在对话交付。需要跨会话持久文件时，用 create_file 保存受支持的 Markdown/文本；遵守同名确认，pending 不算保存成功。若内容含仅本会话可访问的运行引用，同时在交接中写出必要的非敏感事实，避免下一会话只有打不开的 ID。不会因此自动发送给他人、创建新会话或写入长期记忆。

## 根据交接续办

只有用户要求继续执行时才行动。先核对当前工作区、文件版本、已有改动与相关服务，再执行最小下一步。过期审批或历史“同意”不能代替当前工具所需的审批，旧测试和运行记录也不能代替状态检查。交接与现场冲突时以可验证现状为依据，指出差异，不盲目重做可能已经发生的操作。
