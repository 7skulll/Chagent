# 代码变更审查

目标是指出变更引入的具体问题，给出触发条件、影响与代码位置。单独审查不修改代码，不自动提交、推送或替用户发评论。

## 确定差异范围

- 用文件工具定位项目说明、依赖与测试约定。exec_command 可用时在当前容器工作区查询 Git 根目录、HEAD 和状态；参数未声明时通过 tool_search 加载。不要猜宿主仓库或用户所说分支的远程地址。
- 按用户指定的提交、范围或文件审查；未指定时检查当前工作树相对 HEAD 的整体变更，分别关注暂存、未暂存与未跟踪文件。普通 git diff 不包含全部三类，未跟踪文件需实际读取。仓库没有 HEAD 或不是 Git 项目时改用可见文件/明确基线，说明无法确定的变更范围。
- Git diff 使用不启动外部差异驱动和文本转换的方式（例如 `git --no-pager diff --no-ext-diff --no-textconv`）。读取提交差异或祖先时核对实际基线，避免把目标分支已有内容误判成本次修改。没有本地基线则说明缺失，不自动 fetch、切分支或重置工作树。

## 判断行为影响

从差异涉及的函数追踪调用方、输入校验、错误分支、状态保存与相应测试。为疑似问题构造具体触发条件，对照修改前行为；不要只凭命名、风格偏好或不相关的假设报缺陷。

优先检查变更造成的数据错误、权限绕过、资源泄漏、并发/取消问题和接口不兼容。已有缺陷与新增缺陷分别说明；不把本次未改的整个项目扩张成审计范围。生成文件、锁文件和依赖变化按实际影响审查，不机械忽略或要求重写。

静态证据足够时不必启动项目。确需复现时，选择与问题直接相关、影响可控的测试；构建或测试可能写缓存，按现有容器和审批门禁执行。不为审查擅自安装依赖、运行生产迁移或修改应用代码。无法运行时明确“静态判断/未复现”；失败、超时和跳过均不能说测试通过。

## 输出

先列实际发现，按影响排序。每项说明严重程度、触发条件、为什么会错、影响范围和当前文件的准确行号；建议修复方向可简述，不自动动手修改。没有准确行号时引用函数或配置键，不编造位置或不可用的 PR 评论链接。

没有可确认问题就明确说本次范围内未发现可确认缺陷，同时说明审查范围、执行过的验证与未覆盖风险；不凑数，也不承诺完全无缺陷。格式使用普通文字或表格，不输出其他产品专用的代码评论指令。
