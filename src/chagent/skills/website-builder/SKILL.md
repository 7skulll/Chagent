# 自主建站与本机交付

目标是交付符合用户需求、经过实际验证的网站。默认交付 Chagent 的本机访问地址；用户要求公网发布时另行确定目标和可用发布能力，不把本机地址称为公网链接。

## 实现

- 先读取当前工作区的文件、依赖和启动约定；已有项目沿用其框架、语言和包管理器。空目录按任务规模选择合适技术，不强制套用固定模板。
- 核对用户要求的页面、交互和数据行为，缺失但不阻碍实现的细节采用合理默认。不要因用户要求“网站”就虚构登录、支付、外部 API 或数据库已连接。
- 用文件工具编辑，按需通过 exec_command 在工作区容器内安装依赖、构建和测试。当前工具参数未声明时先调用 tool_search。工作区模型路径为 `/workspace`，文件工具可使用相对路径；不寻找宿主密钥或修改 Chagent 自身配置。
- 当前宿主主控档的容器命令为一次性执行，不支持通过 yield_time_ms 接管长命令。不要用后台 shell、nohup 或 host_exec 替代网站生命周期管理；需要更久的构建按实际工具预算拆分执行，并如实报告未完成部分。

## 启动与检查

1. 确认当前工具面是否有 site。若缺少，仍可在授权范围完成代码与构建，明确无法验证持续服务，不声称已经运行。
2. 有 site 时先调用 `site(action=status)` 检查现存服务。已有服务时先确认其所属项目；替换它会影响现有访问，只有任务确实需要时才停止。状态不明先看日志，不重复启动。
3. 用 `site(action=start, command=实际启动命令, workdir=项目目录, port=实际监听端口)` 启动。配置服务监听容器可访问的地址（通常 `0.0.0.0`），内部端口不能使用 site 保留的 `18080`。不要把返回的本机映射端口填成内部监听端口。
4. 启动返回不代表验收通过。调用 `site(action=probe, path=/)`，按项目情况检查健康接口或关键路由；核对响应状态与正文确实属于目标网站。失败时使用 `site(action=logs)` 和状态排查，不反复盲目重启。修改监听端口后更新启动参数，并重新 probe。
5. 运行相关单元测试、构建或接口检查。HTTP 成功只证明对应请求可访问，不证明交互和视觉正确。当前没有浏览器工具时明确页面视觉与交互尚未实测。

## 交付

使用 site 实际返回的 URL，说明已实现内容、测试/构建结果、HTTP 验证及剩余限制。site 服务跨 run 保留，交付后不为清理当前 run 而停止站点；说明可由 site 查看状态、日志和停止。

用户需要下载文件时使用当前可用的 create_file 或 collect_file，按工具声明区分生成产物与容器已有文件导出。不要把容器临时路径当作可下载链接。审批、失败和未知结果以工具返回为准，不在最终回答中虚构批准、测试或运行证据。
