## 16. 宿主原生交互 stdin 与重启/未知演练（2026-11-05）

**对象与方法**：本机 macOS，用户 8765 宿主主控实例（`CHAGENT_HOST_DB_COMPOSE=true`，工作区 `/Users/macbook/Desktop/测试用`）与其 Compose PostgreSQL。主控两次以 `kill -9` 终止后带迁移 `0022` 重启；交互输入与审批决策由真实 DeepSeek 驱动的 HTTP 脚本发起（脚本只在本文件注明「agent-driven」的场合代替点按，审批事件与工具结果全部落库）。模型自述不作为证据，所有结论以 `approval_requests`、`native_executions`、`native_stdin_writes`、`tool_calls` 与实际进程状态为准。

**实现范围**：迁移 `0022` 给 `native_executions` 增加 `interactive`、`process_id`、`child_pid`，状态机加入 `running`；新表 `native_stdin_writes` 以启动批准之外的单次写入批准为主键，记 `pending/written/failed/unknown`。`host_exec` 新增 `yield_time_ms`：交互启动立刻返回 `process_id`，子进程留在本 run 的进程管理器；新工具 `host_process` 提供 list/read/write/stop，read/list/stop 不问，write 每次一张独立审批卡（subject 含目标进程、真实目录、输入字节数与 `close_stdin`，卡片写明只对这次输入有效）。写入先以 `pending` 占位再动 stdin，主键冲突即拒绝，重放不会二次写入。主控重启把 `starting/running` 执行与 `pending` 写入一律标 `unknown`，且不重试。

**闭环一：一次启动、两次写入、三张审批卡**（run `be66749d-566b-478a-9544-8433c39d8a8e`）。真实模型先 `exec_command` `pwd`（退出码 0），再 `host_exec cat`（`yield_time_ms=3000`），随后 `host_process read`（无卡）、`write "hello-native-drill"`、`read` 看到回显、`write close_stdin=true`。

| 事实 | 证据 |
|---|---|
| 三张独立审批，逐次批准 | 同 run 三条 `approval_requests` 均 `approved` 且 `consumed_at` 非空：`host_exec` 启动、`host_process` 写入、`host_process` EOF |
| 写入逐条审计 | `native_stdin_writes` 两行 `written`，`chars` 分别为输入原文与空串（EOF），`close_stdin` 分别为 false/true |
| 读不需要审批 | 两次 `host_process read` 未产生审批行，返回回显与状态 |
