## 文档维护规则

- **不再按批次新起文档。** 新验收写进《验收记录汇总》的一个分节，新决策写进《历史决策档案》的一节；只有形成长期契约的内容才单独立篇。
- 例外只有一种：**会改动契约本身的方案，在实施前单独立篇**。当前有一篇：《自主建站整体方案》交付后把实际契约并入《统一可编程执行契约》，把取舍和证据分别写入历史决策与验收记录。同理，前端模块化交付后边界并入《网页与工作区设计》第 2.1 节、证据写入《验收记录汇总》第 15 节，原方案页已删。两者都只在其阶段未完成期间保留。
- 当前行为写专题，未来工作只排在《实施计划》，交付证据写《验收记录汇总》或《实施记录》；不另起版本号路线图。
- 写清实现、自动测试、真实工具、真实模型浏览器和真实项目分别验证了什么。
- 历史数字标日期；测试跳过不计通过，合成 fixture 不计真实项目。
- 删除旧计划时先迁移仍有效的决策并修复引用；保留支持结论的原始数据。
- 合并文档时把有效结论迁走再删原文件，并在提交信息里写明，方便从 git 历史取回。
