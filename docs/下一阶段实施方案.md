# 路线图：work 模式（第四版）

状态：2026-10-30 替换第三版。Z 批收口后，重心从「网页能跑」转向「对话能留住人」：**先做 work 模式（只读对话），code 模式（本地代码执行）达到启用门槛后再开放**，门槛见[执行边界设计](执行边界设计.md) §14.4。第二、三版的交付结论仍压成 §4 一张表，批次过程留在[实施记录](实施记录.md)。

一句话结论：**框架侧已经到顶（每轮 7ms），下一个瓶颈不在循环里，在「对话本身好不好用」——渲染、重生成、出处、附件，而不是再加一个工具。**

## 2. 为什么下一步是网页

Y 批把网页定为唯一入口，但网页目前只是「能对话」，还不是「能管理」。下面四条全部是 2026-10-30 实测，不是推测：

1. **44 个按钮里 24 个点了没有反应。**（Z1 已关闭：44→20、孤儿 24→0，并由静态断言守住，见 §5．以下为当时的实测记录。）逐个核对 `index.html` 的 `<button>` 与 `app.js` 的监听：20 个有绑定（18 个直接绑定、2 个经表单提交生效），其余 24 个没有任何行为——左侧图标栏 8 个里 7 个、品牌下拉、通知、搜索、项目、前进／新建标签页／全屏、输入框上方两个 chip、语音、右侧浏览器栏 4 个、右侧三张工具卡。界面在承诺不存在的东西，这与全文其余部分「如实写边界」的做法自相矛盾。
2. **会话不能重命名、不能归档。** `SessionManager.rename/archive/restore` 三个方法在服务层已存在，`SessionArchivedError` 与 `SessionNotFoundError` 都已接进网页错误映射，但 26 个端点里没有对应的写入口。更糟的是 `GET /api/sessions` 默认 `include_archived=False`：一旦在 CLI 归档，网页里这个会话就彻底消失，且没有任何入口把它找回来。
3. **审批没有「有没有人在看」的知觉。** `ApprovalBroker.request` 的等待循环只看 `expires_at`，不看 SSE 订阅者。关掉浏览器后，run 会在原地等满 `CHAGENT_APPROVAL_TIMEOUT`（默认 300 秒）才 `expired`：期间这个会话发不了新消息（同会话至多一个活跃运行，再发返回 409）；超过 300 秒才回来的用户，看到的是一个「命令未执行」却已经按失败收尾的答案，还得重新问一遍。
4. **用量完全不可见。** `model_calls.response` 里每轮都存着供应商回报的 `input/output/cache_read/cache_write/total_tokens`，但网页只显示上下文估算值，从不显示真实用量；`UsageCost` 有类型定义、有反序列化，**但全库没有一处构造它**——成本从来没有被采集。

四条里前两条是缺口（少东西），第三条是语义错误（在没人看的时候还在等），第四条是浪费（数据在库里却不用）。Z 批按「先补可靠、再改语义」排序：Z1 删假界面、Z2 补会话管理、Z3 把用量读出来、Z4 改等待语义、Z5 让后台运行可见。

## 3. 成本方程（口径未变）

一次运行 ≈ **轮次 ×（首字延迟 + 生成长度／速率 + 框架开销）+ 工具耗时**。

| 分项 | 实测 | 占比 | 还能优化多少 |
|---|---|---|---|
| 首字延迟（供应商） | 570ms/轮 | 40% | 不在我们手里 |
| 模型生成 + 工具执行 | ≈860ms/轮 | 59% | 只能靠「少说话、少来回」 |
| 框架（上下文构建、调度、事件） | **7ms/轮** | **0.5%** | 已到顶 |
| 提示缓存 | 87.1%（P1 样本）／83.4%（H 批后复测） | — | 前缀断裂 0 次 |

推论（第二版已证，继续有效）：把 SQL 从 46 条压到 20 条省不出一轮；把编辑成功率从 2/3 提到 1 直接省一轮。**能答出「减少几轮或几次无效调用」的批次优先做。**

Z 批是个例外：它不减少模型往返，买的是「工具在正确的时候停下」与「屏幕上的数字可信」。这类批次按**能力边界**验收（同 S 批沙箱的例外条款），但实施记录里仍要如实写「轮次没有变化」，不许用界面改动冒充效率提升。

### Z2 · 会话管理闭环（已交付）

**动机**：`rename/archive/restore` 服务层现成，端点缺失；归档等于永久消失（§2 第 2 条）。

**交付**：

- `PATCH /api/sessions/{id}`：body `{title?, archived?}`，走 `SessionManager`，返回 `Session`。`title` 为空串表示清空标题；`archived=true` 归档、`false` 恢复。同一个端点做两件事，因为它们都是「改会话元数据」，且都要过 `current.session()` 的归属校验。
- `GET /api/sessions?archived=hide|include|only`（默认 `hide`，与现状一致）+ `q=`（标题子串，`ILIKE`，大小写不敏感）。
- 前端：会话行右侧悬停出现「⋯」，菜单两项——重命名（行内变输入框，回车提交、Esc 取消）、归档；侧栏底部加「已归档（n）」开关，切到归档视图后可恢复；头部加真搜索框，输入 250ms 防抖后带 `q` 重新拉列表。
- 归档会话仍可打开查看历史（只读），但发新 run 返回 409（`SessionArchivedError` 已接好），输入框置灰并写明原因。

**验收**（`tests/test_web.py` +5）：重命名后列表与详情都变、刷新保持；归档后默认列表不再返回、`archived=only` 能拿到、恢复后回默认列表；归档会话 `POST /runs` 返回 409 且不建 run；`q` 命中标题子串且不命中正文；`title` 200 字上限与 CLI 同源（`SessionManager._title` 抛 `ValueError` → 400）。前端手工过一遍上述四条。

**回退**：新端点独立，删掉后前端菜单退回隐藏；`archived` 参数默认值等于现状，不改变老客户端行为。

### Z3 · 用量面板（只报 token，不报钱；已交付）

**动机**：真实用量在库里，界面上一格都没有（§2 第 4 条）。

**决策**：**不显示金额。** `UsageCost` 从未被构造，等于成本从未采集；临时按价格表估算会把「审计事实」变成「猜测」，而价格表还要按供应商与模型维护、随时会变。要做钱，必须先有价格表、明确标注「估算」、并写清是按哪一天的价——那是另一个批次的事，本批不做。因此面板只回答三个问题：花了多少 token、缓存省了多少、哪个 run 最贵。

**交付**：

- `GET /api/sessions/{id}/usage`：按 run 聚合，每行 `{run_id, started_at, model_calls, input, output, cache_read, cache_write, total_tokens}`；`SUM` 直接取自 `model_calls.response->'usage'`，缺 `usage` 的行计入 `model_calls` 但不计 token（不猜）。
- `GET /api/usage?days=7`：按天的全局汇总，同一套字段。
- 前端：会话标题右侧一个小 pill，显示 `12.4k tokens · 缓存 83%`；点击打开详情（本会话按轮次的表）。配置对话框加「本机用量（近 7 天）」一节。命中率定义：`cache_read / (input + cache_read)`，分母为 0 时显示 `—` 而不是 `0%`。
- 数字格式：<1000 原样、≥1000 用 `k`、≥1e6 用 `M`，保留一位小数；不在前端做二次求和（后端给的就是和）。

**验收**（`tests/test_web.py` +3，固定夹具写 3 条 `model_calls`）：端点返回的和等于手算值；缺 `usage` 的行不污染 token 合计但 `model_calls` 计数正确；命中率分母为 0 时前端显示 `—`。纯读，不影响任何写入路径。

**回退**：只读端点与只读界面，删掉即无影响；不新增表、不新增迁移。

### Z4 · 审批的在场语义（已交付）

**动机**：关掉浏览器后 run 空等 300 秒（§2 第 3 条）。深夜里一条命令把整个会话挂在那里，第二天看到的是过期后继续跑完的结果。

**交付**：

- `WebRuntime` 记录每个 run 的活跃 SSE 订阅数（`GET /api/runs/{id}/events` 进出各加减一次，`finally` 里减，避免连接异常时泄漏）。
- `ApprovalBroker.request` 增加可选参数 `audience: Callable[[UUID], bool]`：仅在 `remote=True` 且调用方提供时生效。循环里维护 `unwatched_since`——无人订阅持续超过宽限（默认 10 秒）就以 `deny` 收敛，note 写 `no viewer`，工具结果文本明确「没有页面在等待这条命令，未执行」，与「被用户拒绝」区分开，避免模型换参数重试。
- 宽限 10 秒的理由：刷新页面重连实测在 1–2 秒内完成，10 秒足够覆盖；再长会让「人走了」的代价重新变大。
- CLI（`remote=False`）行为完全不变。

**验收**（`tests/test_approval_flow.py` +3）：无订阅者时审批在 ≤12 秒内 `expired`／`denied`，run 以 `model_stop` 收敛，目标文件不存在（未执行），工具结果 reason 为 `unwatched`；有订阅者时等满 300 秒仍 `pending`（不提前过期）；订阅者中途断开后重新连上，不会因为 10 秒窗口被误杀（重连后 `unwatched_since` 清零）。

**回退**：`CHAGENT_APPROVAL_UNWATCHED_GRACE=0` 关闭，退回绝对 TTL。

### Z5 · 后台运行可见（已交付）

**动机**：A 会话跑长命令，切到 B 会话后 A 仍在跑，但侧栏、标题、状态栏都不提；用户不知道它结束没有。

**交付**：`GET /api/runs?active=true` 返回活跃 run 的 `{run_id, session_id, started_at, current_tool}`；前端在侧栏会话行加运行中圆点（1 秒轮询，仅在有活跃 run 时轮询），切回该会话时走既有的 SSE 重连路径续播。

**验收**：A 跑 45 秒命令、切到 B，A 行出现圆点；圆点在 run 结束后 1 秒内消失；回到 A 时消息不重复、不缺失；在 B 点「停止」不会停掉 A 的 run（`state.run` 已按会话重置，需加断言锁住）。

**回退**：只读端点 + 一个圆点，删掉即回到现状。

## 6. 明确不做

| 不做 | 理由 |
|---|---|
| 继续压 SQL／事件路径 | 单轮 7ms，全压掉也省不出一次首字延迟；写入路径已收两步（1.6 秒流式回答 260 条 SQL／81 事务 → 59／21）。剩下 `model_calls.request` 每轮仍存整份消息数组，改存 `message_ids[]` 能省 90% 存储，但那是磁盘不是延迟，判定不做 |
| Codex 的 `world_state` 哈希增量 | 为 100+ 工具、200KB 前缀设计；我们前缀几 KB 且缓存已到顶 |
| `spec_plan`／`tool_search` 动态工具加载 | 阈值未到：工具 >20 个或 schema >30KB 再议 |
| 多 Agent／子 Agent 委派 | 一次委派至少 +2 轮串行 |
| 新增只读工具 | 工具面 8 个已够，边际收益被 `grep`／`glob` 吃掉 |
| 把文件工具也塞进 OS 沙箱 | `WorkspaceFS` 的 dirfd + `O_NOFOLLOW` 已守住路径边界 |
| 用 Docker 当沙箱 | 路径翻译、`.venv` 符号链接、UID 映射成本高一个量级 |
| 网页显示金额成本 | 价格表要维护且随时会变，库里没有可信的成本字段；显示估算会把审计事实变成猜测（见 Z3） |
| 网页多标签并行会话 | 两个标签都往 `localStorage` 写工作区与当前会话，会互相覆盖；要支持得先做服务端 UI 状态，收益不抵一个状态机 |
| 会话全文搜索（消息正文） | 需要额外索引与分词，当前 `q` 只搜标题已够；等会话数上千再说 |

## 9. 第四版：work 模式（当前阶段）

### 9.1 判断

第三版解决的是「网页能不能跑」，这一版解决「对话能不能留住人」。三个事实：

1. **回答是纯文本。** `displayMessage` 只用 `textNode`，Markdown、代码块、表格、链接全部退化成等宽文字。写代码的人第一眼就会走。
2. **回答不能改。** 没有重新生成、没有编辑重发、没有失败重试；用户不满意只能重新开一个会话，上下文全丢。
3. **回答没有出处。** `web_search` 的结果在模型文本里，`read_file` 的页码在工具结果里，用户看不到「这句话是从哪来的」。

这三条都不需要新工具，只需要把已有的数据渲染出来、把已有的 run 接上操作。**这是当前性价比最高的一批工作。**

### 9.2 模式边界

两种模式的工具面、开关与服务端约束写在[执行边界设计](执行边界设计.md) §14.2。本节只记一条铁律：

> **工具没注册才是约束，界面隐藏不是。**

`work` 是默认模式，没有写文件、没有宿主命令，因此没有审批链、没有沙箱、没有进程管理。`code` 在 `CHAGENT_CODE_MODE=on` 且 §14.4 六条门槛全绿之前不出现。

### 9.3 WK0 · 收口（已交付，`5e4265d`）

不是新功能，是把已实现的东西对齐。五项均已落地，实测见[实施记录](实施记录.md) 第 27 节：

1. **提交 Z2–Z5。** 已在 `82c6a51` 与 Z6 一同提交。
2. **`sessions.mode` 迁移。** 迁移 `0015_session_mode.sql`：默认 `work`，CHECK 限 `work|code`，旧行按默认值成为 `work`。
3. **注册按模式裁剪。** `create_builtin_registry(*, mode)` 的 `mode` 必填（漏写即 `TypeError`）；每个启用的模式一份 `ToolExecutor`，绑自己的 registry；一次 run 在循环外解析一次面，本 run 内不切。
4. **接口与诊断。** `/api/info` 增 `{default_mode, code_mode}`；`/api/config` 也带上两者；`Behavior:` 增 `mode=… code=on|off`，`config show` 增 `modes:` 行；开关关闭时失效的沙箱／审批／宿主命令开关在启动时打 `Warning:`。

**验收**（已达成）：全量 **489 项**通过（本机约 60 秒，0 跳过）；真实网页入口实测 `tools=5`（`list_dir`／`read_file`／`glob`／`grep`／`read_artifact`），`--demo` 恒为单面 9 个。**回退**：删掉 mode 列则回到单一模式，其余改动不变。

附带一件必须说明的事：`CHAGENT_ALLOW_HOST_COMMANDS=true` 而 `CHAGENT_CODE_MODE=off` 时，宿主命令现在**不注册**（以前会注册）。这是 WK0 的目的，但对旧配置是一次行为变更，所以不静默——启动打印 Warning 行。

### 9.4 WK1 · 读得舒服（已交付）

**交付**（代码在 `src/chagent/web/static/markdown.js` 与 `app.js`）：

- Markdown 子集渲染：标题、列表、引用、表格、代码块、行内代码、链接。**先转义再渲染，禁止内联 HTML**，链接只允许 `http(s)`。安全模型见[网页对话设计](网页对话设计.md)「回答的渲染」。
- 代码块：语言标签、一键复制、横向滚动、不换行折断。
- 流式渲染按 `requestAnimationFrame` 节流，避免每个 token 触发一次重排。
- 滚动跟随：贴底时自动跟随；用户上翻后停止跟随，右下角出现「回到最新」。
- 超过 2 000 字的回答默认折叠，保留前 8 行。
- 消息级「复制」。

**验收**：含代码块、表格、`<script>alert(1)</script>` 的回答渲染正确且不执行脚本（`tests/test_markdown_render.py` 6 项，跑的是真实文件，不是 Python 复刻）；流式输出时页面无明显抖动；上翻后新内容不抢滚动位置。**不做**：富文本编辑器、图片内联渲染、数学公式。

### 9.5 WK2 · 改得动（已交付）

**交付**：

- **重新生成**：`POST /api/sessions/{id}/runs` 增 `regenerate_from=<message_id>`，以该助手消息之前的历史为上下文新建 run，不写第二条用户消息。
- **编辑并重发**：增 `edit_message_id` + 新文本；旧消息保留原始内容，界面上折叠为「已编辑的原文」。
- **旧回答折叠**：`messages` 增可空列 `superseded_by`（迁移 `0016_message_supersession.sql`）。退休的是一个**后缀**而不是一个点：回放过滤 `superseded_by IS NULL`，阅读不过滤。
- **失败重试**：错误气泡上的「重试」复用 `regenerate_from`，不新写用户消息，也不重复注入上一轮的失败事实。

**验收**：重生成产生新 run，旧回答折叠且可展开；编辑后历史不被改写（原始内容仍在库里，`tests/test_web.py` 逐字断言）；替换目标先校验再建 run（问句不能重新生成、回答不能编辑、跨会话 404、两个字段同时给 400）。**不做**：消息树／分支切换。

**两处被这一批改对的旧假设**（原先只对「一个 run 必有自己的用户消息」成立）：`RunState.current_input` 退化为最近一条用户消息；`BasicContextBuilder` 在没有本 run 消息时把最后一组当当前轮；`ContextManager` 把这一组排除在可摘要范围外。缺了这三处，重新生成会以 `ContextIntegrityError` 或 `RuntimeError: coroutine raised StopIteration` 结束——实测就是这样失败的。
