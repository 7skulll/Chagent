# 任务经历与短索引

任务经历是历史线索，不是已审核的长期事实、当前任务状态或用户指令。它与 `memories` 表分开存储，不参与 `MemoryService.enrich` 的自动注入。

一个得到最终模型回答的运行，在 `runs.finish` 的完成事务中写入一条 `task_recaps`。记录包含工作区、会话、运行、原始用户消息和最终回答消息 ID、当时显式维护的 TaskState，以及经过明显凭据遮盖的短摘录。记录以 `run_id` 为主键，重复完成不会复制。显式 `/remember` 和没有最终回答的工具停止运行不生成经历。读取结果明确标记 `run_outcome=answer_recorded`、`task_completion=unknown_without_current_verification`；回答完成仅说明本轮产生了回答，不等于任务已验证完成。TaskState 中的 pending 可保留明确记录的待办，记录不推断偏好或项目事实。

`search_task_history` 只返回当前会话工作区最近的短索引，最多 20 条，默认工具读取 12 条；`read_task_history` 通过运行 ID 读取同工作区的一条经历，并从源消息按需生成较长摘录。网页的长期记忆弹窗也可查看近期任务经历，API 为 `GET /api/task-history?query=...` 和 `GET /api/task-history/{run_id}`。索引和详情都不跨工作区；若原回答被重新生成或编辑所取代，旧经历立即从读取结果中消失。旧工作区仍未绑定时不能读取其经历。

摘录由程序确定性截取，避免二次模型调用和未经审核的推断；原会话消息仍是最终证据。凭据遮盖只覆盖明显模式，不能保证识别任意秘密。当前版本不回填来源不明的旧会话，不做跨会话的模型语义合并，也不把任务经历提升为已生效记忆。
