# 会话与上下文基础管理

## 本次实现

| 模块 | 已实现 |
|---|---|
| SessionManager | 创建、查询、按工作区分页、重命名、归档与恢复 |
| 历史管理 | 按消息序号向前分页，原始记录保持不变 |
| TaskState | 显式目标、约束、决定、待办、来源与修订号 |
| ContextBuilder | 预算选择、完整轮次裁剪、工具配对检查、元数据隔离 |
| ContextSnapshot | 选中来源、每条消息选择理由、预算与估算方式 |
| 命令行 | 管理会话、维护任务状态、查看上下文快照 |

真实模型与固定响应模型共用这些接口，[本地网页](网页对话设计.md)也复用会话与上下文管理。[自动历史摘要](上下文压缩设计.md)与[长期记忆](长期记忆设计.md)已接入；显式 TaskState 的自动约束抽取仍未实现。API Key 与模型选择见[模型配置](模型配置.md)。

## 类与数据流

```text
CLI / 本地网页
  → SessionManager
      → ConversationRepository
          → sessions / task_states / messages

AgentRunner
  → 开始运行（锁定会话，检查归档和活动运行）
  → 读取工作区、显式 TaskState 和合法历史
  → ContextBuilder.build
      → 检查消息与工具调用完整性
      → 注入系统规则、工具声明与显式任务状态
      → 预留输出和安全余量
      → 保留当前运行，选择较新的完整历史轮次
      → 返回 ModelRequest + ContextSnapshot
  → 保存请求与快照
  → 模型与工具循环
```

SessionManager 负责调用方输入校验与会话操作；Repository 负责具体 SQL 和事务。ContextBuilder 只处理传入数据，不查数据库、不修改历史，也不写入任务状态。

## 会话管理规则

- 创建会话时验证工作区确实为目录，保存规范化路径；后续继续会话使用已保存工作区。
- 会话列表按创建时间和 ID 倒序，以 `next_cursor` 做稳定分页；重命名不会改变此排序。
- 默认不列出归档会话，设置 `include_archived` 可以同时读取活动与归档会话。
- 归档保留消息与运行记录；归档会话不能启动新运行，恢复后可以继续。
- 活动运行期间可以重命名，但不能归档或修改 TaskState。
- 归档、任务状态更新和运行启动共享会话行锁，避免检查与更新之间的竞争。
- 不提供清空或永久删除；新目标可以创建新会话。

历史分页从最新消息向前读取，每页内部按时间顺序排列。下一页使用 `next_before`，不以可变页码定位。分页是检查原始记录的接口，不将任意一页直接作为模型上下文。

## 显式任务状态

```text
TaskState
  goal                  当前目标
  constraints           明确登记的约束
  decisions             已作出的决定
  pending               未完成事项
  source_message_ids    本会话原始消息引用
  revision              更新版本号
```

状态由用户或调用方显式维护，不根据模型回答自动更新。来源必须属于同一会话，不能引用其他项目或会话的消息。

更新需要提供 `expected_revision`。更新成功后版本加一；版本冲突返回 StateConflictError，调用方应重新读取后决定如何修改，不盲目覆盖。

Runner 在开始运行后读取状态，运行期间禁止更新，使该运行使用固定版本。每次上下文快照保存这一版本号；完整请求保存当时的状态文本，因此后续状态更新不会改写过去请求。

普通历史中尚未登记为 TaskState 的要求仍然是普通历史，会受到裁剪影响。当前没有自动识别全部早期约束的能力。

## 上下文预算与裁剪

```text
input_budget = model.context_window - output_reserved - safety_reserved
```

ContextPolicy 默认预留模型的 `max_tokens` 作为输出预算，安全余量为 256，历史消息软上限为 200。可通过构造函数注入其他策略。

选择顺序：

1. 保留基础指令、工具定义与显式任务状态。
2. 保留历史中的系统规则；当前运行可在完整工具交换边界压缩，保留原始用户输入和最新完整交换。没有运行 ID 时至少保留最新用户轮次，详见[第二版设计](长任务与工具产物设计.md)。
3. 从新到旧加入完整用户轮次，直到达到预算或历史消息上限。
4. 一旦某个历史轮次无法纳入，停止加入更早轮次，保持连续的近期历史。

一轮由用户消息开始，包含由它引发的模型请求、工具调用和结果。不会只留下孤立工具结果，也不机械删除单条消息来凑预算。

200 条是可选历史的软上限：工具配对完整性优先于这一数量限制。大工具文本通过产物引用进入上下文；压缩后若必需内容仍超预算，记录 `context_rejected` 并使运行失败，不截断原始用户输入或拆开工具批次。

原始消息、文件结果和旧请求快照不因裁剪而删除。裁剪是当前请求的视图选择，不是会话清理。

### token 估算

默认 ByteTokenCounter 使用消息 JSON 的 UTF-8 字节数加每条消息开销作为保守估算，计入工具声明和任务状态。它不是供应商 tokenizer，也不保证与未来实际 API 格式完全一致。

TokenCounter 是可替换接口。真实模型接入时应提供适用的计数方法；实际供应商用量与本次估算分开保存，不将估算伪装成实际消耗。

### 工具与元数据

构建前检查工具调用 ID、工具名称和结果是否配对，拒绝缺失、重复或孤立的工具结果。当前运行只能在完整工具批次结束后构建下一次模型请求。

模型视图不自动包含工具的 UI details、历史 token 用量或执行耗时；原始存储仍保留这些数据。构建使用副本，不因规范化或调用方修改请求而改变持久化历史。

失败、取消和中断运行保持可检查，但当前基础策略不将其原始消息回放给模型，以免携带未完成的工具批次。失败后的状态摘要尚未实现。

## 上下文检查

每次成功构建记录：

- 当前策略与 token 估算器名称。
- 输入预算、输出预留、安全余量和估算 token。
- 选入的原始消息 ID。
- 每条历史消息的选入状态及理由：system_instruction、current_turn、recent_complete_turn、summarized、token_budget 或 history_limit。
- TaskState 修订号。
- 使用的摘要 ID、版本、覆盖边界和未做选择裁剪前的投影估算。
- 注入的长期记忆 ID、版本、作用范围和用量；候选不会注入。

预算拒绝发生在模型调用之前，保存拒绝事件与原因，不伪造模型请求记录。旧版本已经保存的快照保留原有格式，不重新计算成新策略的结果。

## 使用示例

```sh
# 创建与查看会话
uv run --env-file .env python -m chagent.sessions create --title "项目开发"
uv run --env-file .env python -m chagent.sessions list --limit 20
uv run --env-file .env python -m chagent.sessions show <会话UUID>

# 重命名、归档与恢复
uv run --env-file .env python -m chagent.sessions rename <会话UUID> "新标题"
uv run --env-file .env python -m chagent.sessions archive <会话UUID>
uv run --env-file .env python -m chagent.sessions restore <会话UUID>

# 查看历史、任务状态和请求选择记录
uv run --env-file .env python -m chagent.sessions history <会话UUID> --limit 20
uv run --env-file .env python -m chagent.sessions state <会话UUID>
uv run --env-file .env python -m chagent.sessions context <会话UUID> --limit 5

# 首次状态修订；后续使用读取到的最新 revision
uv run --env-file .env python -m chagent.sessions state <会话UUID> \
  --expected-revision 0 \
  --set-json '{"goal":"完成基础设施","constraints":["不修改现有业务文件"],"pending":["运行验证"]}'

# 使用同一会话继续原有执行链路
uv run --env-file .env python -m chagent --session <会话UUID> "继续"
```

本次迁移为 `0003_sessions.sql`，增加会话更新时间、归档时间与 task_states。命令入口会应用尚未执行的迁移，也可使用 `python -m chagent.storage migrate` 显式执行。

## 基础验证

测试覆盖会话分页与工作区过滤、历史无缺口、归档阻止新运行、活跃运行阻止状态修改、并发版本冲突、来源隔离、任务状态注入、预算拒绝、完整工具配对、UTF-8 估算和原始记录不变。

当前模型上下文加载仍会读取该会话的全部合法历史，再依据摘要边界做预算选择；数据库侧按完整轮次限量加载仍作为后续性能优化。自动摘要已通过新增编排层接入，见[上下文压缩设计](上下文压缩设计.md)。
