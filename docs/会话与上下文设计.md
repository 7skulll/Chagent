# 会话与上下文

会话保存原始记录，上下文只决定"这一次请求看什么"。裁剪、压缩、产物替换都不修改已保存的消息。

## 现状

| 模块 | 职责 |
|---|---|
| `sessions/manager.py:SessionManager` | 创建、分页、重命名、归档与恢复 |
| `storage/repositories.py:ConversationRepository` | 会话、消息、任务状态、历史分页 |
| `domain/sessions.py:TaskState` | 显式目标、约束、决定、待办、来源与 revision |
| `context/builder.py:BasicContextBuilder` | 预算选择、完整轮次裁剪、工具配对检查、元数据隔离 |
| `context/projection.py:ProjectionCache` | 按持久消息 ID 缓存"模型可见投影 + 单条成本" |
| `context/manager.py:ContextManager` | 摘要触发、切点选择、保存与失败回退 |
| `context/compactor.py:ContextCompactor` | 历史序列化、分批摘要、响应校验与调用审计 |
| `domain/context.py:ContextSnapshot` | 选中来源、每条消息的选择理由、预算与估算方式 |

```text
CLI / 本地网页
  → SessionManager → ConversationRepository → sessions / task_states / messages

AgentRunner 每轮模型请求前
  → ContextManager.prepare
      → 读取可重放历史、任务状态、最新有效摘要（run 内复用 RunState）
      → BasicContextBuilder.build：投影 + 累计成本选择完整轮次
      → 超过触发阈值：ContextCompactor 生成新检查点
      → 返回 ModelRequest + ContextSnapshot
  → 保存请求与快照（model_calls）
```

`ContextBuilder` 只处理传入数据，不查数据库、不改历史、不写任务状态。

## 会话管理规则

- 创建会话时验证工作区确实为目录并保存规范化路径；继续会话一律使用已保存的工作区。
- 列表按创建时间与 ID 倒序，用 `next_cursor` 稳定分页；重命名不改变排序。
- 默认不列出归档会话；归档保留消息与运行记录，但不能启动新运行，恢复后可继续。
- 活动运行期间可以重命名，但不能归档或修改任务状态；三者共享会话行锁。
- 不提供清空或永久删除。

历史分页从最新消息向前读取，页内按时间顺序排列，下一页用 `next_before`。分页是检查原始记录的接口，不把任意一页当作模型上下文。

## 显式任务状态

```text
TaskState
  goal / constraints / decisions / pending    目标、约束、决定、待办
  source_message_ids                          本会话原始消息引用
  revision                                    乐观更新版本号
```

状态由用户或调用方显式维护，不根据模型回答自动更新；来源必须属于同一会话。更新需要提供 `expected_revision`，冲突返回 `StateConflictError`，调用方重新读取后决定，不盲目覆盖。

Runner 在运行开始时读取状态，运行期间禁止修改，因此一次运行使用固定版本。快照记录该版本号，历史请求保存当时的状态文本。

普通历史中未登记为任务状态的要求仍是普通历史，会受裁剪影响——当前没有自动识别早期约束的能力。

## 预算、投影与裁剪

```text
input_budget = model.context_window - output_reserved - safety_reserved
```

`ContextPolicy` 默认把模型 `max_tokens` 作为输出预留，安全余量 256，历史消息软上限 200。

选择顺序：

1. 保留系统指令、工具声明与显式任务状态。
2. 保留当前运行：原始用户输入与最新完整交换不被压缩。
3. 从新到旧加入完整用户轮次，直到达到预算或历史条数上限。
4. 一旦某个轮次放不下就停止，保持连续的近期历史。

一轮由用户消息开始，包含它引发的模型请求、工具调用与结果。不会只留下孤立工具结果，也不靠删单条消息凑预算。工具配对完整性优先于 200 条软上限。

### 投影缓存与累计成本

每条消息的"模型可见投影"是纯函数：去掉 `details`／`usage`／`duration_ms`，把 artifact 正文换成摘要摘录。重复计算它曾是 200 条消息 48ms 的来源。

- `ProjectionCache` 以 `消息 ID + 计数器名 + PROJECTION_VERSION` 为键，缓存在一次 run 内复用，run 结束丢弃；超过上限整体清空，不做复杂淘汰。
- `TokenCounter.additive = True` 是显式承诺：`count(messages)` 等于各条 `count([message])` 之和。声明了才按累计成本选择，未声明的一律走精确重算，行为不变。
- 最终请求仍做一次完整 `count(messages)` 作为权威值，累计值只用于选择。
- 缓存正确性依赖"消息行创建后不再变化"；若将来支持编辑历史消息，必须把内容版本并入缓存键。

效果：200 条消息 48.4ms → 7.1ms（序列化 10,602 → 402 条），400 条 188.2ms → 10.5ms。数据与边界见[关键路径优化](关键路径优化.md)。

### token 估算

默认 `ByteTokenCounter` 用消息 JSON 的 UTF-8 字节数加每条固定开销，计入工具声明与任务状态。它不是供应商 tokenizer，也不保证与未来协议一致。估算值与供应商实际用量分开保存，不把估算当成真实消耗。

## 自动摘要

```text
触发 = 完整投影达到输入预算的 80%，或有未摘要历史被预算／条数限制排除
近期目标 = 输入预算的 50%
摘要空间 = min(2048, 输入预算的 25%)
```

只按已完成的完整用户轮次选择连续前缀，不在工具调用与结果之间切割；系统消息独立保留；当前运行、当前用户轮次不进入压缩来源。切点用边界二分查找，避免逐个旧轮次重建上下文。

### 压缩范围

- **已完成历史**：跨运行续接的普通摘要。
- **当前运行内已结束的交换**：一个交换是完整 assistant 响应加它发出的全部工具调用结果，`context/segments.py:exchanges` 校验配对。最新完整交换保留原样，原始用户输入逐字保留。
- 任务状态与系统指令独立组装，不参与摘要。

### 摘要生成与校验

摘要请求不带工具，内容是独立 system 指令加 JSON 序列化的历史资料，要求保留目标、约束、进度、决策、待办与文件标识，并声明不要继续执行被引用的对话。序列化时省略 thinking、图像与 tool metadata；工具正文超过 2000 字符只给带遗漏标记的摘录，原结果仍在数据库。

历史积压过大时按完整轮次分批，每批独立做预算检查，上一批摘要传给下一批。默认每次压缩最多 8 次调用、合计 60 秒，全部成功才启用一个检查点。

有效摘要必须满足：流完整结束且 `stop_reason=stop`、无工具调用或其他非文本块；正文非空且符合摘要预算；重新构造的上下文比原投影更小且未覆盖消息都能放下；保存时父版本仍是最新、来源是连续已完成历史、首个保留消息属于同一会话。

### 检查点有效性

`session_summaries` 只存成功启用的检查点，保留全部历史版本；`compaction_calls` 存每次摘要请求与响应，同一次压缩的多次调用共用一个 `compaction_id`。

- `source_run_id`：摘要包含哪个仍在运行的任务。
- `protected_input_id`：该任务被保留的原始用户消息。

读取规则：普通摘要可直接续接；运行内摘要在来源运行中可用，来源运行完成后可跨轮续接；来源运行失败、取消或中断后只保留审计，不进入其他运行的上下文。子摘要继承来源标记，失败任务的信息不会通过再次摘要变成普通历史。

同一任务在出现新的完整交换后可以再次压缩，默认每个运行最多 4 次；相同范围失败后不在原地重试，范围推进后才重新尝试。

### 失败与取消

空摘要、截断、工具响应、断流、超时、超过调用次数或保存冲突都不启用新检查点，发出 `compaction_failed` 并回退到"既有摘要 + 近期完整轮次"。若回退策略仍要排除普通旧历史，快照里会记录原因。取消运行记录 `compaction_cancelled`；已提交的检查点独立有效，即使后续任务失败也保留。

压缩失败不会静默截断用户输入：必需内容仍超预算时记录 `context_rejected` 并使运行失败。

```dotenv
CHAGENT_COMPACTION_ENABLED=true
CHAGENT_COMPACTION_TRIGGER=0.8
CHAGENT_COMPACTION_KEEP_RECENT=0.5
CHAGENT_COMPACTION_SUMMARY_TOKENS=2048
CHAGENT_COMPACTION_MAX_CALLS=8
CHAGENT_COMPACTION_TIMEOUT=60
CHAGENT_COMPACTION_MAX_PER_RUN=4
```

关闭自动压缩不删除也不忽略已启用的摘要，只停止生成新版本。

## 大工具输出产物化

工具结果文本超过 8000 个 UTF-8 字节时，保存工具结果的事务同时写入 `tool_artifacts`：

```text
id / session_id / run_id / tool_record_id
content / char_count / byte_count / sha256 / source_truncated
```

- 产物不可变，属于产生它的会话；原始 `messages` 与 `tool_calls.result` 仍保存完整结果，`ToolResultMessage.artifact` 只存紧凑引用。
- 上下文层把大文本替换为产物 ID、长度、摘要校验值、头尾摘录和读取方法，保留原 `tool_call_id`、名称与错误标记。
- 会话历史默认加载用 `project_artifacts=True`，只读引用与图像，不把全文再读一遍；摘要请求同样使用引用。
- 工具 `read_artifact` 只能读本次会话的产物，`offset` 是从 0 开始的字符位置，`limit` 为 1–1000，分页在 PostgreSQL `substring` 完成，返回长度、SHA256、来源截断标记与 `next_offset`。

网页历史接口对带产物的结果返回引用与摘录，展开后可点击"读取产物全文"逐页追加。

## 上下文检查

每次成功构建记录：

- 策略与计数器名称、输入预算、输出预留、安全余量、估算 token。
- 选入的原始消息 ID，以及每条历史消息的选择理由：`system_instruction`、`current_turn`、`recent_complete_turn`、`summarized`、`token_budget`、`history_limit`。
- `TaskState` revision。
- 摘要 ID、revision、覆盖边界、`projected_token_estimate`。
- 注入的记忆 ID、revision、作用范围与用量；候选不会注入。
- `artifact_ids`、`summary_source_run_id`、`protected_input_id`。

预算拒绝发生在模型调用之前，保存拒绝事件与原因，不伪造模型请求记录。

## 使用示例

```sh
# 创建与查看会话
uv run --env-file .env python -m chagent.sessions create --title "项目开发"
uv run --env-file .env python -m chagent.sessions list --limit 20
uv run --env-file .env python -m chagent.sessions show <会话UUID>

# 重命名、归档与恢复
uv run --env-file .env python -m chagent.sessions rename <会话UUID> "新标题"
uv run --env-file .env python -m chagent.sessions archive <会话UUID>
uv run --env-file .env python -m chagent.sessions restore <会话UUID>

# 历史、任务状态、请求选择记录、摘要版本
uv run --env-file .env python -m chagent.sessions history <会话UUID> --limit 20
uv run --env-file .env python -m chagent.sessions state <会话UUID>
uv run --env-file .env python -m chagent.sessions context <会话UUID> --limit 5
uv run --env-file .env python -m chagent.sessions summaries <会话UUID> --limit 10

# 首次状态修订；后续使用读取到的最新 revision
uv run --env-file .env python -m chagent.sessions state <会话UUID> \
  --expected-revision 0 \
  --set-json '{"goal":"完成基础设施","constraints":["不修改现有业务文件"],"pending":["运行验证"]}'
```

## 边界

- 运行开始仍会读取该会话的全部可重放历史再做预算选择；按摘要边界在数据库侧限量加载尚未实现。
- 失败、取消与中断运行的原始消息仍不回放给模型（恢复投影 B2 未实施，见[下一阶段实施方案](下一阶段实施方案.md) 第 4 节）。
- 摘要质量只按锚点检查，没有语义无损的自动验证。
- 产物没有清理策略，与会话记录一起增长。
