## 发现的问题

### 1. 回答结束时强制跳到底部

复现：让真实模型执行搜索与抓取，在运行过程中上翻阅读历史。记录到 `#conversation` 的 `scrollTop=549.58`、`scrollHeight=2406`、`clientHeight=285`；运行结束后变成 `scrollTop=4282.5`、`scrollHeight=4570`、`clientHeight=287`，重新位于最底部。没有点击「回到最新」。

代码原因：`connectRun` 的 SSE `end` 事件调用 `openSession(state.session)`；`openSession` 重新渲染消息并无条件调用 `scrollBottom()`，覆盖此前的阅读位置。流式期间的 `follow` 判断不能保护这一结束路径。

后续修复要求：区分主动打开会话和同一会话运行结束的刷新；后者在用户已经上翻时保留阅读锚点，用户仍在底部时继续跟随。用真实浏览器分别复验两种状态。

### 2. 长网页截断使目标核对无法完成

测试问题：搜索 Python 官方文档中的 `pathlib.Path.read_text`，抓取官方页面核对，并用两句中文概括、附官方链接。

实际：搜索结果包含 python.org 邮件列表与第三方镜像；官方 pathlib 页抓取在 20,000 字符附近截断，目标方法位于截断之后。模型使用 1 次搜索、4 次抓取、1 次 grep 和 2 次 read_artifact，仍未获得目标条目。最终回答披露了未能读到官网目标段落的限制，提供了来源，但也加入了额外说明，未严格满足两句要求。

因此这里只证明真实搜索、抓取、来源 UI 可用，**不能把“官方目标段落已核对”记为通过**。更换 URL 锚点不会自然解决供应商返回整页前部再截断的问题；需研究按片段检索、保留完整抓取结果后分页，或明确限制并减少无效补抓。

### 3. 错误与语言细节

- 上传存储故障显示英文 `Server request failed`。重试可用，但用户无法从提示区分磁盘权限与网络失败。
- 中文任务的若干工具前置说明为英文。最终附件回答为中文，仍有语言一致性问题。
- 空态仍显示代码项目专用起手式（找 src 的 TODO、解释 src/chagent），与默认 work 模式的通用文件工作区定位不完全匹配。本项为界面观察，不是功能失败。

## 验收后修复与复验（2026-11-02）

以下为后续修复记录，上文保留首次验收事实。代码未提交；保留了验收前已有改动。

- **滚动重置已修复**：SSE 结束刷新同一会话时，在用户上翻的情况下恢复原消息锚点和相对位置；仍在底部时继续跟随，主动切换会话仍显示最新。DOM 回归分别覆盖三个分支。真实模型生成 120 条建议时，上翻后的 `scrollTop=0`，当时仍在生成、`scrollHeight=7210`；回答完成并折叠长文后 `scrollTop` 仍为 0（`scrollHeight=5733`），「回到最新」仍可用。
- **长网页目标读取已修复**：`web_fetch` 增加 `find`（不区分大小写的字面查找）和 `offset`，返回 `next_offset`、`match_offset`；缓存供应商返回的完整正文，按 URL 去掉 fragment 后复用，避免换锚点重复抓取。仍保留单次正文上限和响应体上限，缓存过期后需重新抓取。自动测试覆盖尾部命中、分页、缓存复用、查无结果和越过末尾。
- **真实长网页复验通过**：在 8877 的真实 `deepseek-flash` 会话中，模型只调用一次 `web_fetch`，参数 `find="read_text", max_chars=6000`。实际正文 55,530 字符，命中位置 32,224，返回 offset 31,724 / next_offset 37,724。展开工具结果，明确读到官方 `Path.read_text(encoding=None, errors=None, newline=None)` 定义、自动关闭、3.5 引入与 3.13 新增 newline 的原文，最终中文回答有官方链接。复验没有重新覆盖搜索排序；原搜索和来源 UI 的通过结论保持。
- **上传报错已修复**：目录权限错误为中文 403，磁盘空间不足为中文 507，其他存储错误为中文 500，不显示底层文件路径；网络错误继续使用原有独立文案。真实浏览器故障注入显示「上传目录不可写，请检查工作区权限后重试」；恢复 0700 后点击重试，107 B 上传成功。磁盘满及其他 I/O 错误通过故障注入单元测试验证，未实际填满磁盘。
- **语言与空态已调整**：系统指令要求回复和进度跟随用户语言、遵守长度与格式；空态标题改为「今天想处理什么资料？」，起手式改为工作区资料清点、文档概括和下载摘要。模型格式遵循仍是软约束：本次方法概括之外仍有一句前置说明与来源行，不能宣称任意“两句”要求都严格满足。
- **回归结果**：最终完整 unittest **512 项通过、0 跳过，93.129 秒**，包括 PostgreSQL 集成测试和本机沙箱测试。首轮发现的旧 edit_file 提示指引与环境注入断言不一致已处理：保留“工具可用时才编辑”的条件指引，环境注入测试断言无工作区标题。`git diff --check` 通过。
