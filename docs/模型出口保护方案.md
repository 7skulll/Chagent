# 模型出口保护方案

2026-11-05。方案已按下述模型出口与工具入参映射落地；自动测试和真实模型证据见[验收第 20 节](验收记录汇总.md#20-模型出口路径保护2026-11-05)。下文保留原设计及尚未验证的范围。

## 边界与目标

宿主主控保留真实路径作为数据库身份、文件系统根和本机审计值。模型侧只使用虚拟 `/workspace`；文件工具、命令、网站和原生工具收到虚拟路径时必须还原到当前会话工作区，不能借此访问其他目录。模型请求发出前检查最终供应商 payload：真实工作区绝对路径先映射为 `/workspace`，若仍含 Chagent 程序源码保护根路径则拒发并留下 run 审计。旧会话、摘要、记忆、上传文本与网页正文都必须走同一出口检查，不依赖写入时过滤。

## 实施顺序

1. **单一映射器**：按当前工作区规范化根路径做边界匹配，模型可见文本与工具调用历史的绝对路径映射为 `/workspace`；工具返回的虚拟路径在执行前还原。相对路径保持原样。不得改写落库的宿主审计、用户工作区文件或 HTML 页面显示的本机路径。
2. **工具执行**：文件路径与补丁头的虚拟根还原为工作区相对路径；命令、网站和宿主原生命令的 `workdir` 及命令正文还原为当前宿主根。文件执行层继续拒绝 `..` 越界和指向别的宿主目录的绝对路径。本机真实命令行只用于执行与审计，返回模型时仍映射为虚拟根。
3. **出口钩子**：在 HTTP 适配器组好 OpenAI/Anthropic payload 之后、发起 `POST` 之前检查，覆盖 task、summary、memory 三类请求和重试。命中受保护源码路径时拒绝，不回退到无检查发送；审计只记命中类别、run ID 和请求用途，不存泄露片段。
4. **验收**：两个不同宿主目录的真实工具结果、命令 `pwd`、网站和宿主审批结果在模型请求里都只见 `/workspace`；模型用 `/workspace` 调文件与命令可执行；旧历史和记忆中的真实路径被映射；命中程序源码保护根的请求零出网且有审计。分别测 OpenAI 与 Anthropic payload、摘要与记忆后台请求。真实模型网页验收不能只凭模型自述，以请求捕获和工具记录为准。

当前已验证：双供应商 payload、真实 DeepSeek 文件工具闭环、保护路径零出网与数据库事件。宿主原生命令、`site`、摘要和后台记忆的真实供应商路径仍需各自专项验收；自动化回归覆盖它们共用的出口函数，但不等于专项实测。

## 限制

这是路径字符串保护，不扫描图片、二进制与任意编码，也不承诺绝对防外泄。用户主动要求模型处理的其他机器路径不会被猜测为受保护目录。容器仍有现有的文件与网络权限；出口保护不改变其隔离强度。
