# 工作区与文件编辑器实施方案

日期：2026-11-03（Asia/Shanghai）。状态：F1–F4 已实施并验收，F5 待实施。本文只记录需求、设计与分批划分；**当前实现契约、接口和证据统一在[工作区 F1–F4 实施与验收](工作区F1-F4验收-2026-11-03.md)**。文中“目标”“应”描述的是设计意图，不等于已交付能力；两者不一致时以验收记录为准。

本方案是工作区与文件编辑功能的专题实施细化；项目总体路线见[实施计划](实施计划.md)。已有可信开发代码闭环见[开发版验收](代码开发验收-2026-11-03.md)。实施时复用现有 Runner、会话、数据库和文件工具，不另建一套 Agent。

## 1. 已确定的产品要求

以下来自用户明确要求，作为首版范围：

1. 会话记录按工作区分组。用户可以在已有工作区创建新对话，也可以新开一个工作区。
2. 用户选择本地文件夹作为工作区，直接操作原目录；生成的输出文件也放在该工作区。
3. 中间是聊天，右侧侧边栏查看文件结构、打开文件和编辑文件；可以自由调整面板比例。
4. 首版编辑代码、Markdown、TXT、JSON、CSV 等文本文件；PDF、图片提供预览。
5. 手动保存。用户修改后明确提醒需要保存，不静默自动写入磁盘。
6. 用户始终可以在编辑器手动编辑；Chagent 在 work 和 code 两种模式都可以修改已有文件及上传文件。覆盖同名输出时提示确认。
7. 首版包含新建文件、新建文件夹、重命名和删除。

后文的上传目录、回收站、大小限制、标签页与冲突按钮等属于本方案建议的首版默认设计；它们不是用户额外指定的要求。实现中若需改变，应记录理由并更新本方案。

## 2. 当前基础与变化范围

| 方向 | 当前可复用内容 | 本轮变化 |
|---|---|---|
| 工作区 | workspaces 表、路径准入、工作区列表和打开接口 | 文件夹选择、工作区分组导航、最近工作区与不可用状态 |
| 会话 | 会话已关联工作区，支持创建、搜索、归档和恢复 | 工作区内创建、按组展示和切换恢复 |
| 文件访问 | WorkspaceFS、目录描述符、no-follow、文件身份检查、读取/写入/编辑/补丁 | 统一文件服务、编辑器 API、目录创建/重命名/回收与版本冲突 |
| 网页 | 静态 HTML/CSS/JavaScript、聊天、右侧产物与上下文面板 | 文件树、编辑器、预览、多标签、拖动比例 |
| Agent | work 资料工具；可信开发 code 的写工具、执行和测试 | 普通 work/code 都可写文件；命令执行仍是 code 能力 |
| 输出 | create_file 生成数据库下载；上传落入工作区 | 输出落盘、聊天文件链接、编辑器打开、同名确认 |

本方案明确调整现有“网页 work 禁写”的行为，不可只改界面文案或只打开 code 的 writable 开关。工具注册、网页实际 runner 校验、输出工具、配置显示与对应测试必须同步更新。此前“work 保持禁写”的记录是历史交付事实，不作为本轮新需求的限制。

只读代码分析如保留，应作为用户显式选择的只读配置，名称和能力显示清楚；新普通工作流程的 work/code 都允许文件编辑。不能在界面声明可写时继续由旧只读门禁裁掉写工具。

## 3. 工作区与会话组织

### 3.1 左侧导航

```text
＋ 打开文件夹

项目 A
  ＋ 新对话
  对话一
  对话二

资料文件夹 B
  ＋ 新对话
  对话三
```

- 首次使用先选择文件夹，再开始聊天；已有工作区内新建会话不再要求重选目录。
- 同一真实路径复用同一工作区；不同路径的同名文件夹分别展示，并用父目录辅助区分。
- 打开历史会话时同步切换到它所属的工作区；右侧文件树与文件操作目标随之切换。
- 保留会话搜索和归档，默认搜索当前工作区；明确提供跨工作区搜索入口时，结果必须标明工作区。
- 工作区登记和会话关联保存在数据库，重启可恢复列表；不持久化文件夹全部内容。
- 重新进入工作区时重新校验目录和准入条件，不能把历史登记当作永久通过检查。
- 目录缺失、移动或权限不足时显示不可用原因，保留历史记录。重新定位需显式选择目标，不能按文件夹名称自动绑定到另一个目录。
- “从列表移除工作区”不删除原目录，也不等同于删除工作区中的文件。

### 3.2 选择文件夹

首版面向本机 macOS，点击“打开文件夹”后由本机服务调用系统目录选择器；用户取消则无状态变化。选中的目录经过现有准入检查后登记为工作区。

不能用浏览器目录上传代替打开原目录：上传会复制内容，无法表达持续操作用户原目录的语义。选择器不可用时提供手工输入路径的明确退路。具体平台调用方式在实现时验证；当前网页仍是本机单用户入口，不扩展为远程服务器浏览客户端磁盘。

继续拒绝 Chagent 运行源码目录、其子目录及包含它的父目录，保留运行时等已有边界。选择文件夹只授予该工作区，不扩大到其父目录或相邻目录。

## 4. 页面布局

```text
┌─────────────┬────────────────────┬────────────────────────┐
│ 工作区      │                    │ 文件树                 │
│   会话列表  │       聊天         ├────────────────────────┤
│             │                    │ 已打开文件标签         │
│             │                    │ 编辑 / 预览            │
│             │       输入框       │ 保存与未保存提示       │
└─────────────┴────────────────────┴────────────────────────┘
```

- 左侧工作区/会话导航，中间聊天，右侧文件面板。
- 左中、中右之间提供可拖动分隔线；右侧文件树与编辑区之间支持调整高度。
- 支持收起两侧面板，设置最小可用宽度，布局比例在本机记忆；拖动不能让聊天输入或保存按钮消失。
- 窄窗口采用“聊天 / 文件”切换，避免将三个面板挤成不可用窄列。
- 原有“上下文”保留为右侧独立页签；文件树成为右侧默认内容。原有产物入口迁移到文件链接和历史产物区域，保留旧记录可访问性。

## 5. 文件树、编辑和预览

### 5.1 文件树

目录按需展开并分页加载，不在进入工作区时递归扫描全部文件。支持刷新、新建文件/文件夹、重命名、删除和恢复。

默认隐藏 `.git` 等内部目录，提供显示隐藏文件开关。首版回收站 `.chagent/trash/` 不进入默认树、Agent 搜索和上下文；其他隐藏文件是否可见不代表自动授予额外读取范围。

仅访问当前工作区内通过检查的文件；符号链接可以显示为不可打开的链接项，不跟随链接读取、写入或递归删除。非普通文件和硬链接继续遵循既有身份规则，界面给出可理解的限制原因。

### 5.2 文本编辑

- 支持多个打开文件标签，标签和标题展示相对路径。
- 代码、Markdown、TXT、JSON、CSV 等作为文本编辑；CSV 首版不是表格软件。
- Markdown 提供编辑/预览切换，沿用安全渲染规则，预览不执行嵌入脚本。
- 文本编辑大小上限建议沿用现有文件工具的 1 MiB；超限文件展示原因及下载入口。
- 首版以 UTF-8 文本为主。无法可靠解码时只读提示，不用乱码覆盖原文件；保存保持未修改部分的换行约定，遇到无法保真的编码先拒绝编辑并说明原因。
- 浏览或打开文件不自动将完整文件放进模型上下文；Agent 仍通过任务相关工具读取。

### 5.3 PDF 和图片

PDF 提供分页浏览，图片提供缩放预览；首版不直接编辑这两类文件。预览和模型读取是两条能力，图片可预览不代表模型已支持图片理解，扫描 PDF 也不因此获得 OCR。

二进制预览通过受工作区校验的内容接口提供，不把原目录挂为无校验静态文件目录。不支持的格式显示基本信息并提供下载。

## 6. 保存、草稿与修改冲突

### 6.1 手动保存

- 输入只修改编辑草稿；点击“保存”或按 `⌘S` 才写入磁盘。
- 文件标签显示未保存标记 `●`，编辑区显示“未保存”状态；保存失败时草稿保留。
- 关闭有改动的标签、切换工作区、删除/重命名涉及草稿的文件前，提供保存、放弃或取消。
- 切换同一工作区的聊天不丢弃草稿；切回已打开的文件继续显示其草稿。
- 刷新或关闭页面时有未保存内容则触发浏览器离开提醒。首版不承诺崩溃后恢复未保存草稿；浏览器提醒不能替代保存。
- 页面内草稿状态按工作区 ID 和相对路径隔离，不能把 A 工作区的同名文件草稿用于 B 工作区。

### 6.2 版本检查

读取文件返回内容版本（以内容哈希为主）和文件身份，保存请求必须携带读取版本。后端重新检查并使用现有原子替换机制；同一服务内的文件写操作共用工作区协调机制。

| 情况 | 处理 |
|---|---|
| 文件版本未变化 | 保存并返回新版本，清除未保存标记 |
| Agent 或外部程序修改了磁盘文件 | 冲突提示，保留用户草稿，不自动覆盖 |
| 文件被删除或路径变化 | 提示位置失效，允许另存为 |
| 权限不足、磁盘已满等写入错误 | 显示具体原因，保留草稿 |

冲突时提供查看磁盘版本、另存为、确认覆盖；确认覆盖仍绑定最新版本，不能凭旧确认覆盖此后出现的新修改。首版不做自动合并。

Agent 写入后，已打开且无草稿的文件可重新加载；有草稿则只提示磁盘已变化。浏览器重新获得焦点、保存前和手工刷新时也重新检查外部变化。首版优先采用按需检查/有限轮询，不要求立即引入跨平台全盘文件监听。

版本检查用于减少正常并发覆盖，不宣称能防同一 OS 用户恶意并发替换，或让任意 Shell 写入与编辑器形成文件事务。同工作区不同会话的 Agent 写入和手动保存需要共享协调；长进程可能写文件的限制必须在实现与验收中说明。

## 7. 新建、重命名和删除

- 新建文件/文件夹位于用户选中的目录；校验名称，禁止父目录穿越和根目录替换。
- 文件及目录重命名默认不覆盖已有目标；撞名时提示用户改名，不静默合并目录。
- 目录重命名成功后更新已打开文件的路径；涉及未保存草稿时先处理草稿，不能丢失编辑内容。
- 删除前展示目标与影响范围，目录删除不跟随符号链接。不得将工作区根作为普通文件树删除目标。
- 建议删除采用工作区内 `.chagent/trash/` 回收站：确认后移动原对象，记录原路径和回收时间，支持恢复。
- 恢复发生同名冲突时保留现有对象，让用户改名恢复或取消；不直接覆盖。
- 回收站不自动清空；永久清除不作为首版默认删除行为。回收移动失败时不退化为永久删除，明确报错。

用户可以编辑和管理文件，不依赖模型请求或当前会话是否允许命令执行；操作对象始终是当前已打开并通过检查的工作区。切换会话或会话归档不应自动把工作区编辑器变为只读。

## 8. Agent、上传和生成输出

### 8.1 work/code 的文件能力

普通 work 与 code 都注册读取、创建、编辑和补丁工具；code 另外提供配置允许的命令、测试与进程能力。写文件与是否逐次审批分别装配，不重新将文件编辑绑定到未完成的完整 C3 系统。

用户通过界面手动编辑与 Agent 调用文件工具复用文件服务及版本检查，分别记录操作来源。Agent 的文件编辑使用读取版本，不能在未读取最新内容时静默覆盖用户刚保存的修改。

### 8.2 上传与输出落盘

- 上传文件建议默认放到当前工作区 `uploads/`；成功后出现在文件树，返回真实相对路径和文件版本。
- 生成文件默认放工作区根目录；用户指定子目录时按指定路径保存。生成目录不存在时使用明确的目录创建流程。
- 磁盘文件是后续读取和编辑的依据；数据库保留会话记录、来源和必要历史快照，不形成另一份独立可编辑的当前版本。
- 生成/上传/修改结果在聊天中提供“打开文件”和下载；打开前由工作区 ID 与相对路径定位，避免同名串用。
- 编辑已上传文件后，后续读取必须根据当前文件内容与哈希更新解析结果，不继续使用旧上传内容或旧解析缓存。
- 旧数据库生成文件保留历史下载能力，首版不自动批量导出到用户目录；用户主动保存到工作区时遵循同名确认。

### 8.3 同名输出确认

区分已有文件的编辑与生成/上传输出撞名：

| 操作 | 行为 |
|---|---|
| 用户在编辑器保存当前文件 | 版本一致时保存；发生冲突才要求处理 |
| 用户要求 Agent 编辑已有文件 | 正常编辑，必须检查读取版本 |
| 生成或上传文件与已有文件同名 | 提示“覆盖 / 保留两份 / 取消” |
| 用户明确选择另存为且目标同名 | 同样走覆盖确认 |

确认必须由宿主记录，绑定工作区、目标相对路径、已有版本和待写入内容，不接受模型自行声明“已获确认”。取消不写入；确认期间文件变化则失效并重新提示；重复提交不能重复消费。

这是一项限定于文件输出的确认流程，复用现有交互和持久化能力即可，不扩张为命令前缀授权系统。等待、取消、页面刷新和超时行为需覆盖测试；审批/确认等待不能长期持有文件写锁。

任意 code Shell 命令仍可能修改工作区，通用同名检测无法完整拦截其写入。本确认契约覆盖文件生成、上传、另存为等受控接口，不能宣传成“所有命令覆盖文件都会弹窗”。

## 9. 后端与数据设计

### 9.1 统一文件服务

在现有 WorkspaceFS 和 boundaries 基础上增加文件服务，供编辑器 API、上传及 Agent 文件工具共同使用。工作区准入、相对路径、文件身份、版本检查和原子写入不能在三条路径分别实现。

建议的接口能力如下，具体路径命名在实现时统一：

| 能力 | 关键输入/输出 |
|---|---|
| 选择并打开工作区 | 用户选择的本机目录；返回工作区 ID、名称、可用状态 |
| 列目录 | 工作区 ID、相对目录、分页；返回类型、名称与元数据 |
| 读文本 | 工作区 ID、相对路径；返回文本、编码/换行信息和版本 |
| 保存文本 | 相对路径、内容、期望版本；返回新版本或冲突 |
| 文件预览/下载 | 校验工作区与路径后返回受限内容；支持 PDF 必要的分段读取 |
| 新建/重命名 | 目标路径、对象类型或新名称；默认不覆盖 |
| 回收/恢复 | 当前目标、期望身份或回收记录；返回操作结果 |
| 输出确认 | 目标版本、待写内容及单次确认记录 |

接口以工作区 ID 和相对路径标识对象，不能仅依赖前端当前目录。沿用现有本机请求来源校验，文件操作失败不能把底层凭据或不相关宿主路径写进错误。

### 9.2 数据归属

- 复用 workspaces 与 sessions 关联，不重复建立一套工作区概念。
- 工作区列表需支持显示名称、最近使用和失效状态；是否新增字段在核对现有 schema 后确定。
- 文件内容直接保存在源目录；数据库不保存整个目录镜像。
- 输出确认、文件操作记录和回收信息按工作区隔离；单次确认需可在刷新后恢复。
- 布局、展开目录和打开文件标签可作为本机界面状态；不能把这些状态当作工作区授权。

## 10. 分批实施与交付条件

| 批次 | 范围 | 依赖 | 完成条件 |
|---|---|---|---|
| F1 工作区导航 | 原生文件夹选择、分组会话、组内新对话、重启恢复和不可用状态 | 现有工作区/会话基础 | 同目录不重复登记、历史会话恢复正确，选择器取消无副作用，工作区不串用 |
| F2 文件服务与管理接口 | 目录列表、文本读写、版本校验、新建、重命名、回收/恢复 | F1 的工作区标识与准入 | 真实源目录操作正确，越界、身份变化、撞名和保存冲突明确拒绝 |
| F3 右侧文件编辑器 | 文件树、多标签、手动保存、草稿提醒、比例调节 | F2 | 用户可浏览编辑文本，切换/关闭不丢草稿，冲突保留草稿，窄屏可用 |
| F4 Agent 与输出统一 | work/code 文件写入、上传/输出落盘、同名确认、聊天打开文件 | F2、F3 | 两模式能修改已有及上传文件，磁盘结果可见；确认不可伪造/复用，刷新取消可恢复 |
| F5 预览与整体验收 | PDF、图片、外部变更检查、错误恢复、跨流程回归 | F1–F4 | 完整流程通过，预览不被当作模型理解，已有编码/只读/会话能力无回归 |

批次可分别交付，但完整首版包含 F1–F5，不能将首版要求的删除或预览推迟后仍宣布全部完成。目录操作、新输出确认和编辑器并发是本轮主要新增逻辑；不同时重写框架、引入多人协作或云同步。

## 11. 验收矩阵

| 场景 | 必须验证的结果 |
|---|---|
| 初次进入、已有工作区新对话、新工作区 | 目录选择和会话归属正确，取消选择不创建空工作区 |
| 同名目录、同名文件、跨工作区搜索/切换 | 始终用正确工作区，不混用文件、草稿与会话 |
| 重启、目录删除/移动、权限变化 | 历史保留，重新准入，失效有明确提示 |
| 文本编辑与手动保存 | 编辑前不落盘、未保存提示明确、快捷键有效、保存后真实文件一致 |
| Agent/外部程序并发修改 | 旧版本保存被拒，草稿保留；无草稿文件可刷新 |
| 新建、目录重命名、删除、恢复 | 原目录结果正确，打开标签同步，无穿越或隐式覆盖 |
| 同名输出确认 | 覆盖/保留两份/取消分别正确；内容或版本变化后旧确认失效 |
| 上传后编辑、解析缓存 | 后续 Agent 读取新内容，文件树和磁盘一致 |
| PDF、图片、不支持格式、大文件 | 按支持范围预览或明确提示，不执行不可信内容 |
| 中途取消、保存故障、刷新与关闭 | 不丢已保存文件，不误报保存成功，草稿和确认状态行为符合契约 |
| 布局和窄屏 | 比例可调且可恢复，聊天与编辑操作始终可达 |
| 旧功能回归 | 会话历史、SSE、停止、来源、旧产物下载、code 隔离与显式只读配置正常 |

端到端流程：选择文件夹 → 创建对话 → 上传文件 → Agent 修改 → 编辑器打开并手动保存 → 同名输出确认 → 重命名 → 删除与恢复 → 重启恢复工作区和会话。分别在 work、code 路径核对真实磁盘结果，并使用真实模型进行代表性验证。

自动测试、真实文件系统操作、浏览器交互和真实模型分别记录，跳过不计通过；未验证的平台、编码、格式和工具链不能写成已支持。

## 12. 发布、回退与后续文档

每批更新当前行为对应专题和验收记录；本方案保留设计决策与未完成项，不把设计当成交付证据。正式更新总体排期时同步实施计划，避免两处状态相互矛盾。

回退可以隐藏新界面或关闭新入口，但必须保留原目录文件、已保存修改、会话和历史产物。不得以重置 Git、恢复旧快照或自动清理回收站作为程序回退方式。原目录上的已完成编辑不承诺事务回滚。
