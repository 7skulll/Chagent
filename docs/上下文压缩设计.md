# 第一版：上下文压缩闭环

本文保留第一版的实现说明。当前已实现[第二版长任务与工具产物](长任务与工具产物设计.md)，扩展了运行内压缩、检查点有效性和每次运行的多次压缩机制；有关“当前运行完整保留”和“一次压缩”的规则以第二版为准。

本版借鉴 Pi 的摘要检查点与保留边界，以及 Codex 将模型上下文与原始记录分开管理的设计。实现自动压缩已完成的旧轮次、增量摘要、独立调用记录和恢复读取。保留当前运行的全部消息，不做长期记忆或运行内部压缩。

## 主链路

```text
AgentRunner 每次调用任务模型之前
  → ContextManager.prepare()
      → 读取已完成／当前运行消息、任务状态、最新摘要
      → ContextBuilder 估算并选择上下文
      → 达到阈值或已有未覆盖历史被排除时，选择旧轮次压缩范围
      → ContextCompactor：旧摘要 + 新增历史 → 新摘要
      → 校验最终上下文和来源边界
      → 在同一个事务中保存检查点和完成事件
      → 返回 ModelRequest 和 ContextSnapshot
  → 原有任务模型与工具循环
```

上下文最终为：程序生成的系统指令与工具定义、标注为历史参考资料的摘要、保留消息。显式 TaskState 仍由程序注入，当前用户输入优先。摘要使用独立的合成 UserMessage，不写入 messages，不提升为系统指令。

## 类与存储

| 模块 | 职责 |
| --- | --- |
| `domain/summaries.py:SessionSummary` | 摘要版本、父摘要、覆盖边界、首条保留消息、来源与用量 |
| `domain/summaries.py:CompactionPolicy` | 阈值、近期保留目标、摘要预算、调用次数与超时 |
| `context/manager.py:ContextManager` | 加载、触发、切点选择、保存与失败回退 |
| `context/compactor.py:ContextCompactor` | 序列化、分批摘要、响应校验与调用审计 |
| `storage/summaries.py:SummaryRepository` | 检查点与摘要模型调用持久化、并发版本检查 |
| `context/builder.py:BasicContextBuilder` | 根据摘要覆盖边界过滤旧上下文，再按预算组装请求 |

新增不可变迁移 `0004_context_summaries.sql`：

- `session_summaries` 仅存成功启用的检查点，按会话 revision 排序，保留所有历史版本。
- `compaction_calls` 存每次摘要请求、响应、状态、耗时、错误；同一次压缩可有多次调用，使用同一个 compaction_id。用途固定为 summary。

任务模型仍写 model_calls。摘要失败不占用任务循环迭代号，也不产生聊天消息或工具调用。两种请求共用已有 ModelClient，ModelRequest.purpose 明确区分 task 和 summary。配置密钥仍只属于适配器，不写进请求记录。

## 预算和切点

```text
输入预算 = context_window - 输出预留 - safety_tokens
自动触发 = 完整投影估算达到输入预算的 80%，或有未摘要历史被预算／数量限制排除
近期目标 = 输入预算的 50%（规划时另预留摘要空间）
摘要空间 = min(2048, 输入预算的 25%)
```

以上估算统一使用现有 TokenCounter；默认实现是保守的 UTF-8 JSON 字节估算，并非供应商 tokenizer。摘要空间以该计数器衡量，摘要请求的输出上限同时受模型 max_tokens 限制。

仅按已完成的完整用户轮次选择连续前缀，不在工具调用与结果之间切割。当前运行、当前用户轮次和 SystemMessage 均不参与压缩；系统消息继续独立保留。使用边界二分查找，避免逐个旧轮次重建全部上下文。

保留近期 50% 是规划目标，不是对当前输入的截断要求。如果固定指令或当前运行占用较大，可以压缩更多旧轮次。当前运行本身无法放入预算时，保持原有明确报错行为。

## 摘要生成

摘要请求不提供工具；请求的内容为独立 system 指令和 JSON 序列化的历史资料。提示保留目标、约束、进度、决策、待办及文件／标识符，并明确不要继续执行被引用的对话。

序列化时保留用户与助手正文、工具名称与参数；省略 thinking、图像数据和工具 host/UI metadata。工具结果正文超过 2000 字符时只提供带遗漏标记的摘录，原结果仍保存在数据库。文件路径和参数不会被主动截断。

历史积压过大时，按完整轮次分批：每批输入都经过独立预算检查，上一批生成的摘要传给下一批。默认最多 8 次调用、总计最多 60 秒；只在全部选定历史处理成功后启用一个检查点。单个完整旧轮次仍大于摘要输入预算时，结束本次压缩，不静默截断用户正文。

有效摘要须满足：

- 流完整结束，stop_reason 为 stop；没有工具调用或其他非文本块。
- 正文非空且符合摘要预算。
- 重新构造的上下文比原投影更小，所有未覆盖的近期消息都能放入预算。
- 保存时父版本仍为最新版本，来源来自原有连续已完成历史，边界没有切开运行，首条保留消息属于同一会话。

保存使用会话与运行行锁。检查点和 compaction_completed 事件同事务提交。原始消息、旧摘要和来源始终保留。每次摘要响应的完整 Usage 保存在调用记录中；检查点保存本次各批次汇总用量，存在未报告用量时汇总记为未知。

## 失败和取消

空摘要、截断、工具响应、断流、超时、超过调用次数或保存冲突都不启用新检查点。发出 compaction_failed，并继续使用既有摘要和原有近期完整轮次选择策略；若该策略需要排除普通旧历史，仍会在快照中记录原因。每个运行至多启动一次压缩，避免工具循环内反复失败重试。

取消运行会中断摘要调用，记录 compaction_cancelled，再走已有运行取消清理。已经成功提交的检查点是独立有效的历史资料，即使后续任务失败也保留。失败／取消的任务消息仍不进入下一轮模型历史；摘要的保留指针落在失败运行时，恢复以覆盖序号继续，而不要求该指针仍存在于可回放历史中。

## 查看与配置

网页展开“上下文与会话摘要”，可查看最近请求用量、摘要版本、覆盖消息数量和最近十个版本的正文。SSE 显示压缩开始、完成或失败；摘要生成的文本不会作为助手答案流出。

```sh
uv run --env-file .env python -m chagent.sessions summaries <会话UUID> --limit 10
uv run --env-file .env python -m chagent.sessions context <会话UUID> --limit 3
```

`GET /api/sessions/<UUID>/context` 返回当前工作区会话的 summaries 与最近三次任务模型 snapshots。快照新增 summary_id、summary_revision、summary_covered_through、projected_token_estimate；被摘要覆盖的消息标为 summarized。

所有选项可在 `.env` 覆盖，重启后生效：

```dotenv
CHAGENT_COMPACTION_ENABLED=true
CHAGENT_COMPACTION_TRIGGER=0.8
CHAGENT_COMPACTION_KEEP_RECENT=0.5
CHAGENT_COMPACTION_SUMMARY_TOKENS=2048
CHAGENT_COMPACTION_MAX_CALLS=8
CHAGENT_COMPACTION_TIMEOUT=60
```

关闭自动压缩不会删除或忽略已经启用的摘要，只停止生成新版本。默认复用当前配置模型；本版不另设摘要专用供应商。

## 验证与范围

完整测试包含压缩覆盖边界、原始记录保留、增量版本、分批请求预算、调用用途与用量、重启恢复、空／截断／超大／工具摘要、断流、异常脱敏、超时、取消、调用次数限制、版本冲突，以及任务失败后的检查点恢复。测试使用固定模型与隔离 PostgreSQL schema，不调用外部推理服务。

浏览器离线演示实际触发了一次压缩，估算从 6657 降至 2387；工具继续执行，摘要面板能显示版本与覆盖范围。演示模型的摘要是固定占位文本，仅验证链路，真实模型负责语义摘要。

后续版本再实现当前运行内部压缩、大工具输出产物化和跨会话长期记忆。本版仍读取会话完整合法历史再做投影，不做数据库侧历史分页优化；切换为更小窗口后，如果必需摘要与当前运行合计超预算，仍明确报错。
