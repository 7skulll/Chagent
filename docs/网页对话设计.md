# 本地网页对话

当前网页服务使用 FastAPI，完成本地服务、SSE 流式输出和最小聊天页面。复用现有 AgentRunner、SessionManager、模型适配器和 PostgreSQL，不另建聊天循环，不引入前端框架或打包工具。定位仍为回环地址上的本地单用户 Agent。

## 启动

先安装依赖、准备数据库并在 `.env` 配好供应商 Key，详见[模型配置](模型配置.md)与[数据库配置](数据库配置.md)。

```sh
uv sync
uv run --env-file .env python -m chagent
# 脚本启动（由 uv 加载 .env；脚本显式设置 PYTHONPATH）
uv run --env-file .env ./scripts/start.command
```

打开 <http://127.0.0.1:8765>。工作区默认 `~/Chagent Workspace`（首次启动时创建），网页里可以切换；启动会应用数据库迁移。

启动器负责三件事：端口被其他程序占用时顺延到下一个空闲端口；同端口已在运行本应用时只打开浏览器、不起第二个进程；服务开始监听后自动打开浏览器（`--no-open` 关闭）。

```sh
# 固定响应模型，用于离线验证网页和工具链路
uv run --env-file .env python -m chagent --demo
# 多供应商配置时选择 DeepSeek，工作区与端口也可指定
uv run --env-file .env python -m chagent --provider deepseek --workspace /absolute/project --port 8766
```

当前模型由进程启动参数与服务端环境变量决定，网页只展示供应商与模型，并提供只读的运行时配置面板。密钥不会发送给网页——面板上只显示 `set`／`missing`；这一版不提供网页上修改模型或切换模型的界面。

当前脚本不会自动加载 .env；推荐以上 `uv run --env-file` 方式。直接双击依赖已有进程环境，配置加载一致性列为下一批修复。

## 分层

| 模块 | 职责 |
| --- | --- |
| `web/__main__.py` | 解析配置，固定绑定 `127.0.0.1`，启动一个 Uvicorn worker |
| `web/app.py:create_app` | 服务生命周期、路由、本地访问边界、静态资源 |
| `web/app.py:api` | FastAPI APIRouter，按会话、运行、上下文、记忆分组的接口 |
| `web/schemas.py` | Pydantic 请求与响应契约、类型与边界校验 |
| `web/app.py:WebRuntime` | 工作区范围检查，托管生成任务，启停后台提取 worker，关闭时取消任务 |
| `AgentRunner` | 原有模型和工具循环，新增可选的运行开始通知 |
| `RunRepository` | 原有事件存储，新增最新运行查询和事件分页 |
| `web/static/` | 原生 HTML、CSS、JavaScript，使用 Fetch 和 EventSource；`markdown.js` 是独立可测的 Markdown 子集渲染器（WK1） |

数据库连接池和模型 HTTP 客户端在应用启动时创建，关闭时先结束生成任务，再释放资源。

## HTTP 接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/info` | 工作区、当前模型与模式（`default_mode`、`code_mode`） |
| GET | `/api/workspaces` | 见过的根目录与各自会话数，按最近活跃排序；目录已不存在的会被略过 |
| POST | `/api/workspaces` | `{"path":"/abs/dir"}` 打开一个目录；之后它才能作为其他请求的 `workspace` 参数 |
| GET | `/api/config` | 生效的沙箱、审批、联网、压缩、预算与工具数（`tools` 是本构建默认面的数量）；密钥只回 `set`／`missing` |
| GET | `/api/sessions?limit=50&before=<UUID>&workspace=<path>&archived=hide\|include\|only&q=` | 指定工作区的会话列表与游标；`archived` 默认 `hide`（`only` 为归档视图），`q` 只搜标题（`ILIKE`，不搜正文） |
| POST | `/api/sessions` | `{"title":"新会话","workspace":"/abs/dir","mode":"work"}` 创建会话；`mode` 省略即构建默认，`code` 在开关关闭时返回 409 |
| PATCH | `/api/sessions/<UUID>` | `{"title":"新名字"}` 或 `{"archived":true\|false}`，空串表示清空标题；归档会话发新 run 返回 409 |
| POST | `/api/uploads?name=<文件名>&workspace=<path>` | 请求体是原始字节，落到该工作区的 `uploads/`，返回相对路径与 sha256 |
| GET | `/api/sessions/<UUID>` | 会话信息（含 `mode`）及 `latest_run` 状态 |
| GET | `/api/sessions/<UUID>/messages?limit=100&before=<sequence>` | 历史消息，页内从旧到新，返回 `next_before`；每条带 `superseded_by`（非空表示已被后来的 run 替换，见「重新生成与编辑重发」） |
| GET | `/api/sessions/<UUID>/sources` | 每个 run 实际注入的长期记忆（键、版本、范围、正文），供回答下方的「依据」使用 |
| GET | `/api/sessions/<UUID>/context` | 摘要版本和最近三次任务模型上下文快照 |
| GET | `/api/sessions/<UUID>/artifacts/<UUID>?offset=0&limit=1000` | 会话所属工具产物的字符分页 |
| GET | `/api/memories?status=&limit=&before=` | 记忆分页列表，可按状态筛选 |
| POST | `/api/memories` | 手动创建记忆 |
| GET · PATCH · DELETE | `/api/memories/<UUID>` | 读取（含同键冲突）、编辑、删除，改动需 `expected_revision` |
| POST | `/api/memories/<UUID>/accept` · `/reject` | 审核候选；冲突时另需 `replace_id` 与 `replace_revision` |
| GET | `/api/memories/<UUID>/revisions` | 最近 100 个版本快照 |
| GET | `/api/sessions/<UUID>/usage?limit=50` | 该会话每次运行的 token 用量（输入／输出／缓存读写／合计）与汇总，含缓存命中率 |
| GET | `/api/usage?days=7` | 按天汇总已打开工作区的 token 用量；只报 token，不报金额 |
| POST | `/api/sessions/<UUID>/runs` | `{"text":"你好"}`；返回 HTTP 202 和 `run_id`。运行继承会话模式，带上不同的 `mode` 返回 409。另两种形态：`{"regenerate_from":"<助手消息 UUID>"}` 重新生成那条回答（不带 text），`{"text":"改过的内容","edit_message_id":"<用户消息 UUID>"}` 编辑后重发。两者都会让从该条起往后的记录退出回放，原记录保留可读 |
| GET | `/api/runs?active=true` | 当前请求工作区尚未收敛的运行（`run_id`、`session_id`、`started_at`、`current_tool`），供侧栏「后台运行」入口使用 |
| GET | `/api/runs/<UUID>` | 运行状态和错误；等待审批时额外投影 `waiting_for=approval` 与 `approval` |
| GET | `/api/runs/<UUID>/memory-job` | 独立的后台记忆任务状态，无任务时 job=null |
| GET | `/api/runs/<UUID>/events?after=0` | SSE，重连也支持 `Last-Event-ID` |
| GET | `/api/runs/<UUID>/approvals` | 待确认的宿主机命令（`waiting_for` + `pending` 列表） |
| POST | `/api/approvals/<UUID>/decide` | `{"approve":true}` 或 `false`；批准只对这一次调用生效，重复决策返回 409 |
| POST | `/api/runs/<UUID>/cancel` | 请求取消；已经结束时返回当前状态 |

会话列表每页最多 100 项，消息每页最多 200 条。JSON 请求上限 64 KiB。会话不存在或不属于「已打开的工作区集合」时返回 404；同会话并发生成和归档会话生成返回 409。输入错误返回 400，运行后的模型错误通过持久化的运行状态和 SSE 显示。

会话的重命名、归档与恢复已由 `PATCH /api/sessions/<UUID>` 接到网页（Z2），归档会话仍可打开查看历史，但发新 run 返回 409。**会话模式已在 WK0 落地，并于模式分离批次改为可在聊天区切换**：`sessions.mode` 决定后续 run 解析哪份工具面，`PATCH /api/sessions/<UUID>` 带 `mode` 即可在 `work`／`code` 间切换，进行中的 run 持空闲锁拒绝切换（409），切到 `code` 前跑与 code 会话相同的隔离预检（失败 503，`CHAGENT_CODE_MODE=off` 时 409）。切换只影响之后的 run，历史里另一模式的工具记录原样保留。聊天区标题旁的开关按 `/api/config` 的 `code_mode` 显示，run 进行中禁用。接口约定见[执行边界设计](执行边界设计.md)。

## FastAPI 参数校验与接口文档

路径 ID 与分页游标使用 UUID 类型；分页、产物偏移、事件序号在 Query／Header 参数上声明范围。请求体统一使用 Pydantic 模型，禁止额外字段，不把数字转为字符串，也不把布尔值或数字字符串当作修订号。聊天正文最多 16000 字符且不能全空白。记忆编辑区分“未传字段”和“显式 null”，修订号必须是正整数。

FastAPI 的请求校验错误统一映射为原前端兼容的 HTTP 400：

```json
{"error":"body.text: Field required","details":[{"location":["body","text"],"message":"Field required","type":"missing"}]}
```

错误不回显 Pydantic 的 input、ctx 或请求正文。业务层仍负责工作区隔离、来源校验和版本冲突，Pydantic 不替代这些规则。信息、会话、运行、记忆和产物等响应使用声明的返回模型；消息正文与上下文快照保留可扩展的 JSON 内容。

本地 ASGI 边界在 JSON 解析前把请求体限制在 64 KiB；`/api/uploads` 是唯一例外——它接受任意 content type，由上传端点自己按流累计并限制在 20 MiB，边界只放行、不缓冲（否则一份文档要在内存里存两遍，还会因「不是 JSON」被拒）。非空修改请求须使用 application/json，否则返回 415。SSE 沿用现有持久化事件投影，不改用随 HTTP 请求取消的后台任务。HTTP 接口不会接收模型 Key，Key 继续只在服务端配置。

`/openapi.json` 由路由和模型生成，校验错误状态与实际 HTTP 400 保持一致。`/docs` 是读取该定义的本地接口参考页，资源来自 `/static/api-docs.html` 和 `/static/api-docs.js`；不加载 Swagger CDN、远程字体或其他外部资源，也不会自动执行任务或修改数据。聊天与文档均保留 CSP、Host 和 Origin 限制。

## 审批

`CHAGENT_APPROVAL` 不是 `never` 时，宿主机命令可能在执行前停下来等人。运行仍是 `running`：`GET /api/runs/<id>` 投影 `waiting_for=approval`，页面根据 `approval_requested` 事件拉取待确认项，显示命令原文、目录与有效期，两个按钮走同一个 `POST /api/approvals/<id>/decide`。批准只对那一次调用有效；参数改变、过期或重复决策都不会执行。等待期间不占执行槽与工作区门，其它会话照常运行。

## 流式事件与任务生命周期

发送消息时先让原有 Runner 持久化用户消息和运行记录，取得运行 ID 后返回。生成任务由 WebRuntime 持有，不依附发送请求或 SSE 连接。每个会话仍由数据库唯一约束保证至多一个活跃运行，不同会话可以同时生成。

SSE 先注册版本通知，再按序读取 `run_events`，每批最多 200 项；提交后通知唤醒，1 秒兜底查询补足通知遗漏和跨进程写入，等待新事件时不占用数据库连接。事件 ID 是运行内的 sequence，`update` 的数据为：

```text
id: 4
event: update
data: {"type":"text_delta","payload":{"delta":"你好"}}

```

网页使用 `model_started`、`text_delta`、`tool_started`、`tool_completed` 展示进度。`run_completed`、`run_failed`、`run_cancelled`、`run_interrupted` 标记运行结束，读到该运行的首个终态事件即发送 `end` 关闭流；游标已经越过终态时直接结束。每隔约 15 秒发送注释心跳，浏览器重连使用 Last-Event-ID 继续读取。

记忆提取事件（`memory_job_queued`、`memory_extraction_started`、`memory_saved`、`memory_extraction_failed`）会追加在 `run_completed` 之后，属于运行之外的记账。SSE 在终态关闭，所以终态之后的事件不会由回答流推给浏览器；网页独立查询 memory-job 状态，最多轮询 2 分钟，切换会话后停止旧轮询；但**直接读事件表时"最后一条是终态"不再成立**，消费方应以终态事件为界，而不是以读到末尾为界。

`/remember` 短路产生的运行仍以普通 `run_completed` 结束（`end_reason=explicit_memory`，页面状态显示"已写入长期记忆"），事件只有 `run_started` → `text_delta` → `memory_command_resolved` → `memory_saved` → `run_completed`。这条路径的 `memory_saved` 落在终态之前，因此记忆列表刷新不依赖后台 job 轮询。

刷新后读取会话和历史，如果运行仍在进行，就重新回放这一运行的事件；它的助手输出仅由 SSE 渲染，避免与历史重复。运行结束后重新加载数据库中的最终消息；同会话刷新在用户上翻时恢复消息锚点与阅读位置，仍贴底时继续跟随，主动切换会话则定位到最新。工具参数和结果可展开查看；回答正文按 Markdown 子集渲染，见下节。

点击停止会取消 Runner 任务，记录终态，并将进行中的工具调用标记为结果未知。重复停止不会再次中断落库清理。页面断开不取消生成；正常关闭服务会取消所有该服务托管的运行。浏览器只在 `localStorage` 里保存当前会话 ID、当前工作区与两处侧栏的折叠状态，消息与运行事件仍然只存在 PostgreSQL。

## 回答的渲染（WK1）

回答按一个**固定子集**渲染：标题（h1–h4）、列表（含一层嵌套）、引用、表格、围栏代码块、行内代码、链接、粗体、斜体。富文本编辑器、图片内联渲染、数学公式不做。

安全模型只有一条，但必须完整：`markdown.js` **先对整段文本转义，再识别结构**，所以输出里出现的每个标签都是这个文件自己写的模板。结构匹配跑在转义后的文本上（引用行因此是 `&gt; `），内联代码和链接先换成占位符，再统一还原，避免被后续规则二次解释。**不支持内联 HTML，也不打算支持**——答案是模型生成的不可信文本，没有哪个白名单能让 `<img onerror>` 变安全。链接在正则层面就限定 `http(s)://`，`javascript:` 与 `data:` 只能是字面文本；能变成链接的都带 `target="_blank"` 与 `rel="noopener noreferrer"`。

其余四条是使用感的：

- **代码块**带语言标签、一键复制、横向滚动（代码换行比滚动更难读），不另起一个新工具。
- **流式渲染按 `requestAnimationFrame` 节流**：增量先累加到缓冲区，每帧只重绘一次；否则一段 3 000 token 的回答会重排数千次。
- **滚动跟随**：贴底时自动跟随；用户向上翻就停止跟随，右下出现「回到最新」。`follow` 是一个布尔量，「新内容抢滚动位置」被这一条关掉。
- **超过 2 000 字折叠**到 8 行，展开按钮在裁剪盒之外（否则折叠按钮自己被裁掉）；每条消息有「复制」。

## 重新生成与编辑重发（WK2）

历史仍然是**只追加**的：替换不改写旧行，只给它写上 `superseded_by`（迁移 `0016`）。

| 操作 | 请求 | 效果 |
|---|---|---|
| 重新生成 | `{"regenerate_from":"<助手消息>"}` | 不写新的用户消息；从那条回答的 sequence 起，往后的记录全部退出回放 |
| 编辑重发 | `{"text":"...","edit_message_id":"<用户消息>"}` | 同上，再追加一条新的用户消息（旧的原文仍可读） |

三条边界：

1. **退休的是一个后缀，不是一个点。** 一条消息不可能被单独替换而后面几轮仍然有效，所以序号大于等于它的都一起退出回放。
2. **回放与阅读分开。** `messages(current_run=…)` 给模型的历史过滤 `superseded_by IS NULL`；`GET .../messages` 不过滤，界面把被替换的那条折在「已编辑的原文」／「被重新生成的回答」里，可以展开对照。
3. **重新生成不重复提问。** 这类 run 没有自己的用户消息，所以 `RunState.current_input` 取最近一条用户消息（上下文压缩保护它、记忆召回读它），`BasicContextBuilder` 把「当前轮」退化成最后一组。

失败重试复用这条路径：错误气泡上的「重试」就是 `regenerate_from` 那条失败的回答，不新写用户消息，也不重复注入上一轮的失败事实。不做消息树与分支切换——那要树形 schema 和整棵树的投影，成本高于收益。

## 出处：搜索结果、文档引用与注入的记忆（WK3）

每条回答下方有一个**依据**折叠块，默认收起，没有来源时不出现（空卡片比没有卡片更差）。三路来源：

- **网页**：`web_search` 的 `details.results` 带 `snippet`／`site_name`／`date`／`authority`／`score`，卡片显示标题、站点名（供应商给的标签，缺了才退回域名）、摘要与发布日期，点击在新标签打开；`web_fetch` 带 `url`／`title`／`format`（WD 批后没有 `status` 字段，所以判断依据是「有没有 `url`」）。
- **文档**：`read_file` 解析 PDF／Word／Excel 时把每块的 `page`／`section` 位置写进 `details.citations`，卡片显示「文件名 · 第 3 页」（Word 是标题路径，Excel 是工作表名）。只写位置不写正文：正文已经在工具结果里，`details` 会被落库两次。
- **记忆**：记忆不是消息，所以单独一个 `GET /api/sessions/<id>/sources`，一次取回整个会话每个 run 注入的记忆及其正文；界面在会话加载时合并进每轮的依据。

这三路都在 `details` 里，而 `details` 按契约**不进模型上下文**（`ToolResultMessage` 的 docstring 已经这么写）。所以 WK3 没有改动任何模型可见的字节——这一批不买效率，只买可见。**不做**正文里的 `[1][2]` 自动标注：那要模型配合编号，先给来源列表。

## 上传（WK4）

上传错误按实际情况提示：目录权限 403、空间不足 507、其他存储错误 500；网络中断另有提示。故障恢复后可重试，重名文件自动编号，底层绝对路径不回显。

左下的 **＋**、拖拽到聊天区、粘贴剪贴板文件，三条入口进同一个队列（`POST /api/uploads`，一次一个文件，原始字节）。每行显示缩略图（图片）或扩展名、文件名、大小、自己的进度与状态；失败可重试、可移除，队列独立于输入框，**失败不清空已输入的文字**。

四条必须说清楚的限制：

- **按后缀分流。** 能进队列的是 PDF／Word／Excel 与文本；其他类型当场报「不支持这种文件类型」，不会先传上去再在三次工具调用之后失效。
- **图片只存不解析。** 缩略图用 `data:` URL（CSP 的 `img-src` 允许），但 `read_file` 没有 OCR，行内直接写「图片：当前工具读不了图片正文」，也不把图片路径写进「请阅读」那句话——界面不替工具许诺。
- **上限 20 MiB**，客户端先拦一次，服务端 413 再拦一次。
- **提示语由队列生成。** 上传成功的可读文件合成一句 `请阅读 uploads/a.pdf、uploads/b.pdf` 放进输入框，用户可以改也可以删；移除一个文件会重写这一句而不是再追加一句。发送成功后已上传的行清空，失败的行留下等重试。

## 本地边界与当前限制

服务仅用于本机单用户，启动入口绑定回环地址并限制 Host；拒绝跨 Origin 请求及 cross-site 浏览器请求，不启用 CORS。会话、消息和运行查询都限定在「已打开的工作区」集合内；静态资源使用固定白名单（`/static` 只服务列表里那六个文件，不做目录读），并设置 CSP（`default-src`／`script-src`／`style-src` 都是 `'self'`，`img-src` 额外允许 `data:`——缩略图用 data URL 而不是 blob，就是为这个）。文本渲染规则：用户输入、工具结果与错误一律用 `textContent`；只有助手回答走 `innerHTML`，而它的输入在 `markdown.js` 里已经被整体转义过。

一个工作区使用一个服务进程。运行本身不进入分布式队列，也不做多进程接管或崩溃后自动恢复：强制杀死进程可能遗留 running 记录，不能通过网页接管其任务。普通退出和页面刷新已覆盖；取消不能回滚已经发生的文件写入或宿主命令副作用。宿主命令沿用原有显式配置开关。

四个旧缺口已全部关闭（WK1–WK4）：回答按 Markdown 子集渲染、流式按帧节流、滚动不再抢位置（WK1）；重新生成、编辑重发与失败重试，旧记录折叠可展开，历史不被改写（WK2）；搜索卡片、文档页码与注入记忆的来源列表（WK3）；拖拽与粘贴上传，多文件队列、进度、重试与缩略图（WK4）。三条能力边界仍然成立：`work` 面只有读工具，work 工作区写入仍关闭，code 的读写与执行由服务端显式配置门槛控制；来源是列表，正文里没有 `[1][2]` 自动标注；图片不进解析链路。

已解决的三个旧缺口：审批获得在场语义（`CHAGENT_APPROVAL_UNWATCHED_GRACE` 默认 10 秒内没有页面订阅就按「无人观看」判为未执行，不再空等满 300 秒，Z4）；真实 token 用量可见（`/api/sessions/<id>/usage` 与 `/api/usage`，只报 token 不报金额，Z3）；界面按钮全部有行为（Z1 之前有 24 个视觉占位，现在 `tests/test_web_ui.py` 静态断言每个 `<button>` 都有 `id` 且被 `app.js` 查过、或是所在表单的提交控件，孤儿数为 0，见[实施记录](实施记录.md) 第 25 节）。外壳与首屏在 Z6 收了一次：只剩一个重复按钮的 60px 图标栏被删除（工作区入口留在侧栏底部的文字按钮上），空会话首屏给出三个基础工具面能做完的起手式，点击只填入输入框（第 26 节）。

已接入自动上下文摘要与大工具输出产物化：网页可展开查看摘要版本、覆盖范围、近期上下文用量，并对产物逐页读取（见[会话与上下文设计](会话与上下文设计.md)）。附件已支持：输入框左下角的 **＋** 把文件传到工作区的 `uploads/`，再把路径写进输入框，`read_file` 按后缀分流到解析层直接读 PDF／Word／Excel（见[基础工具设计](基础工具设计.md)）。不提供富文本编辑器与数学公式，也不在网页上修改模型配置。

“长期记忆”弹窗与 `/api/memories` 覆盖创建、编辑、审核、删除与版本查看，上下文面板展示每轮实际注入的记忆版本（见[长期记忆设计](长期记忆设计.md)）。后台提取由进程内 worker 处理：随应用启动而启动、随关闭而停止，未完成的 job 留在队列里等下次启动，网页不参与调度。

## 对话产物

work 与可写 code 使用 create_file 将受支持文本生成到工作区，聊天提供打开文件与下载。生成或上传撞名时返回待确认状态，右侧提供查看磁盘、下载待写入内容、覆盖/保留两份/取消；未确认不落盘。旧 generated_files 保留历史下载，用户主动“保存到工作区”同样走确认。

## 工作区与编辑器

左侧按工作区分组会话；首次明确选择目录，切换历史会话同步工作区。目录存在性与准入每次重新校验；失效目录保留并提示，不能静默替换成其他目录。当前浏览器选择与布局比例在本机记忆，工作区登记与会话关联持久化在数据库。

右侧默认文件树与多标签文本编辑，另有上下文和历史产物页签。编辑只修改页面草稿，保存或 ⌘S 才写盘；关闭标签、跨工作区切换或重命名/删除涉及草稿时提供保存、放弃、取消。保存冲突保留草稿，并提供查看磁盘版本、另存为和版本绑定的确认覆盖。已有干净标签可按需/有限轮询加载磁盘变化。刷新/关闭页面仅提供浏览器离开提醒，不承诺恢复未保存草稿。

左右列与文件树高度支持拖动和方向键调整。窄屏文件面板覆盖聊天，关闭后回到聊天。新建、重命名、恢复与另存为采用页面内名称表单，不依赖浏览器 prompt。文本以 UTF-8、1 MiB 为编辑范围；混合换行文件当前只读。Markdown 预览沿用安全渲染。PDF 以版本绑定的 PNG 页面预览，PNG/JPEG/GIF/WebP 图片重新编码后缩放查看；格式与资源上限及验收见[F5 记录](工作区F5验收-2026-11-03.md)。具体行为与证据见[工作区 F1–F4 实施与验收](工作区F1-F4验收-2026-11-03.md)。

## 运行配置可见

`GET /api/config` 与命令行打印的 `Behavior:` 同源，网页用工具条上的齿轮面板只读展示：供应商与模型、工具数、单次运行上限、沙箱与出网、审批档位与等待时长、work 文件写入与 code 文件写入（显式只读 code 关闭）、宿主命令、联网与密钥是否存在、压缩与计数器、轮数与进程上限。沙箱、审批策略与工具表都在 `create_runner` 时固定，热改等于半个重启，所以面板不做修改。
