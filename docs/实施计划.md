## 已实施首批：统一入口与文件边界

本轮已将源码目录校验提取为公共策略，覆盖网页、CLI、Runner 与文件工具；原始工作范围如下，当前行为和限制见下一节的交付说明。不能用“命令被隔离”替代“所有入口都受保护”。

工作范围：

1. 将受保护源码根、工作区规范化和准入检查移出 `web/workspaces.py`，建立独立策略模块，由网页、CLI、Runner 与隔离工具共用。
2. 新建与恢复会话、每次运行、工具操作都重新校验授权工作区；失效、被替换或与源码/运行时重叠时拒绝，不相信数据库旧路径。
3. 文件读取、搜索、文档解析、上传共用文件身份检查。硬链接规则覆盖 work 与 code，不只在 isolated 命令启动前扫描；符号链接/父目录穿越继续拒绝。
4. 收口确定性 `--tool` 诊断入口，明确哪些能力只供本地显式诊断。任何面向真实模型的路径都不能借 demo/single-face 或底层 registry 绕过隔离。
5. 明确 scratch 的会话归属和关闭清理。同工作区的不同会话不能默认共享可执行配置或遗留 HOME 文件；运行结束清理进程后再释放资源。

验收：覆盖网页、CLI、新旧会话与程序装配入口；源码父子目录、符号链接、硬链接、失效工作区拒绝；安全工作区读写/上传/测试正常；拒绝路径不启动目标命令。用合成资料验证，不读取真实凭据。

本轮涉及：`web/workspaces.py`、`cli.py`、`agent/runner.py`、`tools/workspace.py`、`tools/search.py`、`tools/sandbox.py`、`bootstrap.py` 和相关测试。具体交付和验证见下方 R1/R2 记录。

## 优先分支：只读 code 模式实施

状态：**统一边界首批及只读 R1–R5 已交付**。首版仅支持满足 isolated/只读/断网/宿主命令条件的网页 code，默认仍 work。完整实现与验收见[只读 code 验收记录](只读code验收-2026-11-02.md)。可写和交互版本继续按下方 C3 等批次推进。工作区已有修改尚未提交，不自动覆盖或混合提交。

本轮交付（2026-11-02）：公共策略移至 `chagent.boundaries`，会话服务、Runner、CLI、网页和工具共用；文件读取/文档/搜索/上传采用 no-follow 目录描述符和硬链接检查；Runner 在每次运行及模型循环检查工作区，工具上下文携带目录身份。禁用会话模式明确拒绝，生产 `single_face` 不再接受非诊断模型。isolated scratch 按 run 分配，进程清理后释放，同工作区的 run 不共享 HOME/tmp。

限制：数据库不保存目录 inode，目录身份只在当前进程/run 内固定；服务重启后按当时路径重新准入，不能识别停机期间普通目录被替换的历史。内核隔离不是对同一 OS 用户主动并发修改的完整防护；模型出口路径保护仍属于后续批次。启动 `.env` 自动加载已在 R3 收尾。

R1/R2 的真实证据为 [15 项隔离检查及 8 项工具检查](diagnostics/readonly-r1-r2-2026-11-02.json)。这是 R1/R2 阶段证据；后续 R4 77 项检查及 R5 真实模型浏览器验收已补齐，见只读验收记录。

### 首版范围与决策

- 首版网页只接受 `code=on`、宿主命令开启、`sandbox=isolated`、`sandbox_writable=false`、命令 `network=false`。缺少任一条件均不开放 code；默认仍为 work，不自动修改用户配置。
- 保留生产模型命令必须 isolated 的现有约束。`workspace-write` 的只读 profile 可以实现及诊断，但不作为生产网页开放条件：它的跨进程信号、IPC 与读取范围不能靠禁写和断网解决。
- 只读指**工作区不可写**；私有 scratch、数据库、上传存储仍可能写入。不得宣称“零副作用”或“任何文件都不能写”。scratch 不得与工作区、受保护源码或运行时重叠，明确会话归属与关闭清理。
- 首版 `process` 仅允许 read/stop；schema 不暴露 write，执行层也拒绝 write（包括 EOF），不提供交互式 stdin。初始命令及其子进程仍统一受内核限制；取消、超时、run 结束清理不变。C3 留给后续交互/可写版本。
- 保持现有 work 工具面；code 不新增 `create_file`，它目前仅属于 work。会话模式继续创建时固定，不新增中途切换。只读配置是服务级，改变配置需要重启。
- 不删除或覆盖显式审批配置。首版不依赖 C3；已有 exec/test 审批策略继续生效，`never` 表示这些命令无需人工审批，不表示可绕过隔离。
- 不新增数据库迁移，不承诺装依赖、构建及任意真实项目测试都可运行；依赖写工作区或需要联网的任务应明确失败原因。

### R1：配置与沙箱禁写

涉及 `config/__init__.py`、`tools/sandbox.py`、`tools/isolation_probe.py`、`.env.example`、配置与沙箱测试。

1. 增 `Settings.sandbox_writable`，环境变量 `CHAGENT_SANDBOX_WRITABLE` 默认 true，只接受 true/false（和既有布尔配置一致）。向 `SandboxSettings`、`SandboxPolicy.writable_workspace` 显式透传，使用关键字构造，避免现有位置参数错位。
2. 两种 profile 按字段授予工作区写权限；isolated 只读只保留设备及私有 scratch 写权限。检查工作区位于允许临时目录下的情况，不能让更宽的临时目录授权重新放开它；无法证明边界时拒绝该组合。
3. 策略哈希/探针缓存必须包含只读字段。现有普通与 isolated 探针均有“工作区可写”断言，改为按策略检查可写/拒写；只读缓存不得复用可写探针结果。
4. 审计 `workspace_writable` 报告实际边界：off 不能报告禁写已生效；backend 缺失、启动或探针失败拒绝执行，不降级。

完成条件：默认 true 的既有行为回归通过；false 的 profile、参数透传、缓存区分及真实内核拒写验证通过。反向结果必须同时证明命令已启动、拒绝原因正确、目标无变更。

### R2：工具与运行装配

涉及 `bootstrap.py`、`tools/builtin.py`、`tools/command.py`、`tools/tests_runner.py`、`tools/processes.py` 及工具/审批测试。

1. code 的实际写工具开关取“调用方允许写 AND 沙箱工作区可写”；网页/CLI/程序装配一致，不能通过直接构造 registry 重新注册只读 code 的三个写工具。work 保持既有入口语义。
2. 集中定义网页只读 code 准入条件供启动器和 app 共用；保留 `_tool_faces` 的 isolated 强制约束，不用 single-face/demo 例外承载真实模型。
3. 在公共子进程环境构造处注入 `GIT_OPTIONAL_LOCKS=0`、`PYTHONDONTWRITEBYTECODE=1`，覆盖一次性命令、run_tests 与长进程，维持环境白名单。
4. `run_tests` 的 pytest 路径增加 `-p no:cacheprovider`，临时目录使用私有 scratch。任意 exec 命令不做字符串改写；ruff/mypy 等缓存需求通过工具说明与用户命令显式关闭或定位到 scratch，不承诺自动降级。
5. `ProcessTool` 支持宿主限定 actions；只读档 schema 只列 read/stop，执行层在调用管理器前拒绝 write/EOF。命令描述与长进程返回提示同步删除 stdin write 指引。

完成条件：点名三个写工具失败；伪造 process write/EOF 不触达 stdin；跨 run 访问失败；read/stop、取消、超时与清理正常；work 与既有可写 CLI 回归通过。

### R3：网页入口与能力显示（已完成）

涉及 `web/__main__.py`、`web/app.py`、`web/schemas.py`、`diagnostics/behavior.py`、静态界面及网页测试。

1. 替换现有三处一律拒绝 code 的门禁，仅通过共用准入函数放行首版配置。新建、恢复旧 code 会话及每次运行均复核能力和工作区，直接 API 请求不能绕过。
2. `/api/config` 与启动诊断同源显示实际 `isolated(ro)`、工作区写入关闭、命令断网、process stdin 不可用及审批策略。前端据配置提供新建 code 会话，默认选 work。
3. 页面用“只读代码分析”说明限制；独立网页搜索按原开关运行，与命令断网分别显示。重启复用已有服务时不得把旧服务误标为新只读配置。
4. 上传、生成文件下载、记忆与 SSE 恢复保持原语义；不将服务自身写入数据库/上传目录描述成沙箱违规。

完成条件：有效组合可创建并运行 code；off、workspace-write、可写 isolated、联网 isolated、命令禁用等组合拒绝开放且提示具体原因；work、刷新、停止和失败恢复通过。

### R4：真实沙箱正反向验收（77 项通过）

扩展现有隔离探针脚本，保存日期化 JSON；只使用独立合成工作区及合成秘密，不把 Chagent 安装源码纳入可读白名单。

- 正向：shell/Python 启动、读取、grep、Git log/diff/status、已有依赖下的 unittest/pytest、scratch 临时文件、长进程 read/stop。
- 反向：重定向、touch、Python 写入、tee、sed 修改、Git checkout；覆盖新增、覆盖、删除、重命名、mkdir、chmod 与符号/硬链接边界。Git 使用有实际差异的受跟踪文件并核对内容，不能用干净仓库无操作退出判定拒写。
- 保持原 C2 的源码/其他目录/凭据读取拒绝、环境清空、HOME 隔离、网络拒绝；增加合成宿主哨兵进程的跨沙箱 signal 拒绝检查，不操作真实用户进程。
- 写入拒绝检查实际 errno（Python syscall 探针预期 EPERM，若系统返回不同权限 errno 需记录并解释）、退出状态和无残留；工具未安装、动态库加载失败、shell 未启动都不算通过。
- 对工作区比较前后文件清单、内容哈希和相关元数据；`git status` 仅作辅助，不能覆盖被忽略文件。验证 scratch 清理及跨会话不可访问。

完成条件：上述必需探针全部通过；任何无法执行/跳过均记录阻塞项，不能把它算作开放验收成功。

### R5：真实项目与浏览器交付（已完成，限定范围）

1. 从已有真实项目选至少一个小型 Python 项目和一个含 Git 历史的项目（可为同一项目），放在获准的独立工作区；记录依赖/解释器实际可访问范围，不扩大源码/用户目录白名单来凑通过。
2. 用真实模型在网页完成“解释代码 → 定位实现 → 看 Git diff → 运行适用测试 → 总结依据”，再验收停止、刷新恢复、命令失败反馈及 work 上传/下载回归。记录不可运行任务与原因，不用合成项目替代真实项目。
3. 运行当时完整自动回归，记录通过/跳过/失败及环境；R4 的安全验收必须零跳过。更新 README、模型配置、执行边界、实施记录和实际浏览器证据。

完成条件：R1–R4 与真实流程通过后才宣布首版开放；这不等于后续可写版本的 C3/C4/C5 已完成。

### 停止条件与回退

任何边界失效、探针失败、跨会话 scratch 泄露、直接 API 绕过都停止开放并修复。运行期不回退到 workspace-write/off。操作回退为关闭 code 并重启服务，保留只读字段与诊断记录，不通过删配置、恢复写权限来“回退”。代码按独立批次逆序回退，不修改用户资料和历史数据库。

## 开放检查清单

- 模型生产入口不能取得未隔离的命令能力。
- 工作区/文件身份检查覆盖所有入口与旧会话，不能越界访问源码或凭据。
- 初始命令及交互 stdin 的授权范围、消费与拒绝行为明确。
- HOME、环境、scratch、读写和网络的正反向探针通过；启动失败不是“成功拒绝”。
- 长任务取消、超时、运行终态和进程清理一致，不承诺回滚已经发生的副作用。
- 真实项目、真实模型网页流程与 work 回归完成，失败/跳过项得到处理。

不设无依据的人日承诺。每批完成后以新增证据更新本文件，已交付过程进入实施记录，不再新增“第六版/第七版”平行路线图。
