## 明确不做（不要再排期）

| 事项 | 理由 |
|---|---|
| 「绝对防外泄」 | 图片、二进制、任意编码无法可靠检出；出口保护只能做到知情 + 可溯源，不承诺绝对 |
| 工具级隔离、应用内沙箱、用启动探针替代容器标记 | 见[历史决策 D3/D5](历史决策档案.md)：`tools/web.py` 在进程内联网，只把 bash 路由出去等于给边界开洞 |
| 容器强隔离（rootless + userns-remap + seccomp） | 需要镜像与内核层重做；当前定位就是「容器不是强安全边界」 |
| 取消后回滚文件与外部副作用 | POSIX 上不可得；改为「执行前记录、终态明确、不自动重试」 |
| 独立 `delete_file` 工具、AGENTS.md 作用域合并、目录树展开到文件、`TaskState` 开放给模型写 | 各自实测过收益不成立，见[历史决策](历史决策档案.md)与[实施记录第 30 节](实施记录.md) |
| OCR、图片正文理解、扫描 PDF 提取、`.doc/.xls` 解析、生成 Office 文件 | 产品边界，见[基础工具设计](基础工具设计.md) |
| 多进程接管、崩溃后自动恢复、分布式队列 | 单用户本机定位，见[网页与工作区设计](网页与工作区设计.md) |
| 给组合 B（容器只读）与 C（无命令边界）开网页入口 | 两者保留给本机 CLI 与 `--demo` 诊断；没有命令能力的网页入口只会把「能聊不能做」包装成产品面 |
| 自动识别普通历史里的早期约束 | 约束只能显式登记为任务状态；从普通历史推断会把聊天内容升级成假授权，代价高于收益 |
| Windows 支持 | `WorkspaceFS` 依赖 POSIX 目录描述符与 `O_NOFOLLOW` |

## 验收规则

- 自动测试、合成探针、真实工具、真实模型网页、真实项目分别记录；**跳过不计通过**。
- 不能用合成项目、离线模型或模型自述替代真实验收；模型说「已批准」不是批准证据。
- 隔离缺失、探针失败、源码越界、配置与实际工具面不一致时，拒绝对应能力，不回退到 `off`。
- 用户工作区里已有的未提交改动不自动 stash、reset 或覆盖。
- 每步独立可交付、可回退；回退保留用户文件与历史，不自动回滚工作区。
- 有缺陷时先修或明确降级声明，不靠文档措辞绕过去。
- 不设无证据的人日承诺；不在跑通闭环前重写框架或扩张分布式架构。
