## 目标与顺序调整

优先借鉴 pi 的直接工具循环，让 Chagent 在本地网页完成「读代码 → 创建/修改 → 执行 → 测试 → 修复 → 交付」闭环。先将逐次审批从编码能力的实施依赖中解耦，再完善授权产品。只读模式继续保留，但不再作为编码主线的终点。

本机 pi 默认以启动进程的权限执行工具，没有内置逐次审批。Chagent 借鉴其简单执行方式和按实际工具组织上下文，复用现有 Runner、数据库、网页与工具，不重写一套 Agent。保留已有工作区边界（当时还保留 isolated 执行，该档已于 2026-11-04 删除）；不通过切换 sandbox=off 达成简化。

首个可写版本采用显式启用的可信开发配置：用户在配置中授予工作区写入和命令执行能力，运行时不逐项询问。这里的「可信」表示授权方式，不表示项目内容或模型命令可信。逐次审批是另一种可选策略，现有配置不能被静默覆盖。
