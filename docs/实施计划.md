## 启动一致性缺口

文档核对代码时确认：`scripts/start.command` 只设置 PYTHONPATH，不加载 .env；Python 网页入口也只读取进程环境。当前使用 `uv run --env-file .env ./scripts/start.command`，不能承诺“填好 .env 后直接双击就可用”。先补启动器的配置加载，保留环境变量优先级、不覆盖用户配置，不在日志输出密钥；离线验证单 Key/多 Key、环境覆盖、自定义数据库和重入已有服务。

这是一项小修复，和下方边界批次分开验证；本轮只校正文档，没有修改启动代码。

## 下一批：统一入口与文件边界

先补所有模型入口的一致约束，再扩展 code 审批。原因：目前源码目录校验在网页、CLI、isolated 策略中分别调用；普通程序调用、恢复旧会话和 work 文件工具的硬链接检查还不是同一条边界。不能用“命令被隔离”替代“所有入口都受保护”。

工作范围：

1. 将受保护源码根、工作区规范化和准入检查移出 `web/workspaces.py`，建立独立策略模块，由网页、CLI、Runner 与隔离工具共用。
2. 新建与恢复会话、每次运行、工具操作都重新校验授权工作区；失效、被替换或与源码/运行时重叠时拒绝，不相信数据库旧路径。
3. 文件读取、搜索、文档解析、上传共用文件身份检查。硬链接规则覆盖 work 与 code，不只在 isolated 命令启动前扫描；符号链接/父目录穿越继续拒绝。
4. 收口确定性 `--tool` 诊断入口，明确哪些能力只供本地显式诊断。任何面向真实模型的路径都不能借 demo/single-face 或底层 registry 绕过隔离。
5. 明确 scratch 的会话归属和关闭清理。同工作区的不同会话不能默认共享可执行配置或遗留 HOME 文件；运行结束清理进程后再释放资源。

验收：覆盖网页、CLI、新旧会话与程序装配入口；源码父子目录、符号链接、硬链接、失效工作区拒绝；安全工作区读写/上传/测试正常；拒绝路径不启动目标命令。用合成资料验证，不读取真实凭据。

预计涉及：`web/workspaces.py`、`cli.py`、`agent/runner.py`、`tools/workspace.py`、`tools/search.py`、`tools/sandbox.py`、`bootstrap.py` 和相关测试。具体改动以实现时复核为准。

C3 首批只做精确的单次授权，不同时扩张持久授权或任意 shell 前缀匹配。若之后需要会话级/项目级授权，再独立定义保存范围、失效与撤销。

路径出口不能保证识别任意编码、图片或源码副本。方案必须列出支持的路径形式、明确拒绝边界，并以捕获的实际供应商请求验证；不能把提示词当成访问控制。

C5 不用五个临时 fixture 冒充真实项目。源码安装目录也不能为回归临时放进可读白名单；支持不了的工具链应记录并留在关闭状态。

## 开放检查清单

- 模型生产入口不能取得未隔离的命令能力。
- 工作区/文件身份检查覆盖所有入口与旧会话，不能越界访问源码或凭据。
- 初始命令及交互 stdin 的授权范围、消费与拒绝行为明确。
- HOME、环境、scratch、读写和网络的正反向探针通过；启动失败不是“成功拒绝”。
- 长任务取消、超时、运行终态和进程清理一致，不承诺回滚已经发生的副作用。
- 真实项目、真实模型网页流程与 work 回归完成，失败/跳过项得到处理。
