# 第五版方案：code 模式（草案）

状态：2026-10-31 起草。**不替代**[下一阶段实施方案](下一阶段实施方案.md)（第四版）；那份文档里的 WK0–WK4 已全部交付且没有待办，本文件是它之后的一段，等 §2 六条门槛全部有证据、且 §4 的批次被接受后，再决定是否合并回路线图。

一句话结论：**code 模式不该马上开——六条门槛里 5 条没过。但核对过程发现三处「现在就在说谎」，其中一处（工具超时）与 code 模式无关，今天就该修。**

## 1. 为什么先做这件事

第四版交付完后，仓库里没有待办批次（`下一阶段实施方案.md` §9.10 的排期表已按「交付完的甘特图只是噪音」删掉）。剩下的只有两条路：继续做 work 模式的体验，或打开 code 模式。

打开 code 模式的闸门是[执行边界设计](执行边界设计.md) §14.4 的六条门槛。那六条是三个月前自己定的，此后 S／K／J 三批动过沙箱、审批与进程，但从没有人回头逐条核过。**在核过之前谈排期，等于拿一句口号当前置条件。**

所以本文档做的第一件事不是设计，是核对。

## 3. 三条从核对里长出来的判断

**第一条：35 秒不是「待实现」，是「现在就在说假话」。**

`run_tests` 的 schema 写着 `maximum: 300000`、默认 120 000，而 `ToolExecutor` 在 35 秒处把它掐死。模型按 schema 传 120 秒，得到的是超时——按第 6 条门槛的判据，这正是「用超时冒充拒绝」。这条与 code 模式无关：只要 `run_tests` 注册着（它现在不在 work 面，但 `--tool` 探针与测试路径仍能碰），承诺就是假的。**应该单独修，不挂在 code 模式后面排队。**

**第二条：`process write` 绕过的不是界面，是策略。**

现在不能利用——work 面没有 `exec_command`，起不了进程。但一旦开 code，模型可以先用 `yield_time_ms` 起一个交互式 shell，再用 `process(action="write", chars="rm -rf …\n")` 喂进去：**审批对象是「第一次 exec_command 的参数指纹」，而真正执行的那条命令从未被审。** 补的位置是 `policy.py` 的 `HOST_TOOLS` 与 `subject()`，不是网页上的一个确认卡。

**第三条：`(deny default)` 那句「macOS 拒绝全局 deny 读」是结论，不是实测记录。**

`sandbox.py` 文件头写着「macOS refuses any profile that denies reads globally (the loader aborts before `main`)」。这句话可能是对的（loader 需要读 dyld 与系统库），也可能只是当时试错后的自我说服——Codex 的 macOS 沙箱走的就是 deny-default 加一张读白名单。**两者差别很大**：如果是前者，C2 就得换隔离手段（合成 HOME + env 白名单 + 进程降权），而不是继续加固 SBPL；如果是后者，C2 只是补一张白名单。这个必须先花半小时证伪，再谈 1.5–2 人日。

## 4. 批次

顺序即优先级。每批独立提交、独立验收、独立可回退；**C0 与 C1 不依赖 code 模式，可以立刻做**。

### C0 · 先证伪（0.5 人日）

不是功能，是把上一节的三条判断变成事实。

**交付**：

- `scripts/probe_sandbox_profile.py`（已起草，2026-10-31）：跑三组 profile——`current`（**直接调用** `tools.sandbox.profile()`，不重抄一遍）、`wide-read`（`(deny default)` + `(allow file-read*)`）、`narrow-read`（`(deny default)` + 系统路径白名单）——记录 `sandbox_apply` 的返回码、`/bin/sh` 能否起来、工作区能否读写、外部写与凭据读是否被拒、本地 TCP 是否被拒，以及子进程能看见几个 `*_API_KEY`。**输出必须写一份到 `docs/diagnostics/`**，因为这是 C2 形态的唯一依据。
- 同一脚本在无法施加 profile 时（exit 71）**拒绝给结论**：`verdict.conclusion` 写「inconclusive」、`checks_meaningful: false`，并以非零码退出。一份什么都跑不起来的报告，逐项都是「拒绝成功」，读起来像边界生效——这一条是防止自己骗自己。
- `docs/执行边界设计.md` §10.4 的能力表按实测重写；`sandbox.py` 文件头那句结论改成「见 diagnostics 的哪一次记录」，或直接删掉。

**验收**：三组 profile 各一条结论，写清「deny default 可行／不可行」与失败点（loader、mach-lookup、还是 sysctl）。**没能给出结论就是没做完**；在 Terminal 里仍报 `inconclusive` 的，要把机器环境记下来（macOS 版本、是否已有外层沙箱），再决定是换机器还是换方案。

**回退**：纯新增脚本与文档，删掉即回到现状。

### C1 · 时间不说谎（0.5–1 人日）

**动机**：§3 第一条。schema 承诺 300 秒，执行器给 35 秒。

**交付**：

1. `AgentTool` 增可选 `timeout_seconds`（默认 `None` 表示用执行器的 35 秒）；`run_tests` 声明 180 秒（比 schema 上限 300 略宽不出来，只声明实际需要的），`exec_command` 声明 `yield_time_ms + 10` 秒，`web_fetch` 保持 35。
2. `ToolExecutor` 按 `timeout` 与工具自报值取较大者，且**上限受一个宿主常量约束**（`CHAGENT_TOOL_TIMEOUT_CEILING`，默认 180），避免工具自己把执行器撑成无限等待。
3. 超时与拒绝分开：执行器超时返回的错误文本明确写「工具在 N 秒内没有返回」，不写「命令被拒绝」。这条是第 6 条门槛的延伸。
4. `processes.py` 的 `wall_timeout <= 0`：保留抛错（0 会被误读成无限），改为接受 `0` 表示「跟 run 同生命周期」并在 run 结束时统一回收——或者干脆不实现，把 `timeout=0` 从 §14.4 第 3 条里删掉。**二选一，不要含糊过去。**

**验收**：`run_tests` 在 120 秒的测试集上跑完并返回真实结果（不是超时）；同一套用例在 200 秒时被 `CEILING` 截断且错误文本可分辨；执行器超时不再与「审批拒绝」共用文案。三条都要在 `tests/` 里，不靠手工。

**回退**：`timeout_seconds` 缺省即回到全局 35 秒，语义与现在一致。

### C2 · 沙箱地板（1.5–2 人日，形态取决于 C0）

**动机**：第 1 条门槛。现状是 allow-default + 定向 deny，能挡写与出网，挡不住「读别的项目」。

**交付**（若 C0 证明 deny-default 可行）：

- `profile()` 改成 `(deny default)` + 读白名单：系统路径（`/usr`、`/System`、`/bin`、`/sbin`、`/Library/Apple`）、工具链路径（`/opt/homebrew`、`~/.nvm`、`.venv`）、工作区、`TMPDIR`；写白名单保持现状。
- 探针从 6 项扩到 9 项：加「读别的项目失败」「`~/.ssh` 失败」「`kill` 外部进程失败」。
- 合成 HOME：`exec_command` 与 `run_tests` 的子进程 `env` 传白名单（`PATH`／`LANG`／`TERM`／`TMPDIR`／合成 `HOME`），不继承宿主机环境。这一条**无论 C0 结论如何都要做**，它同时是第 4 条门槛。
- 探针失败保持 fail closed（现状已经是）。

**验收**：能力边界表，不是测试全绿——

| 行为 | 期望 |
|---|---|
| 沙箱内 `cat ~/.ssh/id_rsa` | 失败 |
| 沙箱内读另一个项目 | 失败 |
| 沙箱内 `cat $DEEPSEEK_API_KEY` | 变量不存在 |
| 沙箱内写工作区 | 成功 |
| 沙箱内 `curl` | 失败 |
| `git status`／`pytest`／`npm install` | 成功 |

**回退**：`CHAGENT_SANDBOX=off`（默认值）；profile 生成器保留旧形态作为一个命名预设，便于 A/B。

### C3 · 授权与长任务（2–3 人日）

**动机**：第 2 条门槛，加上「跑得久的东西要能被授权」。

**交付**：

- `HOST_TOOLS` 加 `process`，`subject()` 对 `action="write"` 取 `chars` 的前 200 字符作为被审对象——**审的是将要执行的字节，不是进程 id**。
- 授权三态：`once`（默认，现状）／`always`（写入 `approvals` 之外的一张 `grants` 表，按 `(workspace, 命令前缀)` 持久化）／`reject`。`always` 的粒度只能是 allowlist 已有的那套前缀规则，不能整条命令。
- 命令拆分（`;`／`&&`／`||`／`|`／换行）：拆得动的逐段判，拆不动的（heredoc、`bash -c`、深层替换）**整条问一次**，而不是直接拒绝。
- 后台任务：`exec_command(background=true)` 返回句柄、完成时发通知，替代 `timeout=0`。

**验收**：同一 `pytest` 第二次不再问（`always` 生效）；`process write` 弹审批且拒绝后 stdin 未被写入；`cat <<EOF` 整条只问一次；`npm run dev` 起得来、可读日志、可停。

**回退**：`CHAGENT_APPROVAL=never`；`grants` 表保留不用；`process` 从 `HOST_TOOLS` 摘掉即回到现状。

### C4 · 网络（1 人日）

**动机**：`pip install` 这类动作在断网沙箱里必然失败。

**交付**：`off`／`grant` 两态，`grant` 走审批，审批文案写明「这条命令获得完整出网能力」。**不做代理**（seatbelt 的出网是二元的，按域名只能靠代理，那是另一个项目）。

**验收**：未授权时 `pip install` 明确拒绝且文案不是超时；授权一次后成功；授权不跨 run 复用。

### C5 · 真实项目回归（1 人日）

**动机**：第 5 条门槛。它是唯一能把「沙箱没坏」和「沙箱没把正常工作也拦了」分开的证据。

**交付**：`scripts/probe_real_projects.py`，吃一份 `--project` 列表（5 个真实仓库的绝对路径），每个跑 `git status`／项目声明的测试命令／`npm install`／`npm run dev`（10 秒后停），记录退出码、墙钟、是否被沙箱拒。报告写进 `docs/diagnostics/real-projects-<日期>/`。

**验收**：5/5 通过，且报告里能看到「哪些命令被拒、拒的理由」。**有任何一个项目因为沙箱而是失败，就回到 C2，不许在 C5 里放宽 profile。**

## 6. 明确不做

| 不做 | 理由 |
|---|---|
| 移植 Codex 那 2 592 行 shell scanner | 先写 200 行 splitter；拆不动的整条问一次，沙箱还在，「问一次」不等于「放开」 |
| Linux bwrap | 第一版只支持 macOS。Linux 上 `code` 不可用是能力边界，不是缺陷 |
| 按域名的网络代理 | 要代理才能做到，那是另一个项目；`grant` 就是二元 |
| Docker 当沙箱 | 路径翻译、`.venv` 符号链接、UID 映射成本高一个量级 |
| 策略语言／规则 DSL | 三种模式 + 一份 allowlist 前缀已经够；多一层可配置就多一层「为什么这条没被拦住」 |
| 在 work 模式下开审批链 | work 面没有宿主命令，审批链在那里只是死代码 |

## 7. 验收口径（沿用第四版）

1. **能力边界优先于测试全绿**：C2／C4 要列「哪些行为被拒绝、哪些没有」，一张测试报告不算。
2. **每条拒绝有独立文案**，不出现「超时」冒充「拒绝」；执行器超时与策略拒绝必须是两句话。
3. 每批记录「轮次／工具调用／墙钟」；本批**不减少模型往返**，实施记录里要写明「轮次未变」，不许用界面或日志改动冒充效率提升。
4. **跳过不是通过**：C0 的探针、C5 的回归，如果在某个环境里跑不起来，记 `skipped` 并写明原因，不能算绿。
5. 沙箱、审批、恢复解决三个不同问题——C2 不许顺手改审批，C3 不许顺手放宽沙箱。
