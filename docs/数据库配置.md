# PostgreSQL 配置

使用本机 PostgreSQL，默认数据库名为 `chagent`，默认使用当前操作系统用户通过本地连接访问。项目使用 psycopg 异步连接池和原生 SQL，不增加 ORM。

## 本地启动

```sh
uv sync
# 仅在数据库尚未存在时执行
createdb chagent
cp .env.example .env
uv run --env-file .env python -m chagent.storage check
uv run --env-file .env python -m chagent.storage migrate
```

`.env` 不提交到版本控制。程序从环境变量读取配置，使用 `uv run --env-file .env` 加载文件；从其他启动器运行时需由启动器注入环境变量。

| 环境变量 | 默认值 | 用途 |
|---|---|---|
| CHAGENT_DATABASE_URL | postgresql:///chagent | 数据库连接信息 |
| CHAGENT_DB_POOL_MIN_SIZE | 1 | 最小连接数 |
| CHAGENT_DB_POOL_MAX_SIZE | 4 | 最大连接数 |
| CHAGENT_DB_TIMEOUT | 5 | 获取连接的超时秒数 |

连接远程或要求密码的数据库时，在本地 `.env` 配置连接地址。不要把密码写入源代码或提交到仓库。

## 使用方式

```python
from chagent.config import Settings
from chagent.storage.database import Database

async with Database(Settings.from_env()) as database:
    async with database.transaction() as connection:
        await connection.execute("SELECT 1")
```

`connection()` 默认自动提交单条 SQL；需要原子执行多条语句时使用 `transaction()`，并在整个操作中传递同一个连接。异常或取消时回滚，成功时提交。一个 Database 实例在一个应用事件循环内使用，关闭后重新创建实例。

## 迁移

迁移 SQL 位于 `src/chagent/storage/migrations/`，按文件名排序执行。新增变更时添加下一个编号的 SQL，不修改已应用文件。

迁移过程使用 PostgreSQL 事务锁串行化，并记录名称和 SHA-256 校验和。重复执行不会重新建表；已应用文件被修改或数据库版本比代码更新时拒绝继续。迁移由命令显式执行，连接数据库不会自动修改表结构。

首个迁移创建 `workspaces`、`sessions`、`runs`、`messages`；第二个迁移增加 `model_calls`、`tool_calls` 和 `run_events`。模型请求同时保存上下文快照，工具执行前保存调用意图。消息正文使用 JSONB，保留现有消息类型结构；外键约束防止消息引用其他会话的运行，唯一索引限制每会话最多一个排队或活动运行。数据库不替代 Runner 的生命周期管理。

第三个迁移增加会话更新时间、归档时间和 `task_states`；已有会话初始化为空任务状态。任务状态通过修订号实现并发更新检查。

第四个迁移 `0004_context_summaries.sql` 增加 `session_summaries` 和 `compaction_calls`，分别保存版本化摘要检查点和独立摘要模型调用。原始消息保留，检查点和启用事件同事务提交。

第五个迁移 `0005_long_runs.sql` 增加摘要的来源运行、被保护的用户输入引用，以及会话隔离的 tool_artifacts 表。来源运行失败或取消时，其运行内摘要不用于后续对话。

第六个迁移 `0006_memories.sql` 增加 memories、memory_revisions 和 memory_extractions。活动键按作用范围唯一；提取请求单独审计，记忆提交与运行完成保持原子性。

## 检查

```sh
uv run python -m unittest discover -s tests -v
CHAGENT_TEST_DATABASE_URL=postgresql:///chagent uv run python -m unittest discover -s tests -v
```

未指定测试地址时，仅运行配置检查，数据库集成测试跳过。指定后，每个集成测试创建独立临时 schema，测试后清理；不改动业务表数据。测试数据库用户需要创建 schema 的权限。

集成检查覆盖迁移并发与重复执行、校验和、事务提交/回滚/取消、JSONB 往返，以及会话关联和活动运行约束。

连接池生命周期参考 [psycopg 官方文档](https://www.psycopg.org/psycopg3/docs/advanced/pool.html)。
