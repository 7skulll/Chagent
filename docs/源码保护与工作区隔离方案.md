# 源码保护与工作区隔离方案

状态：**部分基础能力已实现，完整方案尚未交付**。网页/CLI/会话/Runner 的统一工作区准入、普通文件工具硬链接与 no-follow 检查、环境自动注入移除及 isolated 命令隔离已有实现；虚拟路径与请求出口仍待实现。实施顺序只在[实施计划](实施计划.md)维护。本文描述目标架构；完整虚拟路径与请求出口不作为限定范围可信开发首版的前置门槛，后续顺序以实施计划为准。当前实现及已有验证仍以[执行边界设计](执行边界设计.md)和[实施计划](实施计划.md)为准。只读 code 已在限定范围开放，本文不代表完整源码/路径保护已经交付。

## 1. 目标

Chagent 在用户指定的工作区中处理任务。模型可以知道存在一个工作区及其可用能力，但不应因 Chagent 运行而获得 Chagent 自身源码目录、真实安装路径或其内容。模型发起的操作不能读取或修改自身源码。

将要求拆成可验证的边界：

1. 所有产品入口和后台运行均采用同一权限策略；源码目录、子目录和包含源码的目录不能成为工作区。
2. 文件工具只访问当前会话授权的工作区；宿主命令只有在可验证的隔离环境内才能开放。
3. 应用主动提供给模型的环境信息使用虚拟路径或相对路径，不包含源码真实路径。
4. 在模型请求出口检查已知受保护路径及可枚举别名；命中时拒绝发送，不能静默降级。

**保证范围**：可以测试对已知路径及明确定义的编码和别名不会直接发送，也可以测试工具不能通过指定攻击路径访问源码。不能仅靠路径过滤保证模型不会推断路径、识别任意变形或从公开信息中了解项目。用户主动输入、上传文件和外部网页也属于可能携带路径的数据；命中规则时同样拦截，而不是声称模型能够“遗忘”。

源码副本若由用户放进工作区，系统无法可靠识别所有语义等价的副本。本文保护的是运行中的 Chagent 安装与源码对象，以及可识别的路径或文件身份，不承诺识别任意改写、编码或截图中的源码。

## 2. 参考与差异

本机 Pi 的 `packages/coding-agent/src/core/system-prompt.ts` 按实际工具生成说明并注入 cwd；其默认 read 和 shell 工具使用本地文件系统和进程。cwd 是工作上下文，不是文件隔离边界。借鉴按工具组装提示词，不沿用其默认读取范围。

本机 Codex 的 `codex-rs/core/src/session/world_state.rs` 可注入环境上下文；`codex-rs/linux-sandbox/src/bwrap.rs` 按策略处理文件系统权限。借鉴“上下文说明与系统权限分离”、失败关闭和平台级验证。不能将 workspace-write 等同于工作区外不可读，也不能认为 Codex 默认隐藏自身源码。

## 3. 威胁模型与职责

防护对象是模型提出的工具调用及传入模型的产品上下文，包括旧会话、记忆、摘要、工具结果和后台任务。将工作区文件和网页视为不可信数据；它们不能修改权限策略。

不将同一系统账户下恶意用户、直接修改 Chagent 进程或数据库的攻击者、恶意 Python 扩展以及操作系统内核攻破纳入本阶段承诺。若需抵御本机用户，应使用独立账户、文件权限和独立运行环境。审批不能突破源码保护上限。

## 4. 目标架构

### 4.1 统一策略与工作区

引入与网页无关的安全策略模块，确定程序受保护根目录及真实路径，在会话创建、恢复、每次 run 和工具执行前校验。网页、CLI、演示工具、后台 worker 和程序内调用复用该策略；恢复会话不能信任历史中保存的路径。

工作区规范化后，不得与受保护目录相同、位于其内部或包含它；对符号链接及别名以实际目标判定。工作区被替换、消失或无法解析时失败关闭。已有不合规会话保留数据，但不可运行，界面提示选择安全工作区或创建新会话。

### 4.2 文件工具

沿用目录描述符和 no-follow 操作，所有读、搜索、文档解析、上传及生成文件入口复用统一授权。禁止父目录穿越和符号链接穿越；对已打开文件使用 `fstat` 检查类型和身份，避免先检查路径后打开造成的竞态。

硬链接需要单独处理：首版拒绝读取链接数大于 1 的常规文件，覆盖 read、grep、文档解析等内容读取路径，并在界面说明兼容性影响；这不是跨文件系统副本或运行期间外部改写的完整防护。若某平台无法可靠执行检查，则该路径失败关闭。工具输出与错误使用相对路径或虚拟路径，不暴露底层异常中的宿主绝对路径。

### 4.3 虚拟工作区与提示词

模型可见的工作区统一表示为 `/workspace`；工具层映射到实际工作区。模型不接收真实工作区路径、源码路径、自动目录树和 Git 状态。必要时由工具返回任务相关事实，工作区相对路径保持一致。

系统提示按实际注册的工具生成：简单问候正常回答，不主动列举环境；需要操作时使用工具；不得声称拥有未注册的写入、执行或联网能力。提示词是行为指导，不是访问控制。工作区文件、网页和工具输出均作为数据处理，不能覆盖系统约束。

### 4.4 命令执行

在隔离验收完成前，所有面向模型的入口均不注册宿主命令、测试执行和交互进程工具；配置试图开启时明确拒绝。禁止以审批或自动回退方式绕过。已有 CLI 诊断能力如必须保留，应与面向模型的运行隔离，并不得形成未受限工具调用路径。

后续采用隔离运行环境，仅映射工作区和必要的运行时，设置合成 HOME、最小环境变量、默认无网络；不挂载源码、应用状态及凭据。对可读运行时的范围、动态链接依赖、临时目录及平台后端分别列出策略。启动失败、探测失败或无法证明限制生效时拒绝执行。

旧 `workspace-write` 档不是读白名单，普通工作区外文件可读；新增 `isolated` 档已完成 C0 调查和本机 C2 执行隔离验收，见 [执行隔离实现](code模式执行隔离.md)。它没有实现虚拟挂载和路径隐藏，也不代表本方案 P0–P2 或全部 code 开放门槛完成。不预设其他平台支持同一种隔离。

### 4.5 模型请求出口

在所有供应商适配器之前设置共同的请求校验，覆盖主对话、重试、摘要和记忆提取等后台请求；校验完整结构化请求，包括文本、工具调用和结果、系统段落、历史与附件元数据。建立真实源码路径、规范化路径、已知别名和明确列出的编码形式的检测规则。策略本身和真实路径不得写入发给模型的报错。

命中时拒绝整个请求，在用户界面提示“内容包含受保护的本机路径”，不显示路径，不发出供应商请求；记录不含路径的审计事件。旧历史或记忆导致阻塞时，提供定位类别和安全清理流程。不能只替换部分文本而破坏工具调用配对，也不能把日志、重试或后台 worker 作为绕过渠道。

对图片、二进制附件、任意编码和间接描述无法保证检出；如产品要求严格防止这些通道传递路径，必须禁用未可验证处理的模态或通过可信转换后再发送。转换也需要单独验证，不能宣称通用识别保证。

## 5. 分阶段实施

| 阶段 | 工作 | 完成条件 |
|---|---|---|
| P0 | 建立统一策略；覆盖网页、CLI、新旧会话和后台入口；默认禁用未隔离的模型命令 | 所有入口一致拒绝受保护工作区，旧会话不可绕过；禁用配置失败关闭 |
| P1 | 文件工具统一路径与文件身份检查；虚拟路径与安全错误 | 穿越、符号链接、硬链接及竞态测试通过；正常工作区可用 |
| P2 | 所有模型请求接入出口校验；处理历史和记忆阻塞 | 捕获完整供应商请求，命中时请求次数为零；主流程与后台调用均覆盖 |
| P3 | isolated 的 macOS 执行档已实现；其他后端/工具链未验收 | 源码、凭据、其他项目和网络的正反向测试及实际工具链验证通过后，作为对应平台/工具链执行能力的开放依据；只读已有限交付，可写开发版按当前实施计划验收 |

每阶段分别记录实现、环境、通过与跳过项；文档中的目标不得标记为已交付。P0–P2 不以 P3 命令执行能力为前提。

## 6. 验收矩阵

| 场景 | 预期 |
|---|---|
| 网页、CLI、演示和程序入口选择源码、子目录、父目录或符号链接 | 拒绝；恢复已有会话与新建一致 |
| 工作区被替换或指向保护目录 | 后续运行和文件操作失败关闭 |
| 相对路径穿越、绝对路径越界、目录或文件符号链接 | 禁止访问 |
| 工作区中指向源码的硬链接 | 内容读取和搜索拒绝；记录平台限制 |
| 用户消息、历史、摘要、记忆、工具结果包含已知源码路径或受支持别名 | 请求出口拒绝，供应商未收到请求 |
| 主对话、摘要和记忆后台任务 | 均经过同一出口；重试不能绕过 |
| 开启未隔离宿主命令或隔离探测失败 | 拒绝注册或执行，不回退到宿主 |
| 正常工作区读取、搜索、上传和虚拟路径显示 | 按模式正常工作，不泄露宿主路径 |

除单元测试外，需在支持的操作系统上运行实际隔离探针和完整集成测试；测试跳过不能计为通过。用捕获客户端检查真实序列化请求，并测试拒绝时没有发送。完成后进行独立安全审查，记录已知限制。
