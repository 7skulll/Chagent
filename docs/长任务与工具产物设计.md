# 第二版：长任务与工具产物

本文保留第二版设计。当前已增加[第三版长期记忆](长期记忆设计.md)，与会话摘要及工具产物独立管理。

本版在第一版摘要闭环上增加两项能力：当前运行内部的安全压缩，以及大工具文本的持久化与按需读取。不引入长期记忆、向量库或独立任务调度系统。

## 运行内压缩

每次请求模型前，ContextManager 继续加载原始记录、任务状态和最新可用摘要。压缩范围由两部分组成：已完成历史的完整用户轮次，以及当前运行内已经结束的模型／工具交换。

一个交换是完整的 assistant 响应和它发出的全部工具调用结果。`context/segments.py:exchanges` 对调用 ID 和名称配对，并拒绝缺失、重复或不匹配的结果。执行器尚未结束整个工具批次时不会触发压缩，也不能在同一批次的两个结果之间切割。

```text
system + 原始用户输入 + [模型1 → 工具结果1] + [模型2 → 工具结果2] + [模型3 → 工具结果3]
                         └──────── 可摘要的旧交换 ────────┘   └── 最新交换保留 ──┘

模型实际上下文：system + 历史摘要 + 原始用户输入 + [模型3 → 工具结果3]
```

原始用户输入始终逐字保留，任务状态和系统指令独立组装；最新完整交换原样保留其消息结构，其中大文本工具结果可以使用产物摘录。摘要模型也会收到当前用户输入作为目标资料，但检查点的压缩来源不包含这条被保护的消息。

第一版在必需上下文超过预算时直接拒绝；本版允许内部规划先查看超预算投影，再尝试合法压缩。只有通过预算校验的最终请求才会交给任务模型。如果原始用户输入、系统指令、必要摘要与最新交换仍无法放入预算，明确失败，绝不只删掉某个工具结果来凑空间。

## 检查点有效性

新增迁移 `0005_long_runs.sql`，为 session_summaries 添加：

- `source_run_id`：摘要包含哪个尚在运行任务的执行信息。
- `protected_input_id`：该任务被保留的原始用户消息。

读取规则如下：历史摘要可以直接续接；运行内摘要在其来源运行中可用，来源运行完成后可跨轮续接；来源运行失败、取消或中断后，该类摘要只保留审计，不进入其他运行的模型上下文。

子摘要继承仍在运行的来源标记，不能通过再次摘要把失败任务的信息变成普通历史摘要。检查点保存时校验实际来源、输入 ID、工具批次完整性及首条保留消息。原始记录不改写。

失败分支的摘要版本不会删除。新的检查点可以从更早的有效父摘要继续，revision 仍按整个会话递增；父版本与有效历史边界在事务内重新检查。网页会标注运行内摘要是“仅当前运行可用”“可续接”还是“已失效，保留审计”。

## 多次压缩与限制

同一任务可以在出现新的完整交换后再次压缩。相同压缩范围失败后不会在原地反复重试；范围推进后可以重新尝试。默认每个运行最多 4 次压缩，每次沿用最多 8 个摘要模型请求、60 秒总时限。原有运行超时仍然生效。

```dotenv
CHAGENT_COMPACTION_MAX_PER_RUN=4
CHAGENT_MAX_TURNS=32
```

CLI 与网页装配的 Agent 默认最多 32 次任务模型调用，可配置为 1–128；摘要请求单独计数。达到调用、压缩或时间限制后依照原有终态机制结束，不进行无限循环。

## 大工具输出产物化

工具结果的文本超过 8000 个 UTF-8 字节时，RunRepository 在保存工具结果的同一事务内创建 tool_artifacts 记录，写入：

```text
id / session_id / run_id / tool_record_id
content / char_count / byte_count / sha256 / source_truncated
```

产物不可变，属于产生它的会话。原始 messages 和 tool_calls.result 仍保存工具返回的完整结果；ToolResultMessage.artifact 保存紧凑引用。上下文层将大文本替换为产物 ID、长度、摘要校验值、头尾摘录和读取方法，维持原 tool_call_id、名称与错误标记。

普通模型请求不会再从数据库加载这些产物的全部文本：仓储的 project_artifacts 模式只读取引用及图像内容，上下文层据此构造文本摘录。摘要生成也使用产物引用，避免摘要请求再次塞入大输出。原始记录检查与会话 CLI 默认仍读取完整消息。

文件工具不再提前截断 16000 字符的生成结果，继续遵守原有 1 MiB 文件限制和行分页。命令工具默认最多捕获 1 MiB 输出；显式 max_output_chars 仍可限制为更小的值（参数上限仍为 64000），超出部分排空并明确标记。产物保存的是实际捕获的输出，source_truncated 明确表示上游已有截断，不声称恢复被丢弃的内容。

## 模型与网页读取

装配 Agent 时注册 read_artifact，只读本次 ToolContext.session_id 所属的产物，模型不能通过参数指定其他会话。

```json
{"artifact_id":"产物UUID","offset":0,"limit":1000}
```

offset 是从 0 开始的 Unicode 字符位置；limit 为 1–1000。读取结果报告长度、SHA256、来源截断标记与 next_offset。分页在 PostgreSQL substring 完成，读取一页不加载全文。页大小足够小，不会再次产生嵌套产物。

网页历史接口对带产物的工具结果返回引用和摘录，避免把完整输出与 details.output 重复传给浏览器。展开工具结果后可以点击“读取产物全文（分页）”，逐页追加文本。

```text
GET /api/sessions/<session UUID>/artifacts/<artifact UUID>?offset=0&limit=1000
```

API 先检查启动工作区和会话，再读取会话所属产物；其他会话的 ID、未知 ID 返回 404，非法分页参数返回 400。快照增加 artifact_ids、summary_source_run_id、protected_input_id，方便检查每轮实际输入。

## 验证与边界

测试覆盖六轮工具任务中的多次压缩、原始输入保留、工具配对、失败后摘要分支恢复、取消后的摘要隔离、Unicode 产物分页重组、SHA256、模型通过工具读取产物、跨会话拒绝读取，以及网页历史摘录与分页边界。原有迁移、适配器、摘要失败回退、取消、网页 SSE 与文件工具测试继续运行。

本版完整回归为 86 项测试。浏览器使用离线模型读取设计文档，生成一个 8991 字节的工具产物，验证了结果摘录、分页按钮和字符游标推进；没有使用真实供应商 Key 发起推理请求。

当前不处理图片产物、自动产物清理、搜索产物内容、失败任务自动恢复或跨会话记忆。运行仍由一个本地进程托管。产物与原始审计信息会增长，保留／清理策略作为后续能力；本版不自动删除历史。
