# 工作区 F5 实施与验收

日期：2026-11-03（Asia/Shanghai）。F5 预览、错误恢复与跨流程验收已实施；F1–F5 首版代码范围已覆盖。本文区分自动测试、真实模型、浏览器验收和未验证范围，不把合成项目当作任意业务项目回归。

## 预览与边界

- PDF 使用独立解码进程按页栅格化为 PNG。提供上一页/下一页、页码输入、缩放与适应宽度；不把原始 PDF 放入 iframe 或执行文档脚本。按页 PNG 请求代替原始 PDF 的浏览器 Range 流式读取，不依赖浏览器 PDF 插件。
- 图片支持 PNG、JPEG、GIF、WebP，解码后重新输出 PNG。GIF/WebP 动图仅显示静态首帧；尊重 JPEG EXIF 方向。SVG 可作为文本编辑，不能以活动 SVG 内嵌预览；HEIC/AVIF/BMP 等目前提供明确的不支持说明与下载退路。
- PDF/图片为只读标签，不允许文本保存或另存为；文本草稿、多个标签和工作区隔离继续保留。预览不会自动注入模型请求；可预览不代表模型具备图片理解、OCR 或扫描件识别。
- 文件入口统一使用工作区 UUID + 相对路径，继续校验已打开工作区、路径、目录身份、软硬链接和普通文件规则。页面接口携带读取内容 SHA256；文件变化后旧版本返回 409，重新加载或有限轮询会读取新状态。
- 不支持格式、损坏/加密 PDF、大文件显示原因；允许时下载原文件。输入与下载上限 20 MiB；PDF 最多 2000 页、栅格最长边 1600 像素；图片最多 3200 万源像素、栅格最长边 2400 像素，缩放范围 25%–400%。这些是首版资源限额。

## 实现与依赖

新增 `previews.py` 与 `preview_worker.py`，通过 pypdfium2/Pillow 解码。依赖已写入 pyproject.toml 和 uv.lock，`uv sync` 即可安装，不要求用户另外安装 Poppler。PDFium 不适合并行线程调用，采用独立进程，依据见 [pypdfium2 官方说明](https://pypdfium2-team.github.io/pypdfium2/python_api.html#incompatibility-with-threading)。

- 解码进程只收到已校验的文件字节，不收到用户提供的宿主磁盘路径。
- 清空继承环境，只提供运行所需路径和独立 HOME/tmp；主服务持有的模型 Key 不传入子进程。
- 最多两个同时解码，排队超过 2 秒返回可重试 503。父进程 15 秒超时，子进程 CPU 10 秒上限；stderr 使用受文件大小限制的临时文件，解码进程退出后回收。
- Linux 设置 1.5 GiB 地址空间限额；macOS 不使用其不兼容的 RLIMIT_AS，依靠输入、页面尺寸、像素、并发、CPU 和超时限制。独立进程用于解码故障隔离，不宣称是完整 OS 沙箱。
- 图片输出重新编码，浏览器只接收 image/png；下载仍使用 attachment。响应头避免重复添加 nosniff，保留本机来源校验与 CSP。

新增接口（统一前缀 `/api/workspaces/{workspace_id}`）：

| 方法与路径 | 功能 |
|---|---|
| GET `/preview?path=…` | 类型、版本、身份、页数或图像尺寸；不支持时返回原因与下载能力 |
| GET `/preview/page?path=…&version=…&page=1` | 校验版本后输出单页 PNG；图片同样走重新编码 |
| GET `/file-state?path=…` | 仅查询身份与大小，二进制标签轮询无需重复读取/解码整个文件 |

本批没有新增数据库迁移。现有版本升级仍使用 0018/0019。

## 外部变更与错误恢复

保留 F3/F4 的手动保存与版本冲突策略。二进制文件使用轻量身份检查，变化后更新预览元数据；失败可重新加载或下载。损坏图片、伪装图片、损坏/加密 PDF 不执行不可信内容。

本批修复两处界面恢复问题：确认请求临时失败后重新装配同一待确认记录，按钮不会永久禁用；文件树和编辑标签的选中路径同步，避免视觉选中对象与操作目标不一致。继续检查保存期间输入、工作区切换延迟响应和未保存离开提醒。
