# API Key 与模型切换

## 只配置一个 Key

在本地 `.env` 中配置一种供应商的 Key，即可使用该供应商的默认地址与模型。例如：

```dotenv
DEEPSEEK_API_KEY=你的Key
```

然后运行：

```sh
uv run --env-file .env ./scripts/start.command
```

这会启动真实模型网页；提交消息后才发起模型调用，模型可选择已注册的工具。宿主命令仍然默认关闭。

| 供应商 | Key 变量 | 预设模型 | 协议 |
|---|---|---|---|
| OpenAI | OPENAI_API_KEY | gpt-5.4-mini | Chat Completions |
| DeepSeek | DEEPSEEK_API_KEY | deepseek-flash | OpenAI 兼容 Chat Completions |
| Anthropic | ANTHROPIC_API_KEY | claude-sonnet-4-6 | 原生 Messages |
| 通义千问 | DASHSCOPE_API_KEY | qwen-plus | OpenAI 兼容 Chat Completions |

这些是应用预设，不代表模型永久可用或每个账号都具有调用权限。默认值来自本仓库 models/settings.py 的 PRESETS，不自动升级；本轮文档整理没有重新验证供应商模型目录。通义预设使用北京区域地址，其他区域或专属工作区可以通过 `CHAGENT_BASE_URL` 覆盖。

## 多个 Key 与模型切换

API Key 是账户凭证，不可靠地编码供应商、区域或模型名称。因此按环境变量名称匹配供应商，不根据 `sk-` 等前缀猜测，也不拿同一个 Key 轮流尝试多个服务。

多个供应商 Key 同时存在时，显式选择：

```dotenv
CHAGENT_PROVIDER=deepseek
```

也可以按本次启动选择：

```sh
uv run --env-file .env python -m chagent.cli --workspace /你的资料目录 --provider deepseek "你好"
uv run --env-file .env python -m chagent.cli --workspace /你的资料目录 --provider deepseek --model deepseek-v4-pro "分析这个项目"
uv run --env-file .env python -m chagent.cli --workspace /你的资料目录 --provider openai --model gpt-5.4-mini "你好"
```

`--provider`、`--model` 覆盖同名配置；选择供应商不会自动寻找其他供应商的 Key。没有 Key 或配置有歧义时会在开始运行前报错，不静默退回演示模型。

切换供应商不会改变会话工作区。历史消息转换为所选协议；其他模型的签名思考块不直接回放。请求快照保存实际使用的模型、协议与地址。

## 自定义兼容服务

```dotenv
CHAGENT_PROVIDER=custom
CHAGENT_API_KEY=你的Key
CHAGENT_BASE_URL=https://你的服务/v1
CHAGENT_MODEL=服务支持的模型名
```

自定义服务必须支持流式 Chat Completions 和工具调用。不能仅凭一个通用 Key 自动知道第三方网关地址及模型名。

`CHAGENT_API_KEY` 只用于 `custom`。内置供应商必须使用各自的命名 Key（如 `DEEPSEEK_API_KEY`），即使环境中存在 `CHAGENT_API_KEY` 也不会使用它。此前为内置供应商只配置通用 Key 的用户，需要迁移到对应的命名变量。配置了多个命名 Key 时仍要求明确选择。

命名供应商也支持 `CHAGENT_BASE_URL`，OpenAI 另外接受 `OPENAI_BASE_URL`。地址禁止内嵌账号密码和 query；远程地址要求 HTTPS，本机 localhost/127.0.0.1/::1 允许 HTTP。配置地址由用户控制，模型参数不能更改认证目标。

本机兼容服务若不要求认证，可显式填入占位 Key。模型与预算仍需匹配服务实际支持的能力；“兼容接口”不保证任意模型都支持同样的参数、图像或工具功能。

## 检查配置与离线演示

```sh
# 列出内置预设
uv run python -m chagent.models list

# 只解析并展示所选配置，不发送 API 请求、不显示 Key
uv run --env-file .env python -m chagent.models check --provider deepseek

# 完整解析：模型、预算、沙箱／命令／压缩、数据库，以及被 shell 覆盖的 .env 值
uv run --env-file .env python -m chagent.config show

# 机器可读
uv run --env-file .env python -m chagent.config show --json

# 明确选择固定响应模型，不发送网络请求
uv run --env-file .env python -m chagent.cli --workspace /你的资料目录 --demo "验证基础链路"

# 显式工具演示仍然可用，--tool 隐含 --demo
uv run --env-file .env python -m chagent.cli --workspace /你的资料目录 --tool list_dir --arguments '{}'
```

配置检查只能确认选择和格式，不能证明 Key 有效、账户有余额或模型可访问。当前环境中若已有其他应用配置的多个 Key，也需要明确选择供应商。

`models check` 用于脚本与机器读取，只给 JSON。人读用 `config show`：它以 `.env` 为默认层、**环境变量优先**（与 `uv run --env-file` 的实际行为一致），并逐条列出「被环境覆盖」和「只存在于 shell」的变量。密钥一律只显示 `<set>`，不显示值、哈希或前后缀。CLI 与网页启动时也会打印一行 `Behavior:`，列出沙箱、宿主命令、压缩与轮数上限。

为什么需要有这条命令：环境中的同名变量仍会覆盖 `.env` 对应变量，例如 `DEEPSEEK_API_KEY` 或 `CHAGENT_MODEL`。`config show` 会报告这些覆盖；内置供应商不再使用 `CHAGENT_API_KEY`。

## 运行与记录

- 复用已有 ModelClient、AgentRunner、上下文、工具与 PostgreSQL 链路。
- 解析文本增量、思考块、分片工具参数、停止原因和实际 token 用量；工具仅在完整最终响应后执行。
- OpenAI、DeepSeek 和通义共用兼容适配；Anthropic 单独转换工具与消息格式。
- 不完整流、拒绝、认证失败和未知结束原因进入明确的错误状态；取消会关闭请求，不伪装为正常回答。
- 429／5xx 在同一轮内重试 2 次（0.5s、1.5s 退避）后仍失败才收尾；4xx 与其他错误一次即走。重试只发生在第一次产出之前，因此不会把两段回答拼在一起；也不自动切换供应商，不重放工具操作。
- 密钥字段不进入 ModelRequest 或上下文快照。认证错误使用状态码和安全提示，不持久化服务端可能回显凭证的错误正文。
- 配置对象的 repr 隐藏 Key；`.env` 已排除在版本控制之外。
- 启动时打印 `Resolved:`（供应商／模型／地址／Key 来源）与 `Behavior:`（沙箱、宿主命令、压缩、轮数上限）；`config show` 展开全部行为配置并点名被环境覆盖的 `.env` 值。
- 费用未知时保持 None，不将其记为免费。缓存 token 与普通输入分开，推理 token 是输出的子集。

应用默认上下文预算 65536、输出预留 8192、请求读超时 60 秒、整次运行上限 180 秒、429／5xx 重试 2 次。可用以下变量调整：

```dotenv
CHAGENT_CONTEXT_WINDOW=65536
CHAGENT_MAX_TOKENS=8192
CHAGENT_MODEL_TIMEOUT=60
CHAGENT_RUN_TIMEOUT=180
CHAGENT_RETRY_ATTEMPTS=2
```

`CHAGENT_RETRY_ATTEMPTS=0` 关闭重试（退回一次尝试即失败的行为）。解析结果在启动的 `Resolved:` 行与 `config show` 里都显示为 `retry 2`／`no retry`——一个被 shell 覆盖的值应该表现为一行错的配置，而不是一次无法解释的重试。

这些预算不是通过 Key 查询得到的模型能力。更换模型时应按其真实上限调整；安装可选 tokenizer 时使用 BPE 估算，否则回退为字节估算；两者均不是供应商计费用量。自定义推理模型的专属参数和供应商扩展不承诺自动兼容。

## 网页只读代码分析

默认仍是 work。需要启用时，在本机 `.env` 设置：

```dotenv
CHAGENT_CODE_MODE=on
CHAGENT_ALLOW_HOST_COMMANDS=true
CHAGENT_SANDBOX=isolated
CHAGENT_SANDBOX_WRITABLE=false
CHAGENT_SANDBOX_NETWORK=false
CHAGENT_DEFAULT_MODE=work
```

启动 `./scripts/start.command` 后，侧栏可为新会话选择“只读代码分析”。启动器自动加载项目 `.env`，仅补充进程缺失变量；`--env-file` 可覆盖文件位置，环境优先级保持不变。复用旧服务时显示其实际 behavior，配置变更必须重启服务。`--demo` 不支持 code。

code 工作区由内核禁写，HOME/tmp 是 run 私有可写临时目录。命令断网与 `CHAGENT_WEB_ACCESS` 的独立网页搜索分别显示；审批沿用现有设置，不强制改成 never。适用测试需要其依赖位于已授权工作区或声明的运行时；缺少依赖时如实失败，不扩大白名单或自动安装。当前真实项目范围见[只读验收记录](只读code验收-2026-11-02.md)。


## 网页代码开发（2026-11-03）

显式启用可信开发配置后，侧栏显示“代码开发”，code 会话可创建/编辑文件并执行命令、测试，无需逐项审批。默认配置与 work 工具面不变；不是给只读档自动提权。

```dotenv
CHAGENT_EXECUTION_PROFILE=trusted-development
CHAGENT_CODE_MODE=on
CHAGENT_ALLOW_HOST_COMMANDS=true
CHAGENT_SANDBOX=isolated
CHAGENT_SANDBOX_WRITABLE=true
CHAGENT_SANDBOX_NETWORK=false
CHAGENT_APPROVAL=never
CHAGENT_DEFAULT_MODE=work
```

以上条件不满足时启动拒绝；尤其已有 untrusted/on-request 审批设置不会自动改成 never。配置仅在启动时生效，复用旧服务仍用旧配置。沙箱缺失或探针失败拒绝执行。当前用户 .env 不由该功能自动修改。

work 继续读取资料并生成数据库下载；只有 code 获得三个工作区写工具。两种网页 code 的 process 都仅 read/stop，不提供 write/EOF、PTY、命令联网或自动依赖安装。取消保留已经写入的文件。工具结果提供写入路径、编辑 diff 和测试输出，尚无独立的整轮变更汇总面板。

isolated 的 Python 默认设置 PYTHONSAFEPATH=1；exec_command 中需要项目导入时显式使用 PYTHONPATH=.。run_tests 对 unittest/pytest 在沙箱内部仅设置当前工作区的 PYTHONPATH，并使用独立字节码路径、禁写字节码，避免导入失败及快速等长修改后的旧缓存误判，不继承宿主 PYTHONPATH。

关闭开发配置可设置 CHAGENT_CODE_MODE=off，或改回 configured + sandbox_writable=false 后重启；保留文件和历史，不自动回滚。源码路径保护限制与真实验收见[开发版验收](代码开发验收-2026-11-03.md)。
