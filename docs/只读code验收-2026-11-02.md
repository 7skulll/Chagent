## 实现与实际配置

网页只允许 `code=on + allow_host_commands=true + isolated + sandbox_writable=false + network=false`。`web/policy.py` 同时检查配置、实际沙箱和工具面；新建、恢复与运行 code 会话都会预检。后端缺失或探针失败返回 503，禁用 code 的旧会话返回 409，不能降级成 work。可写和交互 code 仍拒绝，demo 只支持 work。

新会话默认 work，侧栏可选择“只读代码分析”；会话中固定显示禁写、命令断网和交互输入关闭。配置面板同源显示这些字段、审批策略和独立网页搜索。命令工作区禁写不限制服务自身的数据库/上传写入；create_file 仍只属于 work。

启动器现在自动加载项目 .env，只补充进程中缺失的变量，也支持 --env-file。未覆盖用户现有 .env。复用已有服务会打印实际 behavior 并说明新环境配置不生效。本次实际遇到 8877 已有旧服务，按新提示确认其 code=off，转到独立 8893 端口验收，没有停止旧服务。

本次模型：已配置的 DeepSeek deepseek-v4-flash。服务仅监听 127.0.0.1:8893，数据库使用独立 `chagent_readonly_acceptance_20261102` schema；记忆提取和独立网页搜索在本次验收进程中关闭。副本位于 `/private/tmp/chagent-r5-20261102`，未扩大 runtime 白名单。

## 剩余边界与回退

可用范围是 macOS、本机已声明运行时和适用测试。其他 OS、完整项目依赖、构建/安装、命令联网和交互式 stdin 未开放；C3/C4/C5 的可写版本门槛未取消。目录 inode 不入库，停机期间普通目录替换不能追溯；请求出口路径保护仍是后续批次。

需要回退时将 CHAGENT_CODE_MODE=off 后重启，保留只读配置，不通过关闭沙箱恢复能力。旧 code 会话不可继续运行；历史数据仍保存。
