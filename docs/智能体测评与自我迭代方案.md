## 1. 目的与范围

目标是形成“可观察问题 → 可复现 → 可验证改进 → 可阻止回归”的链路，最后才建立人工审查下的提案闭环。不以单一总分代替诊断、能力和权限约束。

| 系统 | 回答的问题 | 交付物 |
|---|---|---|
| T：追踪 | 发生了什么，用户等待与资源消耗在哪里 | 有来源和精度标记的时间线、上下文变化、用量 |
| E：测评 | 是否满足任务要求，结果是否稳定 | 用例、独立判据、重复试验、版本化结果 |
| A：归因 | 哪些现象有证据，哪些根因仍待核实 | 多标签诊断线索、人工复核及可验证假设 |
| L：迭代 | 某项修改是否改善目标且没有破坏约束 | 提案、基线/候选对照、门禁、翻转清单 |

T 与小型 E 可以并行启动；A 依赖证据但不阻止建立基础用例；L 必须等前面的证据和门禁可用。不承诺完成所有归因后才开始测评，也不允许直接从历史频次跳到自动改代码。

## 3. 测评对象、判据与实验记录

### 3.1 基本单位

- case：任务输入、初始夹具、授权边界、验收条件、预算和清理约定。
- trial：某个已固定版本在该 case 上的一次独立尝试；保留失败和取消，不只保存成功样本。
- outcome：运行后实际环境与交付物状态；run 的 completed 仅是控制流终态。
- grader：独立检查某一条件的判据；输出 pass / fail / inconclusive / infra_error 及证据。
- experiment：预先定义的用例集、重复次数、基线与候选、预算和比较方法。

一项操作是否成功，以文件、数据库、HTTP、审批或进程事实判定，不接受模型的“已完成”作为证明。文档综合、审查和交接还必须检查回答/报告正文：来源是否真实、关键事实是否遗漏、是否误述执行结果。环境结果和正文评价分开报告，不能因为 C5 曾出现模型自述错误而禁止评价所有正文。

优先使用确定性断言；人工与经过人工样本校准的模型判定用于语义质量补充。保存判据输入、版本、理由与不确定性；模型评审不能单独使候选自动通过或否决，争议进入人工复核。

### 3.2 每次结果必须绑定的 manifest

| 类别 | 必须记录 |
|---|---|
| 被测版本 | Chagent 完整 commit SHA、未提交补丁哈希、提示与工具声明版本、实际启用技能及内容哈希 |
| 判据与数据 | case/suite/grader 版本和哈希、初始 fixture 内容哈希、预期状态、导出来源与脱敏版本 |
| 执行环境 | 依赖锁文件、镜像 digest、运行平台、网络策略、审批策略、允许挂载与服务初始状态 |
| 模型 | 供应商、实际返回的模型标识（如可得）、请求模型名、推理设置、采样设置、输出/上下文预算 |
| 运行与统计 | trial ID、开始/结束时间、重试、超时、种子（如支持）、用量、价格来源/日期、重复次数与停止规则 |

fixture 可以使用 tar + SHA-256；打包须记录忽略规则、安全解包规则和外部依赖。可移动分支/标签不能固定版本，完整 commit SHA 可以。只固定文件快照不能保证联网依赖、模型服务或镜像可复现；动态模型别名解析不到不可变版本时如实标为限制，不称为完全可复现。

真实模型先用小批预试验估计波动，再在正式比较前固定重复次数和预算；同一 case 从等价初始状态分别运行基线与候选，交错执行以减少时间/供应商波动影响。报告每项成功次数/总次数、差值及适当的不确定性区间；不根据某次翻红后反复重跑直到变绿。两次重跑可用于排查环境，不能作为稳定性证明。

耗时区分活动时间、审批等待与端到端时间；分任务类型报告分布和样本数。成本纳入任务模型、摘要、记忆、模型评审和重试；没有返回费用时记录 unknown，按版本化价格估算的值标为估算，不能补零。人工取消、环境故障和不确定结果单列，同时报告计划试验数和可评分数，禁止静默排除失败美化成功率。

## 4. T：证据与时间线

### 4.1 统一只读事件视图

先在现有表上做投影，避免重复维护一套日志。Span 至少包含：

```
span_id, run_id, parent_id?, links[], kind, source_record_ref,
queued_at?, started_at?, execution_ended_at?, committed_at?,
status, timing_source, timing_precision, tokens?, cost?, warnings[]
```

kind 可为 run/model/tool/approval/compaction/memory/site；没有对应证据的类型不制造 Span。后台压缩与记忆使用因果 links，不强制嵌套在已结束的 run 时间区间内。site 服务可能跨 run，仅把本轮动作计入本轮活动。source_record_ref 可定位到原始行或事件序号，读取仍受原有权限与输出边界约束。

### 4.2 计时口径

1. **累计耗时**：各 Span 时长之和，反映调用开销，允许超过 run wall。
2. **墙钟占用**：在目标观察窗口内取各时间区间的并集；并行工具、重叠审批、投机压缩不能重复扣除。不同类别的并集之间也可能重叠，不能再直接相加。
3. **关键路径**：有明确依赖边时计算阻塞交付的路径；缺依赖证据时不声称得到精确关键路径。
4. **未解释时间**：wall 中未被已知区间覆盖的部分；它可能来自未埋点、提交延迟、排队或调度，不能直接判为框架故障。

当前工具 created_at 是入队时点；tool_started 是审批/调度之后的事件。不能把 created_at 当执行开始，也不能在已排除审批的执行区间中再次减审批时间。批量审批可能覆盖多调用，只计对应区间并集；无 decided_at 时按明确的终止事件或观察时点计算，标注未结束/估算。

文本事件存在合并与缓冲。历史事件的持久化时刻不等于供应商首 token 到达时刻；区分首响应事件、首可见文本和浏览器收到文本。没有客户端计时就不报告浏览器 TTFT。缺少准确起止的历史调用输出 null 或估算区间；P1 先列缺失字段，再决定是否追加单调时钟埋点，不承诺“不需要新埋点”。

### 4.3 上下文差异

展示快照的实际/估计 token 及计数来源、选中消息 ID、排除原因、摘要版本、工具加载和技能/记忆注入。消息消失、fresh window 丢弃和工具输出截断只是变化事实，不直接认定为错误。通过包含明确约束的用例验证关键信息是否仍可用；版本不同或字段缺失时标为不可比。

完成判据：CLI 能输出所选 run 的时间线、证据位置与缺失范围；并发、审批、投机及 post-turn 样本不出现负的“框架耗时”，不把后台工作混成回答失败。UI 在查询与判据稳定后再做，不作为初期前置工程。

## 5. A：从诊断线索到根因

规则输出为：`label + evidence_refs + certainty + possible_causes + missing_evidence + rule_version`，支持多标签、未命中和人工纠正。规则优先是纯函数，输入包括事件、上下文、用例期望、环境基线与 outcome，不局限于 Span 列表。certainty 使用 observed / suspected / confirmed，不伪造未经校准的概率。

| 标签 | 能直接观察的事实 | 升级为根因所需的额外证据 |
|---|---|---|
| F1 规格理解 | 输出或行为违背明确要求 | 核对要求来源与歧义，区分理解错误和执行错误 |
| F2 上下文信息丢失 | 消息移除、摘要替换、结果截断 | 关键事实未被摘要/任务状态保留，且与失败行为有对应关系；必要时做受控对照 |
| F3 工具选择 | 使用了某工具或声明未加载 | 根据目标和工具契约证明不适用，不强制唯一工具调用顺序 |
| F4 参数问题 | schema/类型校验失败 | 区分模型参数错误、适配缺陷、schema 不一致和输入文件异常 |
| F5 执行问题 | 工具失败、unknown 或执行期错误 | 再分环境/依赖/供应商/应用/工具缺陷；retry.py 的结局和可重试性不是责任层 |
| F6 结果理解 | 后续主张/动作与结果明确冲突 | 用状态字段或人工复核确认矛盾，不只对字符串差异做判断 |
| F7 无进展循环 | 重复工具、反复重试或状态查询 | 同时检查结果、文件状态和任务进展；合理轮询及修改后重验不算停滞 |
| F8 预算限制 | 达到轮次、时间、输出或上下文上限 | 上限是停止原因；是否因低效、环境故障或配置不足触发需要另查 |
| F9 审批交互 | 拒绝、超期、无人查看或重复请求 | 区分正确拦截与不必要摩擦，不以减少审批数作为单独优化目标 |
| F10 初始环境漂移 | 试验前环境不符合固定基线 | 比较初始文件/依赖/镜像/服务状态；任务预期产生的文件变化不是漂移 |

开发规则时复核历史失败样本，并抽取 completed、cancelled、interrupted 和正确拒绝的负例。保存人工标签、证据、分歧与复核版本；验证集与调规则样本分开，报告每标签的样本数、精确率/召回率或无法估计的原因。不能只报告“命中多少失败”，也不能用旧 17 个样本宣称准确率已稳定。

改进优先级综合影响、频率、归因可信度和修复成本；越权、数据损坏和错误重试即使低频也可先处理。尚未确认根因时，提案首先补观测或复现实验，不直接改提示词压低标签频次。

## 6. E：用例与回放

### 6.1 首批用例覆盖

首批建立约 12–16 个有明确判据的 case，数量按有效覆盖调整，不以凑数验收。T/A 开发过程中同步维护开发集与独立保留集：

| 能力/约束 | 首批判据示例 |
|---|---|
| 项目阅读、修复、验收 | 引用真实文件；缺陷有复现；修复后行为满足要求；跳过与零收集不算通过 |
| 建站交付 | site 启动、状态/正文匹配、端口变更后重验；HTTP 不等于视觉正确 |
| 运行诊断 | 同会话定位；拒绝跨会话；unknown 不盲重试；日志注入不触发执行 |
| 文档综合 | 来源位置真实、数字冲突保留；扫描件不声称 OCR；XLSX 缓存空值不当作零 |
| 变更审查 | 有缺陷样本能定位；无缺陷样本不凑问题；不自动修复或发评论 |
| 交接与多轮约束 | 当前要求覆盖历史；压缩后约束保留；同工作区摘要不升级为跨会话运行权限 |
| 技能选择 | 应触发、相邻任务不触发、显式点名、工具不可用时的诚实降级；不强制只有一种合法完成轨迹 |
| 执行边界 | 拒绝后无副作用、过期授权不复用、取消/未知不声称回滚成功 |

权限、确定性协议检查可单次执行；真实模型的语义能力按实验记录重复运行。最小多轮与压缩用例首批纳入，不等到自迭代阶段才补。需要浏览器的视觉/点击项暂标未覆盖并保留人工验收，不因此让整站能力自动变绿。

### 6.2 工具回放分级

| 类型 | 做法 | 能证明什么 |
|---|---|---|
| 纯逻辑 | 固定输入测解析、校验、投影、分类 | 确定性函数与契约回归，可优先做到不调用模型 |
| 有状态但可重建 | 在独立文件/库/容器夹具中恢复前置状态，顺序执行编辑、命令、站点动作 | 指定环境中的状态变更；不保证跨平台或外部依赖一致 |
| 外部或宿主副作用 | 默认禁止历史重放；用模拟服务或单独授权的集成测试 | 模拟契约或有限的真实整链，不代表任意历史调用可安全重做 |

历史 arguments/result 只是回放候选，不是完整夹具。必须补执行前文件、数据库状态、依赖与必要调用顺序；缺前置状态的记录标为不可回放。AgentTool.replay 是提示元数据，不是安全保证。审批结果不作为可复用授权，也不在真实宿主重放 native 命令或 stdin。

比较稳定语义、预期副作用与错误契约，按字段声明哪些 UUID/时刻/端口可归一化；对 outcome_unknown、审批决定、退出码等关键状态不得归一化掉。夹具每次独立重建并验证清理，拒绝路径穿越/链接逃逸的归档；不预先承诺全部历史调用“完全确定性、秒级完成”。

### 6.3 模型 cassette

录制前完成授权、脱敏与版本绑定。脱敏若改变请求语义，cassette 仅作有局限的导出，不承诺精确回放。只保存测协议需要的结构，不默认导出私有推理或凭据。

回放按规范化请求指纹、调用序列和协议结构匹配；指纹包含模型参数、提示、工具声明、技能版本等行为相关部分，仅忽略事先列出的非语义字段。请求指纹必须字段完整、消息哈希数量匹配且汇总哈希一致；模型 endpoint 以哈希参与身份绑定，不导出原始 URL。损坏或旧版 cassette 拒绝读取，请求偏离时停止并报告 divergence，不按序硬塞下一条响应，也不偷偷退回付费真实调用。流式中断、错误和取消分别建样本。

cassette 证明固定响应下框架行为，不证明新模型能力提升；提示、工具或技能变更造成偏离时，应转入真实模型比较或重建经审查的录制版本。

## 7. L：提案、可信执行与门禁

### 7.1 保持当前源码边界

Chagent 正常工作区不能包含自身源码；不为“自我迭代”关闭保护。授权导出进程提供与问题有关、已脱敏的源码快照和证据到专用工作区，Agent 只在该区生成 `proposals/*.patch`、假设、复现命令和预期变化。

可信评测进程在独立 checkout 应用补丁，校验基线与允许路径；grader、保留集、凭据和权威结果存储不挂为候选可写目录。单独测试 schema 只能隔离数据，不能替代文件、进程与凭据隔离；候选获得的数据库角色也不能修改判据或权威结果。测试进程自报通过只是一个输入，外部可信检查核对环境和交付物事实。

提案生成者不能自行更新判据、跳过测试、放宽预算或发布新版本。开发用例和保留用例分别维护，保留集由可信评测进程访问，模型不直接获得全部输入/期望。保留集更新要版本化并保留旧结果，不能覆盖旧标准制造“提升”。

### 7.2 门禁与结论

保留原“三绿”分组，但每组必须展开到具体条件：

| 门禁 | 绿色条件 | 非绿色处理 |
|---|---|---|
| G1 任务与稳定性 | 固定用例的任务判据和正文检查满足预登记阈值，基线/候选在相同条件下比较 | 报告成功次数/总数、翻转、区间；证据不足为 inconclusive，不自动通过 |
| G2 权限与预算 | 适用的越权/拒绝/unknown 等约束零违反；用量、费用、时间及人工介入满足预登记上限 | 约束违反直接阻止合并；成本未知或基础设施不完备不能伪装成绿色 |
| G3 基础回归 | 当次单测、适用的纯逻辑/夹具回放通过，预登记必要检查无未解释跳过 | 不适用项明确列理由；必要检查失败、跳过或 infra_error 时阻止自动合并 |

阈值、允许容差、预算、重复次数和人工裁决规则在运行前固定，不能候选失败后调整。每轮有整体成本帽，包含评审、重试和后台调用；触顶停止并保留不完整结果。比较以任务有效性为前提，不接受“拒绝做更多任务”换取低时延或少审批。

每个提案保存：问题证据、基线 SHA、补丁哈希、case/grader/环境 manifest、复现步骤、基线/候选结果、全部翻转及取舍、门禁结果与人工决定。绿灯是合并必要条件，首版仍需人审并由授权发布流程合并；不自动推送或重启用户主控。回退保留数据库事实，不承诺撤销已发生的外部副作用。

P0 的两处实现偏离了上表的最初设想，理由写在这里而不是留给读者猜：**case 加载放在 `casefile.py` 而不是 `cases.py`**，因为 `cases/` 是数据目录，同名模块会让导入解析依赖谁先被找到；**trial 记录单独成 `records.py`**，因为它同时承载聚合规则与存储，按方案原来的文件划分没有归处。评测结果在 P0 是**文件**（每 trial 一个 JSON 加追加式 `index.jsonl`）而不是独立库：判据只需要"来源与版本可定位"，而建一套评测迁移、角色与清理逻辑会在第一次对照之前就欠下维护债；等真正需要跨会话统计时再迁，`TrialStore` 是唯一写入口，换存储不动调用方。

P1 有三处对 4.1 的收窄，都是"没有证据就不制造 span"的直接结果，改的是承诺而不是数据：

- **不产出 site span。** 4.1 的 kind 列表含 `site`，但站点服务的存活期没有按 run 的记录，跨 run 的进程状态也查不到起点；把它画成 span 只能靠推测。站点活动目前只以 `tool` span 出现。要做真正的 site span，先得有服务句柄的起止记录。
- **run span 不参与占用。** 它等于观察窗口本身；计入并集会令 `union == wall`、未解释时间恒为零。4.2 的"未解释时间"要求占用由子 span 计算，这一条现在写进了实现而不是留作注释。
- **压缩按已有证据区分精度**：生命周期事件给出近似事务时间边界（`transaction_time`），包括 completed/discarded/failed/cancelled；只有开始事件则保留开放区间。无生命周期事件、仅调用记录时只报已测 `duration_ms`（`duration_only`，边界为 `null`）。fresh window 与丢弃投机工作即使没有调用行也必须投影。`compaction_calls` 的行是事后插入的，不能用其插入时间反推执行区间。

当前 P1 不增加 `tool_calls.started_at` 迁移：`tool_started` 可提供近似执行起点，但 `created_at` 取事务开始时间，无法替代真实执行或提交时刻；100ms 刷写目标不是误差上界。历史事件关联不明确时起点仍为 null，新工具事件增加 `tool_record_id` 保证关联。若后续需要更准确的时延归因，应另行设计实际执行起止与单调时钟埋点。

P2 有四处对第 5 节的收窄，都是“宁可少说”的选择：

- **不解析自由文本错误消息。** 表里 F4 的"能直接观察的事实"是 schema/类型校验失败，但现库里只有 `PatchError: hunk 1 does not match…` 这类文本，没有结构化校验码。用正则把它读成 F4 会得到未校准的精确外观，因此 F4 只按"失败→同名工具换输入→成功"的结构判定，确定度为 `suspected`，`missing_evidence` 要求结构化校验码。
- **`confirmed` 没有阈值，只有证据。** 规则不产出 `confirmed`，也不存在"置信度 ≥ x 即根因"的规则；升到 `confirmed` 必须有一条 `root_cause` 人工复核记录，且该记录必须给出 `table:record` 证据。确认门取每位评审最新判定，有分歧时不升级；引用还必须属于当前运行并关联对应 finding。没有有效证据的确认会被拒绝并写进 `escalation.rejected`，而不是被静默忽略。
- **线索与标签分开存放。** 压缩发生是事实，信息丢失是结论。前者进 `clues`，后者进 `not_evaluable`。`checked`（规则跑了、条件不成立）与 `not_evaluable`（规则跑不了）分开，避免"没看"读成"看了没问题"。
- **人工标注独立成 `annotations.py` + `annotations/` 台账。** 方案原目录把"诊断线索、人工复核结果"都放在 `attribute.py`；实现时读写分离：`attribute.py` 只读数据库与只读台账，写入走 `annotate` 且分区规则在写入口执行。放在同一个模块里，很容易出现"分析代码顺手改标注"。

P3 有四处对第 6 节的收窄，改的同样是承诺而不是数据：

- **没有整轮重放。** 三层各自回答一个问题，不串成“重跑这次运行”。没有运行器时，把 cassette、状态夹具与规划拼成整轮只会得到看起来像回放的输出；第 6.3 节要求的调用序列匹配与流中错误样本，由 cassette 单独验证。
- **`replay="safe"` 不是回放资格。** 该声明回答“能否再问一次”，`web_fetch` 也声明了它；资格由副作用决定，外部调用一律拒绝，规划不执行任何调用。
- **不重映射绝对路径。** 记录里的绝对根改写成夹具根等于改参数，因此这类调用被拒绝并计数，而不是“修好”后重放。
- **cassette 不能播种新运行。** 它只重放录制时的转录；由脱敏后的响应重建历史会在第二次请求偏离，这是设计而非缺陷。纯逻辑层同样只证明确定性契约没有漂移，不证明工具语义正确。

其余三处（只接受目录夹具、归一化只有 `uuid`/`timestamp`、清理未验证即失败）与逐项理由见[验收第 49 节](验收记录汇总.md#49-回放三层与回放可行性p32026-11-13)。

P4 有四处对第 3 节与第 6.1 节的收窄，改的都是承诺：

- **语义判据不执行。** 3.1 节说“人工与经过人工样本校准的模型判定用于语义质量补充”，但校准样本目前是 0（P2 只建了台账）。因此 `model_rubric` 与 `human_review` 一律报 inconclusive，没有 `spec` 的判据同样报 inconclusive——**不从散文里猜判据**。要打开这条路，先得有一批经两人复核的标注，再谈阈值。
- **首批 12–16 份用例只落地 4 份可执行。** 6.1 节表格中的建站、运行诊断、文档综合、变更审查、交接与多轮约束仍只有声明级用例；本轮新增的是四份**宿主边界**用例（修复与测试、拒绝越界、覆盖需审批、技能交接），因为本机真实执行轴是 `boundary=host, execution=full, 无命令面`。P1 的五份 `boundary=container` 用例保留在库里作为契约声明，**不因不可执行而删除，也不改写声明去将就本机**——改写等于让用例迁就环境，之后没人知道它原本要求什么。
- **没有做“先小批预试验估计波动”。** 3.2 节要求先估计波动再固定重复次数，本轮直接以 3 次重复跑正式对照：预试验本身也要付费，而 3 次是能算出区间的最小值。代价是重复次数的选择没有实验依据，这一点写进报告限制，不假装是校准过的。
- **一次实验不叫稳定，也不叫等价。** `min_repeats_for_stability` 是下限；两臂各 3/3 得到的差值区间是 `[-0.56,+0.56]`，它说的是“这个样本量没分开两臂”，不是“两臂一样”。报告用 `no_difference_observed` 而不是 `no_difference`，就是为了不让读者把“没测出差异”读成“没有差异”。

判分时机也定在这里：**工作区清理之前**判分。trial 只保存哈希、证据与用量，不复制工作区；反过来先清理再判分，内容类判据会一律读不到文件而报 fail——这会把“没看”变成“失败”，比不判更糟。

评测库/独立 schema 保存结果，业务源只读；回放使用另一个可弃置库和低权限角色，不能触碰业务数据或权威结果。先通过最小夹具验证有效性，再扩展规模，不提前建设分布式调度或完整观测平台。

## 9. 首版不承诺的能力

- 不声称全面自动评估回答质量；语义判据需要校准与人工复核。
- 不以一次对照宣称候选更好或两臂等价：3 次重复的差值区间包含 0 时，结论只是“这个样本量没分开”，报告用 `no_difference_observed`。
- 不声称 cassette 测出了新模型能力，也不声称任意历史工具调用可重放。
- 浏览器视觉/交互与跨主控重启的真实进程恢复，仍需独立整链验收；当前 case 中标为未覆盖。
- 不做跨模型总排行榜、无人审查的源码改写/合并/发布、自动放宽权限或预算。
- 不以容器、路径投影或文本过滤承诺绝对隔离/绝对防泄漏；数据导出和候选执行分别控制边界。
