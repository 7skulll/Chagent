# 最小链路

以下说明固定响应模型的验证链路，使用 `python -m chagent --demo` 运行。默认入口已接入[真实模型配置](模型配置.md)，共用相同的 Runner、工具、上下文和存储。

## 已完成的流程

```text
命令行输入
  → ConversationRepository 创建或加载会话
  → RunRepository 原子创建运行、用户消息与开始事件
  → BasicContextBuilder 组装系统指令、工具声明和历史
  → 保存模型请求与上下文快照
  → FakeModelClient 生成 Echo 工具调用
  → 保存工具调用意图
  → ToolExecutor 校验参数并执行 EchoTool
  → 原子保存工具结果、结果消息与完成事件
  → 下一次模型请求读取工具结果并生成最终回答
  → 保存回答、运行终态和结束事件
```

FakeModelClient 根据当前请求末尾的消息决定返回调用或最终回答，不以实例计数维护对话阶段，因此可以跨进程继续同一会话。最终回答来自工具的实际返回内容。

## 主要实现

| 文件 | 职责 |
|---|---|
| `agent/runner.py` | 模型/工具循环、流协议检查、轮数限制、超时和取消 |
| `context/builder.py` | 预算选择完整轮次，保留任务状态并返回请求与选择快照 |
| `models/fake.py` | 固定响应模型，无需外部 API |
| `tools/registry.py` | 显式工具注册与模型声明 |
| `tools/executor.py` | JSON Schema 参数校验、超时与错误结果 |
| `tools/echo.py` | 无副作用的验证工具 |
| `storage/repositories.py` | 会话、消息、模型/工具调用和事件持久化 |
| `domain/codec.py` | JSONB 与有类型消息之间的转换 |
| `bootstrap.py` | 组装依赖，不在类中创建隐式全局服务 |

路径均相对于 `src/chagent/`。模型客户端、工具和上下文构建器通过依赖替换，不需要修改循环流程。

## 持久化内容

- 原始用户、助手与工具结果消息。
- 每次模型请求的完整内容、工具声明、模型配置、响应和状态。
- 上下文构建策略、选入/排除消息及理由、任务状态版本和 token 预算；估算方式与供应商实际用量分别记录。
- 每次工具的参数、实际结果、状态与执行时间。
- 有序运行事件；状态变更与对应关键事件在同一事务内提交。

通过 `ConversationRepository.messages(session_id)` 重新加载有类型的消息，通过 `RunRepository.get` 和 `events` 查看运行与事件。`events(after=sequence)` 支持读取某个序号之后的事件。

## 失败和取消

- 未知工具或无效参数变成错误工具结果，交给模型决定后续回答。
- 未完成或不符合协议的模型流使运行失败，不能执行部分工具参数。
- 模型输出达到长度上限时，不执行其中的工具调用。
- 同会话的第二个活动运行被数据库约束拒绝，拒绝时不保存第二条用户消息。
- 使用活动 Runner 的 `cancel(run_id)` 请求取消。已开始但未保存结果的工具标为 `unknown`，不承诺撤销副作用。
- 异常和取消会保存运行终态。存储本身故障或进程强制退出仍可能留下 `running` 记录；当前不自动重放或接管这些运行。
- 检查历史时可读取全部消息；构建模型上下文时仅包含已完成运行和当前运行，避免失败批次遗留孤立工具调用。

## 当前边界

当前已具备真实模型适配、基础会话管理、显式任务状态、上下文预算选择、[自动历史压缩](上下文压缩设计.md)、[本地网页对话](网页对话设计.md)和[长期记忆](长期记忆设计.md)，尚未实现进程崩溃后运行接管或通用权限策略。压缩失败时回退到既有摘要与近期轮次选择，早期普通历史仍可能被排除；应显式登记需要持续保留的任务约束。详情见[会话与上下文设计](会话与上下文设计.md)。

工具执行器现已注册 Echo 和基础文件工具，并在明确启用时注册单次宿主命令工具。文件工具具备工作区边界；宿主命令不具备进程沙箱，详情见[基础工具设计](基础工具设计.md)。

参数校验采用 [jsonschema 官方校验接口](https://python-jsonschema.readthedocs.io/en/latest/validate/)，没有自行实现部分 JSON Schema 语义。
