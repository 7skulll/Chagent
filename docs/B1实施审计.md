# B1 实施与审计

状态：B1 已实施完毕——运行所有权与失联收敛、后台记忆任务领取令牌均已完成并通过隔离 schema 验收。

## 审计前提

当前运行状态的写入分布在 Runner、RunRepository、ToolScheduler、ContextManager、SummaryRepository 与 MemoryService。后台记忆任务也会在运行终态后追加事件，因此不能简单地在所有事件写入处要求运行仍为 running，否则会破坏记忆处理。

必须覆盖的主运行写入包括：模型开始与响应、文本事件、工具排队／开始／结果、摘要检查点、运行终态及终态事务中的显式记忆和记忆入队。审批尚未实现，因此没有为它提前改变状态集。后台记忆任务使用独立的领取令牌（见下节），不复用运行所有权。

锁顺序统一为：先锁运行行并校验所有权，再做其他受保护写入。锁顺序覆盖恢复扫描、运行终结、工具调用和摘要保存；单纯在 `RunRepository._event` 中补一次 owner 校验不足以保护先于事件执行的数据库写入，因此 `check_owner()` 位于各事务的写入之前，而不是只在事件方法里。

存量运行没有 owner 与租约，迁移将其视为历史遗留：不根据新进程启动时间判断其他进程是否存活，也不会自动终止它们。部署时不得同时运行不执行所有权校验的旧版本。

## 运行所有权实施切片

已增加 `0010_run_ownership`：新运行分配独立令牌和 30 秒租约，运行期间每 5 秒续租。主运行事件、模型与工具写入、终态和摘要事务在同一事务中锁定并校验有效所有权；后台记忆事件使用独立审计入口。续租失败时停止本地运行，不写入成功或取消终态。事务校验不能保证数据库与文件系统副作用原子化。

运行因异常结束时的收尾统一走 `AgentRunner._close_if_running`：先读当前状态，非 running 即不动；`finish` 再次校验所有权，失败时转成 `RunFailedError(storage_error)`。这里必须转换——`finish` 在 `except` 块内抛出，不会被同级的 `except RunOwnershipLost` 接住，否则会以未分类异常逃出 `run()`，且数据库行与返回结果不一致。放弃收尾的运行保持 `running`，由恢复扫描收敛为 `interrupted`，不会谎称 `cancelled`。

迁移保留历史活动运行的空所有权，扫描器不会终止它们；升级时需要停机人工收敛。

## 失联收敛实施切片

网页服务启动后每 5 秒扫描，新运行启动前也扫描；每批使用 `FOR UPDATE SKIP LOCKED` 锁定已过期且有令牌的运行。运行终态、进行中工具的 `unknown`、排队工具的 `cancelled`、未结束模型／压缩调用和终态事件在同一事务中写入，提交后通知订阅者。已完成的工具记录保持原样；`unknown` 不说明外部副作用是否发生，也不会自动重放。

迁移前遗留的无令牌运行不会被扫描器自动终止，因为无法据此证明旧进程已失联；升级前应停止旧版本并单独处理遗留活动记录。

## 后台记忆任务所有权实施切片

已增加 `0011_memory_job_claims`：`memory_jobs.claim_token`，以及 `status = 'running'` 时必须同时具备租约与令牌的约束（`NOT VALID`，迁移时正在运行的旧 job 保留原租约并照常回收，之后的写入一律受检）。

- `claim()` 在领取事务内生成令牌并返回，令牌只存在于进程内，不从行里反推。
- `complete()`、`fail()`、`requeue()` 都要求 `id + status='running' + claim_token` 同时匹配，否则抛 `MemoryJobClaimLost`。这里不能只做"尽力更新"：候选与 job 终态在同一事务里提交，`complete` 抛错才能让候选一起回滚，避免旧尝试留下重复候选。
- worker 捕获 `MemoryJobClaimLost` 后静默返回，既不改 job，也不发 `memory_job_failed`——此时 job 属于新尝试，报告失败会把一个活着的 job 记成失败。
- `reap_expired()` 回收租约时清空令牌，新的领取者拿到新令牌；代理尝试持有的旧令牌从此无法写入。
- 租约过期仍然计一次尝试（语义不变：主动取消不计数，租约过期一定计数）。

残余行为：被回收的旧尝试可能已经花掉一次模型调用，`memory_extractions` 审计行会由新尝试以 `ON CONFLICT (run_id)` 覆盖。这只浪费一次调用，不影响候选与终态的原子性。

## 验收

隔离 PostgreSQL schema 中完整 183 项测试通过，其中 B1 相关用例：

| 用例 | 覆盖 |
|---|---|
| 令牌与过期租约拒绝写入、拒绝续租 | 非所有者与过期租约都不能写事件、不能续租、不能终结 |
| 过期运行收敛 | 运行 `interrupted/owner_lost`，工具 `unknown`／`cancelled`，模型与压缩调用 `interrupted`，事件完整 |
| 强杀后由另一进程收敛 | 真实子进程强杀，另一进程批量收敛 |
| 健康租约与锁竞争不误收 | 未过期、被其他事务锁住时扫描返回空 |
| 取消时所有权丢失 | 返回 `RunFailedError(storage_error)`，运行保持 `running` 交由扫描器收敛，不谎称 `cancelled` |
| 旧领取者不能提交 | 三种写入全部被拒，job 仍归属新令牌并可由其正常完成 |
| 失效领取回滚候选 | 同一事务内写入的候选项随 `complete` 失败一起回滚 |
| 慢 worker 让位 | 租约被回收后旧尝试不写终态、不发失败事件 |

未证明的部分：所有外部工具副作用都能停止（`unknown` 只是记录，不代表撤销）；数据库与文件系统副作用无法原子化。
