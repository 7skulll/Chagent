# 设计总览

Chagent 是运行在本机的单用户 Agent：在本地网页输入（命令行仍保留一次性运行），模型在 Python 进程内以「模型 → 工具 → 模型」循环推进任务，消息、请求、工具调用与事件都落在同一台机器的 PostgreSQL 里。没有账号体系、没有分布式任务队列；有平台级命令沙箱（macOS seatbelt，只在 `code` 模式参与），没有容器。

## 两种模式

能力按会话分成两层，契约见[执行边界设计](执行边界设计.md) §14.2：

| | `work`（默认） | `code`（未启用） |
|---|---|---|
| 定位 | 只读对话：问答、读文档、看代码、查资料 | 在 work 之上改写工作区、执行命令 |
| 工具面 | `read_file` `list_dir` `glob` `grep` `read_artifact`，以及开启时的 `web_*` | work + 写文件／编辑／补丁 + `exec_command` `process` `run_tests` |
| 约束依赖 | 无审批、无沙箱、无进程管理（不存在，不是关掉） | 沙箱、审批、进程管理全部参与 |

两条规则：

- **工具没注册才是约束。** 模式在 `create_builtin_registry(mode=...)` 裁剪，`ToolExecutor` 按本次运行允许集合再校验一次；前端隐藏按钮不算约束。
- **`code` 由构建级开关兜住。** `CHAGENT_CODE_MODE=off` 时任何会话都不能选 `code`，`POST /api/runs` 返回 409 而不是静默降级；六条启用门槛见[执行边界设计](执行边界设计.md) §14.4。模式随会话存储（`sessions.mode`），run 继承、不可按 run 切换。

当前正在交付的是 work 模式（WK0–WK4，见[路线图](下一阶段实施方案.md) §9）：**WK0 已交付**，`code` 的 C1–C4 排在门槛满足之后。

当前能力（截至 WK0；模式已经落地，`work` 是本构建唯一的一层，它不注册任何写文件或宿主命令工具）：

- **work 面**：真实供应商与离线演示两条等价链路、文件检索、PDF／Word／Excel 直接读取与网页上传、联网检索与正文抓取（`web_search` + `web_fetch`，默认关闭、只读、无 JS）、会话与显式任务状态、运行级环境快照、上下文预算与自动摘要、大工具输出产物化、用户／工作区长期记忆（`/remember` 由本地命令直接回答）、可切换工作区的本地网页与 SSE 回放。
- **code 面**：一次调用多处编辑与多文件补丁、宿主机命令与测试运行（含跨调用存活的长命令会话：分次读、写 stdin、杀进程组）。这部分能力已达到可用，但未达到「敢默认开」，因此停在 `code` 模式后面。

## 网页视觉系统

前端仍是一个静态页加一个样式表，没有构建步骤；改样式只动 `src/chagent/web/static/style.css`，结构、id 与事件绑定保持原样（`tests/test_web_ui.py` 仍按按钮与 id 断言）。

- **单一来源**：颜色、字体、字号、间距、圆角、阴影、动效时长全部声明在 `:root`，token 块之外不出现字面色值或 `font-family`。颜色用 OKLCH（中性色带 0.002–0.008 色度，白底不是纯白），字阶固定 11／12.5／14／16／19／22px（相邻步进 1.12–1.19 倍），间距走 4px 网格。
- **控件尺寸**：图标按钮 34px，主按钮（发送）40px，两档相差 6px；对话框里的输入框、下拉与次按钮统一 34px；触屏指针下放大到 40／44px 命中区。
- **布局**：60px 图标栏、260px 会话栏、弹性聊天区（正文测量宽 46rem）、300px 上下文面板；`<1180px` 收起上下文面板并隐藏它的开关，`<960px` 会话栏变抽屉＋遮罩，默认收起、点遮罩或 Esc 关闭、打开会话后自动收起，宽度变化不改写桌面端记住的折叠状态。
- **状态**：每个可交互元素有 `:focus-visible`（2px 描边，不延迟）、`:active`、`:disabled`（三通道：底色、字色、`cursor`）；所有过渡在 `prefers-reduced-motion` 下降为瞬时；`html` 与 `body` 都是 `overflow-x: clip`。
- **空态与错误**：会话为空、记忆为空、用量为空、接口失败各有独立文案与样式；列表加载骨架尚未实现，是已知缺口（本机数据库响应在毫秒级，尚未暴露问题）。
- **回答正文（WK1）**：Markdown 子集由独立的 `static/markdown.js` 渲染，先整体转义再识别结构，输出只可能是固定 15 种标签，链接只有 `http(s)`。代码块 420px 内纵向滚动、横向不换行；表格在自己的容器里横向滚动，从不把转录区推歪；超过 2 000 字折叠为 8 行，展开控件在裁剪盒外。
- **来源卡片（WK3）**：搜索来源给标题、域名、三行摘要与外部链接；文档引用给 `path · 第 N 页`；注入的记忆给键、版本与正文。整块默认折叠，没有来源时不渲染——空卡片比没有卡片更差。
- **上传队列（WK4）**：一行一个文件，34px 缩略图或扩展名块，进度用 `<progress>` 而不是内联样式（CSP 的 `style-src` 是 `'self'`），缩略图用 `data:` URL（`img-src` 只额外放行 `data:`）。

## 模块地图

| 目录 | 职责 |
|---|---|
| `agent/` | `AgentRunner` 模型／工具循环、结束决策、取消、运行级状态 `RunState` |
| `context/` | 预算选择（`builder`）、投影缓存（`projection`）、摘要压缩（`manager`／`compactor`）、会话分段（`segments`）、计数器（`tokens`）、运行级环境快照（`environment`） |
| `memory/` | 检索与注入、显式记忆、候选提取（`service`），后台提取 worker，管理 CLI |
| `models/` | 模型协议与适配器：OpenAI 兼容、Anthropic、固定响应 |
| `tools/` | 工具声明与执行、按会话模式裁剪的两层工具面（`builtin`）、批次调度（`scheduler`）、文件与命令实现、多段编辑匹配（`edit_diff`）、检索（`search`）、补丁（`patch`）、测试运行（`tests_runner`）、会话进程（`processes`：按 run 归属、有界输出窗口、游标读、run 结束回收）、出网（`web`：DeepSeek Search／Fetch 两个工具、按次计费、状态码映射）、沙箱（`sandbox`：seatbelt 策略与探测）、工作区边界 |
| `documents/` | 二进制文档解析：PDF（pypdf，剥页码与重复页眉页脚）、Word（python-docx，标题成段路径、表格转「表头: 值」）、Excel（openpyxl，每表一块、每行带表头）；`Block(text, page, section)` 统一形态，按内容哈希的进程内 LRU 缓存 |
| `storage/` | 连接与迁移、各仓储、产物与记忆任务队列；无 ORM |
| `sessions/`、`web/`、`cli.py`、`__main__.py` | 入口：会话管理与命令行、网页服务（唯一默认入口）、一次性运行（冻结，仅 `--tool` 注入探针）；`web/static/` 是无构建步骤的前端，`markdown.js` 是可单独在 node 里测试的 Markdown 子集渲染器 |
| `domain/` | 消息、运行、上下文、记忆、摘要等纯数据与校验 |
| `bootstrap.py` | 显式组装依赖，不在模块内建隐式全局 |

依赖方向单向：`domain` 不依赖其他模块，`tools`／`storage` 不依赖 `web`，网页层只做参数校验与事件投递。

## 一次运行的完整链路

```text
输入（CLI / POST /api/sessions/{id}/runs）
  → 建运行、写用户消息、run_started（同事务）
  → 加载会话、可回放历史、任务状态、最新摘要 → RunState
  → 读取最近一次正常结束之后失败运行的可恢复事实 → 宿主注记（非消息）
  → ContextManager.prepare
       → BasicContextBuilder：按消息投影 + 累计成本选择完整轮次
       → 达到阈值时 ContextCompactor 生成摘要检查点
  → MemoryService.enrich：按预算注入已生效记忆（同一 run 内复用检索结果）
  → 保存模型请求与上下文快照
  → ModelClient.stream → 保存回答 → 追加到 RunState
  → 有工具调用时 ToolScheduler 分批执行，按调用序提交结果与事件
       （带 yield_time_ms 的命令把子进程交给 ProcessManager，句柄在本 run 内有效）
  → 循环，直到无工具调用、整批要求停止，或达到轮数／时间／预算上限
  → 先 terminate_run 回收该 run 仍持有的会话进程，再 runs.finish（同事务）：终态与 end_reason、事件、显式 /remember 写入、自动提取入队
  → MemoryWorker 在运行之外领取 job，独立超时调用模型，候选与 job 终态同事务提交
```

关键不变量：

- 状态变更与对应事件同事务提交；事件序号在单个运行内连续。
- 运行终态由 `RunStatus` 与 `RunEndReason` 共同表达，返回值、数据库行、终态事件三处一致。
- 用户等待的只有模型与工具；记忆提取、摘要续写都在此之外。
- 原始消息只追加：裁剪、压缩、删除记忆都不改写历史。重新生成与编辑重发同样只追加——旧记录写 `superseded_by` 退休（从被替换的那条起往后整个后缀），回放过滤、阅读不过滤。

## 持久化内容

| 表 | 存放 |
|---|---|
| `workspaces`、`sessions`、`task_states` | 工作区、会话、带 revision 的显式任务状态 |
| `messages` | 原始消息（JSONB，有类型内容块）；`superseded_by` 指向替换它的 run，被替换的记录继续可读、不再回放 |
| `runs`、`run_events` | 运行终态与有序事件 |
| `model_calls`、`tool_calls` | 每次请求的完整内容与上下文快照、每次工具调用的参数与结果 |
| `session_summaries`、`compaction_calls` | 版本化摘要检查点与摘要调用审计 |
| `tool_artifacts` | 超大工具输出正文 |
| `memories`、`memory_revisions`、`memory_extractions` | 记忆、版本审计、提取调用审计 |
| `memory_jobs` | 待提取任务的持久化队列 |
| `approval_requests` | 宿主命令审批：待决／已决状态、参数指纹、单次消费标记、过期时间 |

## 失败与取消

- 未知工具、参数错误、工具执行失败变成错误结果交回模型，不终止运行。
- 流协议错误、供应商错误、输出截断使运行失败，且不执行未完成的工具调用。
- 用户取消时，已开始但无结果的工具标为 `unknown`，不承诺撤销副作用。
- 进程被强杀时租约到期，另一进程的扫描把运行收敛为 `interrupted`、进行中的工具置 `unknown`；迁移前遗留的无令牌运行不自动接管。取消时若所有权已丢失，运行保持 `running` 交给扫描器，不写入 `cancelled`。
- 记忆提取失败只影响 job，运行终态不变；job 带领取令牌，租约被回收的旧 worker 不能覆盖新尝试。
- 失败运行的原始消息不回放，但已提交的副作用以宿主生成的注记进入下一次上下文：确认的写入标为 committed，未确认的标为 unknown 且不宣称成功。注记计入上下文预算，不构成授权。

逐条原因与状态对应关系见[运行与工具调度](运行与工具调度.md)。

## 尚未实现与已决定不做

- 执行边界：工作区路径检查、平台命令沙箱、运行中审批与持久 shell 均已交付。S 批（`CHAGENT_SANDBOX=workspace-write`，写不出工作区与私有临时目录、连不上网、读不到密钥目录；不是容器，读保护是黑名单）；K 批（`CHAGENT_APPROVAL=never|on-request|untrusted`，allowlist 不解析 shell，授权单次消费，等待不占执行资源）；J 批（`exec_command(yield_time_ms)` + `process`：命令跨调用存活、按游标分次读、写 stdin、杀进程组；句柄不跨进程也不跨 run，没有 PTY，run 结束一律终止）；W 批（`web_search` + `web_fetch`；跑在 agent 进程里，因此沙箱不覆盖它，开关默认关；不执行 JS、不登录）；**WD 批**把这两个工具换成 DeepSeek 的 Search／Fetch API（`CHAGENT_WEB_ACCESS=deepseek`，`tavily` 已移除并拒绝启动）：搜索返回 `snippet`／`summary`／`date`／`authority`／`rerank_score`，抓取返回 Markdown，私有地址由供应商拒绝（实测 403），本机不再连接目标。见[执行边界设计](执行边界设计.md)。
- 迁移前遗留的无令牌活动运行需要停机后人工收敛，扫描器不会自动终止它们。
- 跨进程即时通知与浏览器绘制级延迟分布：当前文本已合并，同进程提交后通知，其他进程依靠兜底查询。
- 会话进程之后仍缺的部分：没有 PTY（`top`／`vim` 之类不可用）、没有跨进程接管（重启即失效）、没有把超窗输出落盘归档。文件工具已在线程中执行，命令与测试走异步子进程。
- 联网之后仍缺的部分：没有登录态（cookie／表单）、没有浏览器（不执行 JS、不渲染、不截图）、图片不可读。PDF／Word／Excel 已由 X 批解决（只提文本，扫描件与旧格式 `.doc`／`.xls` 明确报错），所以「设计一个网站并确认它长什么样」仍然做不到——读文档可以了，看得见不行。
- 网页之后仍缺的部分：Z0（`echo` 退出工具面、轮内重试、沙箱探针改 canary）已交付；Z1（删除 24 个假按钮并由静态断言守住）已交付；Z2–Z5（会话重命名／归档／标题搜索、用量面板、审批在场语义、后台运行可见）随 `82c6a51` 一起提交。
- work 模式的 WK1–WK4 已交付（见[路线图](下一阶段实施方案.md) §9）：回答按 Markdown 子集渲染、流式按帧节流、滚动跟随、超长折叠与复制；重新生成、编辑重发与失败重试，被替换的记录折叠可展开而历史不被改写；搜索卡片、文档页码与注入记忆的「依据」；拖拽／粘贴／点选共用的上传队列。四批都没有新增工具，也没有改动模型可见的任何字节。
- work 模式之后仍缺的部分：正文里没有 `[1][2]` 自动标注（先给来源列表）；没有消息树与分支切换（替换是后缀退休，不是树）；图片只存不解析（`read_file` 没有 OCR）；超长回答的折叠是「八行 + 展开」，没有分段目录或按段落跳转；页面没有列表加载骨架。
- `code` 模式面已可用但未开放（WK0 后）：`sessions.mode` 与 `CHAGENT_CODE_MODE` 已接入、工具注册按模式裁剪、任一 run 在开始时固定面；仍未实施的是 `(deny default)` 沙箱与项目级授权。启用门槛与批次见[执行边界设计](执行边界设计.md) §14.4–§14.5。
- 写入路径已收两步：文本增量每 100ms 一批提交，所有权校验收敛为每事务一次。1.6 秒流式回答从 260 条 SQL、81 个事务降到 59 条、21 个；两轮加一次工具从 57 条降到 46 条。剩下的 `model_calls.request` 每轮仍存整份消息数组（F3 的设想），但路线图已判定继续压这条路径省不出一次首字延迟，保留为记录而非待办。
- 评测集：只有诊断脚本与真实链路脚本，没有可比较的回归评分体系。
