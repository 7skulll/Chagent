# 统一可编程执行契约

更新：2026-11-04。网页生产入口只有一套工具面。新会话与旧 `work`、`code` 会话都可使用文件读写、`exec_command`、`run_tests` 和 `process` 的 read/stop。`sessions.mode` 只为读取旧数据保留；创建、修改和运行 API 不接受 `mode` 参数。

## 启动条件

生产网页要求 `CHAGENT_EXECUTION_PROFILE=trusted-development`、`CHAGENT_CODE_MODE=on`、`CHAGENT_ALLOW_HOST_COMMANDS=true`、`CHAGENT_SANDBOX=isolated`、`CHAGENT_SANDBOX_WRITABLE=true`、`CHAGENT_SANDBOX_NETWORK=false` 和 `CHAGENT_APPROVAL=never`。配置不符或隔离探针失败时拒绝启动，不退化成受限工具面。旧 `.env` 会按原值解析，不会自动覆盖；升级时需要显式调整。

`configured`、只读工作区、逐次命令审批与命令联网仍可由底层诊断代码表达，但不属于当前网页产品入口。`--demo` 是单独的无真实模型诊断入口。当前网页不支持 PTY、交互输入、EOF 或命令联网。

## 实际能力核对

启动时同时检查配置、Runner 的显式 `unified` 标记、两种旧会话值是否映射到同一 executor、文件与执行工具是否齐备、命令工具是否共用实际 isolated 沙箱、审批是否为 never，以及 `process` 是否仅允许 read/stop。`/api/info` 与 `/api/config` 的 `programmable` 字段表示生产统一工具面是否启用；`code_mode=false` 是保留给旧前端的“不可选择 code 标签”，不表示命令不可用。

命令隔离限制文件与网络访问；网页搜索工具和模型请求独立于命令沙箱。文件修改与命令副作用在取消时不自动回滚。
