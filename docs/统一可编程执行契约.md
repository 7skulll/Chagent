# 统一可编程执行契约

更新：2026-11-04。网页生产入口只有一套工具面。新会话与旧 `work`、`code` 会话都可使用文件读写、`exec_command`、`run_tests` 和 `process` 的 read/stop。`sessions.mode` 只为读取旧数据保留；创建、修改和运行 API 不接受 `mode` 参数。

## 三个轴

执行行为由三个互相独立的轴描述，全部由开关推导，不能直接设置：

| 轴 | 取值 | 回答 | 来源 |
|---|---|---|---|
| `boundary` | `container` / `none` | 进程跑在哪 | `CHAGENT_EXECUTION_PROFILE`（声明值必须与之一致） |
| `capability` | `full` / `read-only` | 有没有命令执行能力 | `CHAGENT_CODE_MODE` 与 `CHAGENT_ALLOW_HOST_COMMANDS` |
| `gate` | `none` / `approval` | 高危动作要不要人批 | `CHAGENT_APPROVAL` |

推导与校验只有一处：`src/chagent/execution.py` 的 `resolve()`。配置、网页门禁、CLI 与工具装配都读 `Settings.axes`，不再各自列举条件。

合法组合三个：

| 组合 | boundary | capability | gate | 用途 |
|---|---|---|---|---|
| A | `container` | `full` | `none` | 唯一可执行命令的形态；网页只接受这一个 |
| B | `container` | `read-only` | `none` | 只读会话 |
| C | `none` | `read-only` | `none` | 没装 Docker 的降级：读写文件、查资料，不能执行命令 |

第四个结构（`container` + `full` + `approval`）在代码里保留为 `RESERVED`：审批 broker 仍在，但没有入口接线，因此不向模型开放。除此之外的组合在启动时被拒绝，例如本机 `configured` 档加 `CHAGENT_ALLOW_HOST_COMMANDS=true` 会报「Host commands require the container boundary」。

B 与 C 没有网页入口——网页只接受 A。C 就是本机默认档：`configured` + 无宿主命令，能读写工作区文件、查资料，不能执行命令；本机 CLI 的真实模型运行也走这一档，装配时不用统一工具面，保留 work/code 两个都不含命令工具的旧面，因此不会因为缺少命令能力而启动失败。

## 启动条件

网页要求组合 A，并且实际位于容器内：`CHAGENT_EXECUTION_PROFILE=containerized`、`CHAGENT_BOUNDARY=container`、`CHAGENT_CONTAINER_DECLARED=true`、`CHAGENT_SANDBOX=off`、`CHAGENT_SANDBOX_NETWORK=true`、可写工作区、命令开启、`CHAGENT_APPROVAL=never`，启动同时检查容器标记。工作区必须位于 `CHAGENT_WORKSPACE_ROOT` 内。Compose 覆盖 `.env` 的执行档设置；模型密钥仍由 `.env` 提供。容器内命令可联网，子进程环境不继承模型密钥和数据库连接串。显式声明和标记检查用于防止普通宿主误启，不证明容器提供强隔离。

`configured` 在本机保留配置诊断，但不能执行命令，也不能启动生产网页。旧 `trusted-development`、`isolated`、`workspace-write` 配置与 `CHAGENT_DEFAULT_MODE` 会被拒绝。`--demo` 是单独的无真实模型诊断入口。当前网页不支持 PTY、交互输入或 EOF。

## 接口字段

`/api/info` 与 `/api/config` 都返回 `boundary`、`capability`、`gate` 三个值，与启动横幅 `Execution:` 行同源。`programmable` 表示生产统一工具面是否启用（等价于组合 A 成立），`boundary` 只报告位置，不再兼任能力标志。`code_mode=false` 是保留给旧前端的「不可选择 code 标签」；`default_mode`、`execution_profile` 与 `sandbox` 已从响应中移除，`CHAGENT_DEFAULT_MODE` 在启动时明确报错而不是被忽略。`/api/config` 仍返回 `sandbox_network` 与 `host_commands` 这两个原始开关，它们只是三轴的输入，不能当成独立能力：能力一律看 `capability`。

## 实际能力核对

启动时同时检查配置、Runner 的显式 `unified` 标记、两种旧会话值是否映射到同一 executor、文件与执行工具是否齐备、命令工具是否共用实际执行配置、审批是否为 never，以及 `process` 是否仅允许 read/stop。运行时的 `SandboxSettings.allows_execution` 是同一判定的运行侧一半，工具装配与网页门禁都用它，不另写条件串。

容器命令使用容器可见的文件系统和网络。网页搜索工具和模型请求独立于命令执行。`ToolGate` 在取得执行并发位之前处理可选门禁，异常按拒绝记录；当前生产网页无人工审批门禁。文件修改与命令副作用在取消时不自动回滚。容器路径的实际验收见[容器执行阶段验收](容器执行验收-2026-11-04.md)。
