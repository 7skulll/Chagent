# 真实链路测试与 Claude 参考设计

日期：2026-10-28（北京时间）。本轮完成真实供应商测试、参考源码核对和方案修订；没有实施主链路重构，也没有改动业务执行代码。

## 1. 测试结论

真实模型已验证文件工具、持久化历史、显式记忆保存、跨会话记忆注入、自动候选提取、审核后召回、模型摘要压缩和网页 API／SSE 回放。

不能据此给出“全部质量检查通过”的结论：显式 /remember 仍进入通用模型／工具循环。数据库保存成功的同时，模型可能声称无法保存，或额外创建 MEMORY.md。本轮用不含敏感信息的普通语言偏好再次复现，列为 P0。

现有回归测试 103 项全部通过；真实测试证明这些测试尚未覆盖命令的用户可见语义与不必要副作用。

## 2. 运行配置与边界

- 使用项目配置的 DeepSeek deepseek-v4-flash、OpenAI Chat 兼容协议。
- 测试每次模型请求输出上限 768，单请求超时 40 秒，单次运行超时 90 秒，最多 6 次任务模型循环；脚本另设整次调用上限。
- 主链路通过真实 create_runner、HTTP 模型客户端、工具执行器、PostgreSQL Repository、记忆和摘要模块运行，没有用固定模型响应替代。
- 数据使用随机 chagent_live_ schema，文件工作区使用临时目录；请求只含人工构造的样本，不向供应商发送本地参考源码、业务历史或 .env。
- 临时 schema、记忆、摘要、会话和测试文件均已清理。API Key 不进入报告；错误只保留脱敏后的适配器原因或异常类型。
- 网页测试采用 ASGITransport 调用真实接口，未经过浏览器或真实监听端口。该传输会缓冲 SSE，不能用于测量浏览器可见首字或连接中断行为。
- 每个场景主要是一轮样本，供应商缓存也已命中；以下时长不能当成生产中位数或 p95，不能用于声称比 Pi／Codex 快慢。

初次两次请求返回 401。检查变量来源发现：进程继承的 CHAGENT_API_KEY 优先于 .env 中的 DEEPSEEK_API_KEY。只在测试子进程中取消通用变量后，使用项目内的命名 Key 成功。没有修改 .env，也没有把 Key 输出到工具日志。

### 3.1 真实性与断言说明

随机 marker 只写在临时文件中，首次用户提示不提供；续聊必须从已保存的工具历史读取，因此不是仅凭提示猜测答案。

项目记忆在另一新会话召回，并检查 ContextSnapshot.memory_references，而不是只检查回答是否碰巧包含目标文本。

自动候选必须有正确内容和原文 evidence，且初始状态为 candidate。审核通过真实 MemoryRepository.change(accept) 完成；这仅验证了后端审核接口，不等于操作了网页审核弹窗。

压缩场景预置 4 轮人工构造、已完成的受控历史，并将应用预算设为 14,000 触发压缩。不是让真实模型产生全部历史，也不是声称供应商模型只有 14,000 上下文窗口。关键词断言只验证重要锚点保留，不足以证明整个摘要语义无损。

首轮 SSE 断言错误地在原始分片文本中寻找连续的 WEB_LIVE_OK；该字符串实际被分成多条 text_delta。已修正脚本为解析 SSE 并拼接 delta，然后仅重跑网页场景，结果通过。保留初次原始结果，不把测试脚本错误归因于产品。

## 4. 真实模型暴露的新问题

### R1：显式命令缺少独立执行路径（P0）

当前 /remember 在任务完成时由 MemoryService 解析，但原文首先被交给通用任务模型，且没有向模型解释宿主记忆能力。

首次项目事实样本：模型调用 list_dir、read_file、read_file，随后英文回答“没有专用记忆存储，无法直接保存”；同次运行完成时数据库却已经保存为 active。

为排除测试事实被当成敏感内容这一干扰，再发送普通偏好：

```text
/remember workspace project.response_language = 本项目默认使用简体中文回答
```

模型执行 list_dir 两次、read_file 两次、write_file 一次，创建 MEMORY.md，并把它描述为保存位置；数据库也同时保存了同键 active 记忆。

这里既有额外模型延迟，也有两个并行事实来源：PostgreSQL 记忆与模型创建的文件。以后编辑数据库不会同步该文件，可能产生长期矛盾。

修复方向：在进入 AgentLoop 前识别受支持的本地命令。程序完成校验、冲突处理、事务保存和事件记录，直接返回结构化的成功／候选待审核／冲突结果。显式 /remember 目标应是 0 次模型请求、0 次文件工具调用。失败必须明确失败，不依赖模型猜测宿主操作结果。

这是对原方案的优先级调整：命令路由应与自动记忆后台化一起进入首批，而不是先优化微小 CPU 成本。

### R2：模型的“我记住了”与候选状态不同步（P0）

自动提取样本的助手回答包含“我记住了这个称呼，今后会一直这样称呼您”，但实际只生成了 candidate，尚未审核。随后通过程序审核，才在下一新会话中生效。

一次样本不能证明模型总会如此，但足以说明当前链路允许这种不一致。应由程序在界面／API 中明确展示“候选待审核／已生效／保存失败”；模型不能替宿主系统承诺已持久生效。

不要为了迎合助手承诺而直接激活推断结果，现有审核和证据约束应保留。

### R3：辅助调用和调用次数比局部 CPU 更影响当前短任务

文件链路总计 3.071s，其中 3 次模型流约为 0.935s、1.169s、0.911s；3 次上下文准备累计约 11ms。当前这个小样本中，不应宣称只优化 Builder 就能大幅缩短总任务时间。

自动记忆样本中，任务模型约 0.583s，记忆模型约 1.049s，记忆准备阶段约 1.054s。辅助提取明显拖长运行结束，应脱离主任务完成路径。

压缩样本在任务模型前串行执行两次摘要，耗时约 1.422s 和 1.093s。应控制摘要调用次数、结合真实用量校准预算；不能直接并发这些增量摘要，因为后一份可能依赖前一份。

逐增量持久化也有真实代价：首轮显式记忆样本产生 289 个文本增量，增量阶段累计约 395ms，总 SQL execute 664 次。该样本本身又有不必要工具与长回答，所以应先消除多余任务，再优化事件提交。

### R4：配置检查应显示凭据来源

本轮首次 401 来自继承环境变量遮蔽项目命名 Key。建议 models check 增加 key_source 和“通用 Key 覆盖命名 Key”的提示，只显示变量名，不显示值、哈希或前后缀。保留明确的优先级，不自动尝试所有 Key，避免将凭据发送到错误服务。

## 5. 本地 Claude Code 参考实现审查

参考目录是相邻 codeagent/claude-code-main。其 README 名称为 Claude Code Best V5；AGENTS.md 明确自述反编译／复原工程，含桩实现和 feature gate。本报告只引用本地可检查的实现，不将它当成 Anthropic 官方开源源码，也没有安装或用真实 Key 运行这个参考项目。

| 已核对的设计 | 对应源码 | Chagent 应借鉴的部分 |
|---|---|---|
| 本地 slash command 先处理，再决定是否进入模型循环 | QueryEngine.ts 的 processUserInput 与本地命令结果分支 | /remember 返回确定的宿主执行结果 |
| 有序缓冲写入和显式 flush | utils/sessionStorage.ts、QueryEngine.ts | 划分增量预览与可靠提交，降低模型流等待 |
| 每次用户输入只启动一次记忆相关预取，未完成则不阻塞该轮 | query.ts、utils/attachments.ts 的 MemoryPrefetch | 消除同输入每轮重复检索；优先复用本地查询结果 |
| 自动提取有游标、重叠保护、待处理上下文合并、关闭时 drain | services/extractMemories/extractMemories.ts | 自动提取独立生命周期、避免重复工作和并发覆盖 |
| 根据解析后的参数判断并发安全；连续安全调用批次并行，修改上下文按确定顺序应用 | services/tools/toolOrchestration.ts、Tool.ts | 有界并发与修改操作的执行屏障 |
| 流式工具跟踪排队、执行、完成、已交付，取消时清理引用 | services/tools/StreamingToolExecutor.ts | 明确工具生命周期和取消后的结果归属 |
| 摘要连续失败熔断、预留下一轮增长空间 | services/compact/autoCompact.ts | 避免反复失败压缩和预算耗尽后才处理 |
| 记忆整理先检查时间，再扫描会话，再尝试锁 | services/autoDream/autoDream.ts | 把低成本判断放前面，避免每轮昂贵后台扫描 |

### 不照搬的部分

- sessionStorage 的队列到达阈值时会丢弃最旧条目。对 Chagent 的审计和恢复语义，不应丢弃关键操作记录；采用有界背压与明确失败。
- QueryEngine 的部分结束刷新受配置条件影响。Chagent 应明确 completed／游标对应的持久化保证，不能只复制 fire-and-forget。
- StreamingToolExecutor 允许工具块到达后开始执行。Chagent 现有“完整终结响应后才执行”的约束应保留，尤其不能提前执行写入／命令而忽略后续截断与流失败。
- 参考实现的记忆预取依赖 feature gate，提取使用额外 agent。Chagent 先用现有 PostgreSQL 检索与有界 worker，不为相同效果增加多层 agent。
- autoDream 的 PID／mtime 文件锁不能直接替代 PostgreSQL 租约或原子锁；本地文件写入后再读回 PID 不构成可泛化的强互斥保证。
- 注释中的生产统计没有独立验证，不据此推导 Chagent 的默认阈值。参考项目较大的模块和大量开关也不应照搬。

## 6. 修订后的实施优先级

1. P0：本地命令路由与程序确认；候选／生效状态准确展示；自动提取改为持久化后台任务。修复数据事实与用户认知的分叉。
2. P0：保留原方案的运行所有权、失联修复和失败副作用观察记录。真实接口跑通不代表崩溃恢复已解决。
3. P1：增量合并与可靠刷新；检索按输入／记忆版本复用；投影和计数增量化。每项使用离线基线与真实样本交叉验证。
4. P2：工具安全并发、进程会话、运行中输入和重试。默认保留简单调度，新增能力必须有明确状态与取消规则。

首个改动建议选择 /remember 确定性路径：验收 0 次供应商请求、0 次文件工具、数据库与 API 返回一致；同时检查重复内容、冲突、非法输入和数据库故障。这项改动可以单独提交和评审，不要求先完成整个运行时重构。
