# 前端重构方案

> 状态：**实施前方案**。本页描述问题、目标边界、改造顺序与验收判据，不代表当前行为。
> **实施进度（2026-11-05）**：阶段 0 已完成；阶段 1 已开始（`core/dom.js`、`core/api.js` 已抽出，`app.js` 改为 import，`index.html` 改由 `main.js` 作为模块入口）。实际做法、新暴露的三个问题与回归数字见[实施记录第 35 节](实施记录.md)，与下文原方案的差异以该节为准。
> 交付后按[文档维护规则](README.md#文档维护规则)把实际模块边界并入《网页与工作区设计》，把证据写入《验收记录汇总》，本页可删。
> 本方案只动 `src/chagent/web/static/` 与前端测试，不改后端接口、不改 SSE 事件名、不改 `execution.py` 任何三轴语义。

## 1. 结论

前端的问题不是"文件太大"，是**同一个界面有两条互不共享代码的渲染路径**，以及**两个脚本通过 `window` 全局互相调用形成环**。文件行数只是这两个结构性问题的结果。

推荐做法：零构建、原生 ES modules、单向分层、事件流收敛为纯函数 reducer。**不引入框架、不引入打包链、不引入 jsdom/Playwright。**

### 2.1 问题一：`app.js` 与 `file-editor.js` 双向依赖

- `app.js` 调 `window.ChagentFiles?.open(...)`、`?.refresh()`、`?.beforeWorkspace()`（如 `app.js:362-396`、`1318`）。
- `file-editor.js` 调 `window.ChagentWorkspaceSwitch`（`file-editor.js:74`）与 `window.ChagentShowFiles`。

两侧都用可选链 `?.`。**任何一侧改名或未加载，另一侧静默失效**：不抛错、不白屏，只是某个按钮从此没反应。这是当前最难排查的一类缺陷，且现有测试无法覆盖（stub 会补齐缺失的全局）。

### 2.2 问题二：两条渲染路径必须永久保持一致

| 路径 | 入口 | 做法 |
|---|---|---|
| 实时 | `connectRun`（`app.js:820-903`） | 一段约 80 行的 `if (type === ...)` 长链，逐事件直接改 DOM |
| 恢复 | `openSession`（`app.js:641`） | 拉全量消息，全量重建 DOM |

两条路径没有任何共享的渲染代码，却必须产出同样的界面。`liveText` / `liveBuffer` / `liveFrame` / `toolRows` / `follow` 五个模块级变量只属于实时路径，恢复路径另有一套。任何一次"流式中看起来对、刷新后不对"的缺陷都出在这里；C5 暴露的"审批提示没出现"也落在相邻区域（`showApproval`，`app.js:909`）。

### 2.3 问题三：测试脚手架挡在模块化路上

现有前端测试**不是零覆盖**，这点必须记准：

| 文件 | 行数 | 覆盖 |
|---|---:|---|
| `tests/test_web_render.py` | 292 | 内置约 150 行 DOM stub，Node 里跑真实 `app.js`，断言渲染出的 6 条消息、折叠、来源卡、文件卡 |
| `tests/test_file_editor.py` | 130 | 编辑器草稿、冲突、切换工作区、预览 |
| `tests/test_markdown_render.py` | 131 | Markdown 渲染器 |
| `tests/test_web_ui.py` | 131 | HTML 与脚本的 id 双向一致性（文本检查） |

它们全部靠 `eval(require("fs").readFileSync(..., "utf8"))` 加载脚本（`test_web_render.py:175`、`test_file_editor.py:62`）。**`import` 在 `eval` 里是非法的**，脚本一旦改成 ES module，这 553 行测试会同时失效。

另有隐性脆弱：`test_file_editor.py:13` 用 `HARNESS.split('const SESSION =')[0]` 截取公共部分复用。harness 里任何结构调整都会静默改变第二个文件拿到的环境，而它仍然"通过"。

## 3. 目标与非目标

### 3.1 目标（可度量）

| 指标 | 现状 | 目标 |
|---|---|---|
| 最大单文件行数 | 1738 | ≤ 400 |
| `window.Chagent*` 全局 | 7 | 0 |
| 渲染入口数量 | 2（实时 / 恢复） | 1 |
| 直接调用 `document.*` 的模块 | 散落全局 | 仅 `dom.js` 与 `render/`、`views/` |
| 前端测试加载方式 | `eval` 字符串 | `import()` |
| 纯函数单测 | 0（逻辑混在 DOM 代码里） | 覆盖状态推导、格式化、审批文案、上传状态机 |

### 3.2 非目标（明确不做）

1. **不引入框架**。复杂度在"状态与事件"，不在"组件组合"；上框架会引入构建链与 hydration 语义，收益低于 reducer。
2. **不重写 CSS**。900 行 CSS 不是痛点，重写它是纯消耗。
3. **不引入打包器 / Vite / TypeScript 编译**。原生 ESM 直接由浏览器加载，`tsc` 只做 `--noEmit` 检查。
4. **不引 jsdom / Playwright**。现有 stub 已能覆盖"接线是否对"，视觉与布局仍按现有约定人工验收。
5. **不改后端**。若发现必须改接口才能收敛渲染，先停下另立方案，不在本方案内顺手改契约。

## 4. 目标模块划分

```
static/
  main.js              入口：读初始状态、绑定全局事件、启动
  core/
    dom.js             $ / el / textNode / on（唯一直接碰 document 的底层）
    api.js             fetch 封装、withWorkspace、错误规范化
    store.js           单一 state + subscribe + dispatch
    format.js          纯函数：token、字节、路径、标签
  run/
    run-reducer.js     纯函数：reduce(state, event) -> state
    run-render.js      唯一渲染入口：renderRun(root, state)
  render/
    message.js         消息正文、折叠、代码块、动作条
    tool-result.js     工具结果卡、产物分页
    sources.js         依据卡
  views/
    sessions.js        会话列表、菜单、重命名、归档、搜索
    uploads.js         上传队列与拖放
    workspace.js       工作区对话框、浏览、切换
    memory.js          长期记忆
    config.js          运行时配置与用量
    approvals.js       审批卡
  file-editor.js       保留单文件，改为 import 依赖
  markdown.js          不动
  style.css            不动
```

### 4.1 依赖规则（唯一硬约束）

```
main  →  views  →  render  →  run  →  core
                    ↓         ↓       ↓
                   core      core    （叶子）
```

- 只允许向下 import，**不允许同层横向 import**（`views/uploads.js` 不得 import `views/sessions.js`；跨视图协作走 `store`）。
- **禁止任何 `window.Chagent*`**。跨模块调用改为显式 import。
- `core/dom.js` 是唯一允许 `document.getElementById` 的底层；`render/`、`views/` 通过它取节点。
- `run/run-reducer.js` 不得 import 任何 DOM 模块（这是它能被单测的前提）。

### 4.2 渲染收敛的目标形状

```js
// run/run-reducer.js —— 纯函数，无 DOM
export function reduce(state, event) { /* 返回新 state */ }
export function initialState(run) { ... }

// main.js
source.addEventListener("update", e => {
  state = reduce(state, JSON.parse(e.data));
  renderRun($("run-root"), state);
});
```

`openSession` 恢复历史时，把已持久化的事件按同一份 `reduce` 重放一遍，再走同一个 `renderRun`。**"流式中"与"刷新后"从此是同一个函数**，这类缺陷整类消失。

已知需要保留的现有优化：`text_delta` 按 `requestAnimationFrame` 合并重绘（`app.js:69`），滚动跟随（`follow` / `NEAR_BOTTOM`，`app.js:48-60`）。二者都变成 `renderRun` 的输入，而不是模块级副作用。

## 5. 实施顺序

每个阶段独立可交付、可回滚。**任何阶段若必须改后端接口，停止并另立方案。**

### 阶段 0：先让测试能加载模块

这是模块化的前置条件，不是可选项。

改动：

1. 把 `tests/test_web_render.py` 里的 `HARNESS` 字符串抽成 `tests/js/harness.mjs`（保持逐行等价）。
2. `test_file_editor.py` 不再 `split` 字符串，改为从 harness 导出 `createDom()`，需要不同初始环境时传参。
3. 脚本加载从 `eval(...)` 改为 `await import(pathToFileURL(...))`。
4. 为测试保留的接缝（`testOpenSession`、`testSetFollow`）改为**命名导出**，不再挂 `globalThis`。

验证：`tests/test_web_render.py`、`test_file_editor.py`、`test_markdown_render.py` 三文件全部通过，且断言数量不减少。

回滚点：三个测试文件与新增 `tests/js/` 整体还原。

完成判据：`app.js` 仍是普通脚本（未模块化）时，三文件仍能通过——证明"换加载方式"与"模块化"是两件独立的事。

### 阶段 1：纯搬运，切出三个叶子模块

改动：只抽 `core/dom.js`、`core/api.js`、`core/format.js`，`app.js` 改为 `import` 它们；`index.html` 改为 `<script type="module" src="/static/main.js">`，`main.js` 先只做 `import "./app.js"`。

**本阶段不改任何逻辑、不改任何 DOM 结构。** 目的是先验证"原生 ESM 在真实浏览器 + stub DOM + 静态服务三者下都能跑"，这个风险要在最小的改动量上试出来。

验证：全量回归 + 三条浏览器手测路径（见第 6 节）。

回滚点：`git revert` 单个提交即可，`app.js` 保持原样也能跑。

完成判据：`app.js` 减少约 120 行；`window.Chagent*` 数量不变（本阶段不动它）。

### 阶段 2：消除 `window` 全局环

改动：

1. `file-editor.js` 改为 `import { switchWorkspace, showFiles } from "./views/workspace.js"`，删除 `window.ChagentWorkspaceSwitch` / `ChagentShowFiles`。
2. `app.js` 改为 `import { files } from "./file-editor.js"`，删除 16 处 `window.ChagentFiles?.`。**改为直接调用后，缺失会立刻抛错而不是静默跳过**——这是本阶段的主要收益。
3. `markdown.js` 改成默认导出，`main.js` 显式 import。

验证：除回归外，**新增一条"删除某个导出后测试必须失败"的检查**（手工做一次即可，不必入库），确认接缝不再是静默的。

回滚点：单提交还原；期间 `app.js` 与 `file-editor.js` 必须同批改，不能只改一半。

完成判据：`window.Chagent*` 为 0（`grep -r "window.Chagent" static/`）。可把这一条写进 `test_web_ui.py` 作为永久护栏。

### 阶段 3：收敛为单一渲染入口

改动：

1. 抽 `run/run-reducer.js`：把 `connectRun` 的 `if (type === ...)` 长链逐条翻译成 `reduce` 分支，**语义逐条对照，不顺手改行为**。
2. 抽 `run/run-render.js`：把实时路径现在直接写的那些 DOM 更新，改成"由 state 推导 DOM"。
3. `openSession` 的恢复路径改为：事件重放 → 同一个 `renderRun`。
4. `liveText` / `liveBuffer` / `liveFrame` / `toolRows` 从模块级变量移入 state。

这是风险最高的一步，也是收益最大的一步。建议先只收敛 `text_delta` / `tool_*` / `approval_*` 三类事件，`compaction_*`、`memory_*` 这类低频事件留在原处，第二批再迁。

验证：本次改造必须补一个**重放等价性测试**——同一批事件，(a) 逐条喂 `reduce` + `render`，(b) 走恢复路径，两次产出的 DOM 序列化必须一致。这是本阶段唯一的硬证据。

回滚点：`run/` 目录与 `app.js` 的对应段落同批还原；`app.js` 内保留旧连接函数直到新路径通过验收。

完成判据：`connectRun` 中不再出现 `document.*` 或 `$(`；渲染入口只剩 `renderRun` 一个。

### 阶段 4：纯函数与护栏（可与其他阶段并行）

改动：

1. `render/*` 与 `views/*` 里的状态推导抽成 `core/format.js` 或模块内纯函数：token 格式化、来源标签、审批卡文案分级、上传状态机、文件冲突判定。
2. 在 `tests/js/` 下用 `node --test` 直跑纯函数，不经过 DOM stub。
3. `test_web_ui.py` 扩展为扫描全部 `static/*.js`（现在只扫两个文件），并把"禁止 `window.Chagent`"写成断言。

完成判据：`core/format.js` 与 `run/run-reducer.js` 的单测不需要 DOM、不需要 stub、不启动 Node 之外的任何东西。

### 阶段 5（可选）：类型灰度

只在 `core/api.js`、`core/store.js`、`run/run-reducer.js` 三个文件顶部加 `// @ts-check`，用 `tsc --allowJs --checkJs --noEmit` 检查，不产出文件。

后端响应结构用 JSDoc 从 `web/schemas.py` 抄一遍（`@typedef`）。**不上编译，不引入 `.ts` 文件。** 若三个月内没有实际拦下缺陷，直接放弃这一步。

## 6. 验证策略

### 6.1 自动

```sh
NO_PROXY=127.0.0.1,localhost CHAGENT_TEST_DATABASE_URL=postgresql:///chagent \
  PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -q
```

- 全量回归基线：570 项通过、0 跳过（2026-11-05）。任何阶段都不得低于此数，且**跳过不计通过**。
- 前端四个测试文件必须在每个阶段后单独确认，不允许"整体绿了但前端测试被跳过"（`test_web_render.py` 有 `skipUnless(NODE)`）。

### 6.2 人工（每条阶段后都做）

| 路径 | 检查点 |
|---|---|
| 发消息 | 流式文本逐字出现、工具行状态依次变化、结束后不重复渲染 |
| 审批 | 卡片出现一次、批准后执行、拒绝后同会话可继续 |
| 文件 | 打开 → 改一行 → 保存 → 刷新后内容一致；冲突时草稿保留 |

三条路径都不需要新工具。若后续要自动化，优先补这三条，而不是扩大 stub 覆盖面。

### 6.3 未验证范围（必须在交付记录里写明）

- stub DOM 没有布局、没有 CSS、没有指针事件，**滚动跟随与折叠高度无法自动验证**。
- 未做跨浏览器（Safari / Firefox）验证。原生 ESM 支持无问题，但 `dialog`、`matchMedia` 行为未测。
- 性能未测量：`renderRun` 全量重绘在中长会话（500+ 消息）下的开销未知。若退化，需引入按消息 id 的局部更新，那是另一份方案。

## 7. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| `eval` → `import()` 迁移改变变量作用域，某些 `let` 提升顺序变化 | 测试假通过或假失败 | 阶段 0 单独提交，先跑通不加功能；失败即回滚，不带着改模块 |
| 重放语义不一致：`memory_saved`、`approval_decided` 重放会重复插入 DOM | 刷新后出现重复卡片 | `reduce` 对一次性事件做幂等键（事件 id / call id）；重放等价性测试覆盖 |
| 实时路径的 rAF 合并被破坏 | 长回答卡顿 | `renderRun` 保留帧合并，作为 state 更新的节流，而非渲染上的临时补丁 |
| 多标签编辑器草稿在视图拆分中丢失 | 用户输入丢失（不可接受） | 阶段 2 不动 `file-editor.js` 内部逻辑，只改依赖注入方式；改完必须手测"改一半切标签再切回" |
| 前端测试被 `skipUnless(NODE)` 静默跳过 | 假绿 | CI 或本地回归后检查 skipped 计数，跳过即视为未验证 |

## 8. 停止条件

出现以下任一情况，停止后续阶段，把现状记为"部分模块化"，不追求一次做完：

1. 阶段 2 无法在不动 `file-editor.js` 内部逻辑的前提下切断环。
2. 阶段 3 的重放等价性测试无法通过，且原因是对后端事件语义理解不足（此时应先补后端事件文档，而不是在前端做兼容层）。
3. 任一阶段导致全量回归低于 570 项，或出现跳过。
4. 改造期间需要修改 `web/app.py` 或任何 SSE 事件字段。

部分交付是可接受的：**阶段 0–2 完成后，即使不做阶段 3，前端也已经从"两个文件互相静默依赖"变成"单向分层、缺失即报错"，这本身已消掉最危险的一类缺陷。**
