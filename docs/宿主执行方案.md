# Chagent 自主建站整体方案

**状态：设计定案，尚未实施。** 本文是“用户选本机目录，提出一句 Python/Java 建站需求，Chagent 自主创建、测试、运行和交付”的唯一整体方案。2026-11-05 的方案 A（容器内主控加宿主终端代理）仅是未完成原型，不作为目标架构。本文描述目标行为，不代表当前产品已经具备这些能力。

## 1. 目标和成功定义

用户选定一个已存在的本机工作区，提出“写一个 Python 或 Java 网站”。Chagent 应能读取现状，创建或修改项目，在受限环境安装依赖、构建、测试、根据错误修复，持续启动服务，并从本机验证 HTTP 页面。最后交付工作区文件、可访问地址、测试与运行证据、启动和停止方法。

“在本机可用”默认指网站进程在本机 Docker 执行环境中运行，用户可用本机浏览器访问。只有用户明确要求 macOS 原生进程，或任务确实依赖宿主资源时，才申请宿主原生执行。后一种操作必须等待用户在 Chagent 网页审核并批准。因此普通建站可以连续自主推进；原生宿主操作不能同时承诺零确认。

成功必须由实际文件、命令退出码、测试结果、持续进程状态和本机 HTTP 请求共同证明。模型文字、单元测试数量、工具健康探针均不能单独证明建站成功。任意需求和外部依赖不能保证百分之百成功；失败时要准确报告阻碍、保留可继续的状态。

## 2. 当前状态和根因

| 方面 | 当前事实 | 对目标的影响 |
|---|---|---|
| 主控位置 | Chagent 整个进程在容器中，命令在该进程中就地执行；compose 只挂一个宿主目录到 /workspaces | 运行中不能直接接入任意新宿主目录，切换被迫重启 |
| 工作区身份 | 数据库以容器内 root_path 区分工作区和会话 | 两个宿主目录依次挂到 /workspaces 会被当作同一工作区；旧会话可能访问新目录 |
| 容器边界 | 工作区是 bind mount；容器命令可联网，当前容器并非强隔离 | 容器内写文件就是改宿主文件，不能把“在容器里”当作无副作用 |
| 审批 | 容器命令、部分覆盖写入与方案 A 的宿主终端各有确认路径 | 正常编码被多次打断；用户在聊天里回答无法批准终端请求 |
| 宿主执行 | A 原型只支持经终端确认的一次性命令；未完成真实模型闭环 | 无法可靠运行持续的宿主服务，未形成同一网页内的审批体验 |
| 运行与预览 | 容器固定映射 8080；会话进程只属于一个 run | 任意项目端口、长时间运行、断连后的恢复没有统一契约 |
| 验证 | 已有大量组件测试和部分真实项目记录，但缺少固定的一句话建站验收集 | “测试通过”不能外推为 Python/Java 网站均可自主交付 |

2026-11-05 检查发现数据库已有一个会话使用 /workspaces。跨宿主根目录的自动重挂载入口已关闭，运行服务已恢复原挂载目录并关闭宿主执行。迁移前不得把该会话静默指向其他宿主路径。

## 3. 确定的架构

采用“宿主主控 + 每工作区独立容器执行后端”。不继续扩展方案 A 的宿主终端代理。

- **宿主主控**：FastAPI 网页、模型循环、PostgreSQL、稳定工作区身份、审批、执行调度、服务入口和运行状态。主控保存模型凭据；项目命令和容器不能继承这些凭据。
- **工作区容器**：每个活动工作区拥有明确的容器实例和仅属于该工作区的挂载。模型生成的普通安装、构建、测试、应用启动命令在这里执行。容器有资源限制、最小权限、明确网络策略及可复用依赖缓存。
- **宿主执行器**：与模型调用隔离的窄接口。只有准确命令、目录、环境、超时及本次批准均匹配时才启动宿主进程；没有免审批模式。它记录实际启动、退出和未知结果。
- **服务入口**：宿主代理本机端口到相应容器内实际监听端口，提供稳定的本机访问地址。Docker Desktop 下不假设宿主能直接访问容器 IP；端口映射不能在运行中的容器上临时新增，须通过预设入口代理或等效通道解决。

模型只看到可申请的工具；执行位置由工具和主控策略决定，不由模型文字声明决定。宿主主控虽运行在本机，也不得把任意模型参数直接拼成宿主 shell 命令。

## 4. 工作区和数据契约

1. 数据库为每个宿主工作区建立稳定 UUID，保存规范化宿主路径、可选文件系统身份和当前容器映射。会话、记忆、产物和运行记录均引用 UUID；容器路径不充当主键。
2. 每次使用前在宿主重新检查目录存在、身份、符号链接和准入规则。目录移动或身份变化时停用该映射，要求显式重新绑定，绝不自动指向另一个目录。
3. 为一个工作区创建或恢复其执行容器，不重启整个 Chagent。多个工作区可以轮换或并存，资源配额由主控控制。
4. 迁移旧数据前备份数据库。能证明原宿主路径的旧 /workspaces 记录才映射到新 UUID；无法证明的旧会话标为“待重新绑定”，保持可查看审计但禁止工具执行。迁移测试必须验证旧会话、记忆和文件输出不串目录。
5. 保留用户现有未提交改动。A 原型逐项迁移或撤除，不以整包覆盖工作区 UI、数据库或历史记录。

## 5. 执行、审批和风险边界

默认允许在所选工作区内正常创建和修改项目，并在工作区容器内运行构建、测试和服务。风险不能只靠命令前缀或模型“自审”判定；容器必须实际限制路径、凭据、网络与资源。容器对 bind mount 的写入会改变宿主文件，因此执行前和最终交付时要记录文件清单及差异；工作区外写入不得由容器完成。

以下请求在同一 Chagent 网页暂停并显示准确参数：宿主原生命令、工作区外读写、访问本机凭据或其他额外权限。用户看到命令、真实 cwd、用途、预期影响及容器验证证据。批准只对该请求一次有效，不覆盖后续 stdin、改动后的命令或另一个工作区。拒绝、超时、无人查看、取消均不执行；请求已发出但结果不明时标记 outcome_unknown，不自动重试。

审批结果、实际工具结果和最终回答使用同一条持久化记录。模型可引用批准事实，但“模型说已批准”不是批准证据。宿主执行器必须独立验证批准状态，不能接受来自容器的“用户已同意”标志。

## 6. 一次建站任务的闭环

1. 主控锁定工作区 UUID 和容器身份，读取目录与已有改动；保护用户预存文件。
2. 模型制定短计划，使用文件和命令工具创建项目、安装依赖、构建及运行定向测试；失败后读取实际输出并修复。
3. 将服务作为受管理的长进程启动。记录进程标识、实际监听端口、日志位置、超时与停止方法；运行结束、崩溃或容器重建时明确状态。
4. 入口代理提供本机地址。主控发出真实 HTTP 请求，检查状态码和关键内容。涉及前端 JS、页面布局或交互时增加浏览器验证；仅 HTTP 200 不等于页面可用。
5. 主控比对最终文件、测试、服务和 HTTP 证据，交给模型生成总结。最终回答分别列出已验证、未验证、失败或需要用户批准的部分。
6. 如果必须原生运行，先展示容器验证结果，再走网页审批；批准后宿主执行、读回结果、按同样标准验证。用户拒绝时继续容器内可行工作或准确停下。

任务可以跨多次模型调用、用户审批和断线继续。预算是单次活动限制，不应以一个固定 run 超时否定整个项目。重启后能恢复的进程继续跟踪，不能确认的外部副作用标记未知，禁止盲目重复。

## 7. 终端、工具链和性能

普通 Python/Java 网站不要求用户打开 Terminal。容器执行器提供非交互命令、持续进程、日志、停止、stdin 和必要的 PTY；登录、验证码或必须由用户输入的凭据明确交还用户。宿主原生进程的交互输入须另行审批，不沿用启动批准。

基础镜像提供 Python、JDK、Maven/Gradle、Node 与常见构建工具；按项目识别实际工具链。依赖缓存持久化，镜像可预热。首次下载、外部仓库故障、模型能力和用户需求不完整仍可能延迟或阻止交付，系统必须给出可操作的失败说明。

## 8. 实施顺序与交付门槛

**第一交付：自主建站主链。** 先完成稳定工作区身份与旧数据隔离，再把主控迁到宿主、容器变为每工作区执行后端，接入长进程与本机服务入口。用真实模型从空目录分别建成 Python 和 Java 小网站；两者都须通过测试、持续运行和本机 HTTP 验证。切换两个宿主工作区后，会话、记忆、文件和进程不得串用。正常路径无需逐命令确认。

**第二交付：宿主原生操作与恢复。** 在同一网页审批宿主执行，完成批准、拒绝、过期、取消、断连、重启、重复申请和结果未知的验收；补齐 stdin/PTY 的批准边界。真实模型要在容器验证后申请一次必要的原生操作，用户批准后继续交付；拒绝时保证未执行并正确收尾。

每个交付同时提供自动测试、真实工具、真实模型、真实项目和浏览器/HTTP 证据。不能用合成项目、离线模型或模型自述替代真实验收。验收集至少覆盖：Python 新项目、Java 新项目、已有项目修复、依赖安装失败后的恢复、两个工作区隔离、服务端口变化、宿主批准与拒绝。记录实际成功率、耗时、人工介入次数和未通过原因；不承诺所有任意任务必然成功。

## 9. 发布、回退与不变约束

先备份数据库和现有部署配置，在隔离环境演练迁移；随后用新主控读取旧历史，确认工作区映射，再逐步启用执行。旧容器部署保持可回退，但回退后不得把新工作区身份重新解释为旧 /workspaces 路径。迁移和验收通过前，A 原型与跨宿主目录重挂载不得作为正式能力宣传。

需要保持的约束是：用户选择哪个真实目录，任务就只对该工作区生效；普通建站在受限环境自主推进；确需宿主原生执行时由用户在同一网页确认；最终成品与验证证据都能在用户工作区和会话中检查。后续实现选择可以调整，但不能放松这四条，也不能用新增功能掩盖未通过的整链验收。
