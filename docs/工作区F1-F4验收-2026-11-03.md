## 环境与方法

- macOS，Python 3.13，本机 PostgreSQL；测试使用独立临时 schema、临时工作区，结束后删除。
- HTTP 与浏览器使用 `--demo` 离线模型，避免把模型随机性混入文件接口验收；真实模型单独用 DeepSeek `deepseek-v4-flash`。
- 浏览器是 OpenCode 内置 Chromium。本环境逻辑视口固定为 846×778（窄屏），因此窄屏抽屉流程实测，桌面宽度拖拽未实测。
- 自动回归、HTTP、浏览器、重启和真实模型分别记录；合成内容不冒充真实业务项目。

两个环境限制会影响读数，复跑前先确认，否则容易把环境问题误判成代码缺陷：

| 现象 | 原因 | 处理 |
|---|---|---|
| 依赖 seatbelt 的用例被跳过 | 在嵌套沙箱（CI 容器、加固 runner、执行沙箱）内 `sandbox-exec` 无法施加，报 `sandbox_apply: Operation not permitted` | 到普通终端复跑；跳过不计通过 |
| `test_web_render`、`test_file_editor` 假失败 | 宿主注入了 `NODE_OPTIONS`（node 代理 shim），node 启动即崩 | `env -u NODE_OPTIONS ...` 后通过 |

## 实现

### F1 工作区导航

- 工作区分组会话、组内新对话、当前工作区搜索、跨组历史会话切换、首次选择提示；原生 macOS 目录选择入口与手工路径退路。取消不登记工作区。
- 工作区沿用原有 ID 和路径唯一约束；迁移 `0018_workspace_navigation.sql` 记录最近打开时间。目录失效时保留条目并显示不可用，打开时重新准入，不按名称重绑。

### F2 文件服务与管理

- `FileService` 复用 WorkspaceFS 的目录描述符、no-follow、文件身份检查和原子写；HTTP 文件接口使用工作区 UUID + 相对路径，要求工作区已打开。
- 目录按层列出、支持分页与隐藏文件开关；内部 `.chagent` 不显示或开放文件管理。
- UTF-8 文本读取返回 SHA256、文件身份和换行信息；保存必须携带版本与身份，冲突返回 409。保存保留 LF/CRLF/CR 约定；混合换行的文件只读，避免 `<textarea>` 归一化破坏原文件。
- 新建文件/文件夹、原子禁止覆盖的重命名、回收与恢复。macOS 用 `renameatx_np(RENAME_EXCL)`，Linux 用 `renameat2(RENAME_NOREPLACE)`；其他平台明确拒绝安全重命名，不以先检查再覆盖降级。
- 回收记录与 payload 位于工作区 `.chagent/trash/<UUID>/`，跨服务重建可列出和恢复；恢复撞名保留现有文件，可指定新目标。移动失败不永久删除。Agent 搜索跳过 `.chagent`，文件工具拒绝直接访问回收站。
- 文件写入与 Agent 文件工具共享进程内工作区写锁；只读工具保留并发。Shell、外部编辑器及其他服务进程不参与该锁，不保证文件事务或阻止同 OS 用户恶意替换。

### F3 编辑器

- 右侧文件树与文本编辑，另有上下文和历史产物页签。目录逐层展开、分页与隐藏文件开关；新建、重命名、恢复与另存为走页面内表单（内嵌浏览器无原生 prompt）。
- 多标签按工作区 ID + 相对路径隔离；同工作区切换聊天保留草稿，关闭标签、跨工作区切换、重命名/删除涉及草稿时提供保存、放弃、取消。比例可拖动或用方向键调整并在本机记忆，窄屏时文件覆盖聊天。
- 输入只修改草稿；保存/⌘S 才写盘。保存请求中继续输入不会丢失新草稿或把它误报为已保存。刷新/关闭触发浏览器离开提示；不承诺崩溃或刷新后恢复草稿。
- 保存携带读取哈希与身份。冲突保留草稿，支持查看磁盘版本、另存为和确认覆盖最新已读取版本；文件随后再变化仍拒绝。位置失效允许另存为。
- UTF-8 文本，1 MiB 文件上限，最多 25 个标签。Markdown 使用现有安全渲染。浏览或编辑文件不自动把内容注入模型。
- 外部变更检查：窗口重新获得焦点、手动刷新及可见页面每 5 秒检查打开标签与确认状态。干净标签可重载；脏标签只提示。目录树不每 5 秒重绘，避免夺走焦点；Agent 结果刷新也会更新树。

### F4 统一文件与输出

- 普通网页 work 和可写 code 注册 `write_file`/`edit_file`/`apply_patch`/`create_directory`/`create_file`；显式只读 code 全部裁掉，code 命令、测试与 `process` read/stop 保持既有隔离契约。
- 网页实际 Runner 校验同步更新，分别报告 work 写入和 code 写入，模式提示不混用。普通网页 `versioned_files` 开启：修改已有文件必须使用读取 SHA256；补丁的 `versions` 映射对全部已有目标先校验再提交。旧 CLI/确定性诊断调用保留可显式装配的兼容参数，不作网页权限依据。
- 文件工具、手动编辑和上传输出复用 FileService/WorkspaceFS 的路径、身份、原子替换与工作区进程内协调。`create_directory` 只创建已有父目录下一层；`create_file` 的子目录必须已存在，不能隐式创建父链。模型补丁删除进入工作区回收站。
- 上传存 `uploads/`；文本生成默认工作区根或指定已有子目录；聊天和上传卡提供打开文件/下载。解析以当前磁盘内容的 SHA256 缓存，编辑后读取不使用旧上传快照。
- 新输出不再写 `generated_files`。旧表保留历史下载，“保存到工作区”才导出，撞名也需确认。会话产物列表同时展示新磁盘输出和旧历史产物；磁盘是当前版本依据，新表保存输出意图、确认信息与操作来源，不是工作区目录镜像。

### 确认与故障契约

迁移 `0019_file_outputs.sql` 新增 `file_outputs` 与 `file_operations`。确认卡可在刷新后按工作区恢复，用户可查看磁盘、下载待写入内容、选择覆盖/保留两份/取消。提案内容不可变，宿主 token 绑定工作区、路径、内容、已有内容哈希与身份。模型工具只返回输出 ID，不接收确认 token 或“已获授权”参数。

- 无撞名时写入真实文件；撞名返回 pending，文件不变。模型 run 可正常结束，不占执行线程或文件锁等用户，也不自动续跑。
- 确认有效期 24 小时。取消/超时不写入。work/code 的待确认输出不会因为普通页面刷新丢失；运行被取消后，仍 pending 的该 run 输出会取消。
- 覆盖与保留两份均重新核对目标版本；期间变化返回 409、更新目标快照并轮换 token，旧 token 不可复用。确认通过数据库行锁消费，重复提交只有一次成功。
- 上传请求 UUID 与模型 run/tool_call 组合支持去重；同一 `request_id` 改内容会拒绝。保留两份用不覆盖创建；目录重命名沿用 F2 的原子 no-replace。
- 意图先持久化，磁盘写入后记录结果。写盘前标记 staged 并消费 token；进程崩溃或取消造成结果未知时保留 staged，界面提示检查磁盘，不自动重放。文件系统与数据库不构成跨资源事务，不承诺崩溃时回滚。
- Shell 与外部程序不参加文件服务锁；通用命令覆盖不弹本确认卡，也不宣称实现跨进程文件事务。

## HTTP 接口

统一前缀 `/api/workspaces/{workspace_id}`：

| 方法与路径 | 功能 |
|---|---|
| GET `/entries?path=&offset=0&limit=100&hidden=false` | 单层目录与身份；返回 next_offset |
| POST `/entries` | path、type（file/directory）、可选 content；不覆盖 |
| GET `/text?path=…` | UTF-8 内容、version、identity、newline |
| PUT `/text` | path、content、version、identity；手动保存 |
| POST `/rename` | path、target、identity；不覆盖 |
| POST `/trash` | path、identity；回收 |
| GET `/trash` | 待恢复记录 |
| POST `/trash/{record}/restore` | 可选 target；不覆盖 |
| GET `/content?path=…` | 校验工作区后的附件下载，最大 20 MiB，不作为静态目录暴露 |
| POST `/outputs` | path、content、request_id；另存为与输出 |
| GET `/outputs` | pending/staged 意图；刷新恢复，清理已超时 pending |
| GET `/outputs/{id}` | 查询状态；上传队列据此处理已提交/取消/超时 |
| GET `/outputs/{id}/proposal` | 下载仍有效的待写入提案 |
| POST `/outputs/{id}/decision` | token、choice=overwrite/keep-both/cancel |

另有 `POST /api/workspace-picker` 调起系统选择器（取消返回 `cancelled=true`，不可用/超时返回 503，前端给手工输入退路）和 `POST /api/sessions/{session_id}/files/{file_id}/export` 主动导出旧产物。上传撞名返回 202，真正落盘才是 committed。PUT 文本保存纳入本机来源、JSON 类型与请求体大小检查：普通 JSON 请求 64 KiB，文件 JSON 请求 6.4 MB，文件服务另检查实际字节上限。

## 浏览器实测

使用真实页面和真实工作区，关键步骤同时用 shell 核对磁盘，不以页面状态代替文件结果。

- **F1 导航**：手工路径打开工作区；侧栏按工作区分组，显示目录末段与父目录；组内“＋ 新对话”只在该工作区创建会话；跨组打开历史会话会同步切换工作区和右侧文件树；当前工作区搜索只返回本组结果；失效目录保留分组并显示原因，标题不可点击。
- **F2 文件树**：按层展开 `src` 后出现 `main.py`；隐藏开关显示 `.hidden.txt`，不显示 `.chagent`；新建文件/文件夹、重命名、删除、回收站恢复均落在真实目录。

## 服务重启

同一数据库、同一工作区，停止并重启进程后：

- 工作区记录仍为 available，分组和会话列表保留；
- 未决输出 `restart-pending.md` 仍为 pending，页面刷新后确认卡恢复，选择取消后目标文件保持原文；
- 回收记录仍可列出，浏览器恢复为 `restart-restored.txt` 后磁盘内容正确；
- 已保存的 README 内容来自磁盘，重启后编辑器和下载一致；
- 回收站、pending 和文件树均不依赖进程内缓存。

说明：切换工作区会按设计清除“上次打开的会话”，所以重启只验证了工作区和会话列表恢复，没有声称自动重新打开上次会话。

## 真实模型

`scripts/probe_workspace_files.py` 在一次性 schema 和临时目录中分别运行 work/code：

- 读取并编辑上传文本；
- 创建目录并生成 Markdown；
- 同名输出再次生成，确认进入 pending 且原文保留；
- 宿主选择“保留两份”后落盘。

结果：**work、code 两种模式均通过**。原始结果见 [首次运行 JSON](diagnostics/workspace-f34-real-2026-11-03.json) 与 [复跑 JSON](diagnostics/workspace-f34-real-2026-11-03-rerun.json)（两次均为合成内容，run ID 不同）。命令断网、隔离沙箱和 `process` 只读/停止仍由既有执行边界测试覆盖。

|---|---|
| 自动回归 | `Ran 573 tests in 60.050s / OK (skipped=17)`；17 项跳过全部是 seatbelt 不可用，0 失败 |
| 文档 19 项黑盒 | **19/19 复现** |

## 发现与建议

没有阻塞 F1–F4 的缺陷。三点保持记录：

1. 上传撞名选择“保留两份”后，上传卡片仍显示原文件名，但“打开文件”已指向新路径；功能正确，命名展示可后续优化。
2. 原生选择器仍是唯一没有端到端实测的 F1 入口；发布前应在真实桌面上人工点一次选择、取消和权限提示。
3. 同一路径可以积累多张 pending 确认卡（历史 run 遗留 + 新提交）。数据上正确（每 output 一条），但界面会出现多张一样的卡片。建议 pending 列表按 path 折叠，只显示最新一张和“还有 N 条更早的”。

## F5 与后续

F5 仍按[实施方案](工作区与文件编辑器实施方案.md)执行，包括 PDF/图片预览与整体补验；当前下载入口不能当作图片理解或 OCR。本验收不把 F1–F4 通过解释为完整首版完成。

回退不得清理原目录文件、回收站、历史产物或确认记录；重启会自动应用 `0018`/`0019`，旧二进制遇到新迁移会拒绝不匹配 schema，应使用兼容迁移版本关闭新入口。
